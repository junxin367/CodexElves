验证时间：2026-11-03 至 2026-11-04。范围仅为操作等待提示、队列交互中的重复模块读取及必要的按钮反馈。

## RCA 结论

- 状态：**部分确认**。本轮已定位并对照验证重复模块读取的额外耗时，以及等待提示与按钮反馈的问题；没有足够手机现场记录将用户遇到的所有长延迟都归因于这一项。
- 现象：操作刚发出便显示结果待确认的说明；开始编辑、取消编辑和引导存在额外等待，取消和保存期间按钮仅置灰。
- 直接原因：原提示条件把“请求进行中”直接渲染为补充警示；队列操作重复调用原生模块定位，定位又反复读取同一静态依赖链。
- 根因：已缓存模块导出，但未缓存依赖定位过程中读取的源码；已识别的准备函数仍会先重新定位模块。UI 缺少明确的等待提示时限和取消／保存的进行中状态。
- 系统性根因：既有模块定位回归只验证能否定位正确资源，没有连续调用的读取次数断言；等待提示验收没有覆盖短请求与超过阈值的真实交互。
- 因果链：点击操作 → 原生准备或输入合同检查 → 再次读取 `index → app-main → app-initial` → 回执延后；UI 同时提前展示待确认说明。

## 最小修复

| 范围 | 实现 |
| --- | --- |
| 等待提示 | 默认先由按钮表达状态；超过 5 秒仍未确认才显示补充说明。覆盖主消息、队列、删除、侧边会话、目标、问答、既有审批和压缩的待确认提示。 |
| 真实失败 | 明确失败、授权不符或不可用状态仍及时提示，不与普通等待混为一谈。 |
| 操作按钮 | 引导、保存、取消分别显示“引导中”“保存中…”“取消中…”和 spinner；完成后还原。开始编辑保留原有“正在取回”状态。 |
| 模块源码 | 按静态资源 URL 复用源码 Promise，合并并发读取；网络、HTTP 或正文读取失败后清除该条缓存，允许后续恢复。 |
| 模块兼容 | 每次仍检查当前 DOM、Resource Timing、脚本入口及多版本歧义；新 URL 重新读取，不缓存会话状态或执行配置。 |
| 消息保护 | 保留原消息身份、输入合同、归属检查、未知回执锁和不重复提交规则。四次归属检查各约 1～3 ms，并非本轮主要耗时，没有为提速删除。 |

主要代码：`assets/remote-access/app.js` 的 `pendingFeedbackReady`、`queuedEditSubmittingAction`、`renderQueueArea`；`assets/remote-access/native.js` 的 `nativeResourceSource`、`nativeModuleSnapshot` 和队列 `prepare`。
