## 安装包与源码的区别

当前 `dist/android/CodexElves-0.0.1-android.apk` 是 2026-10-18 12:25:21 的构建，大小 2,226,239 字节，SHA-256 为 `C7DC0327A24B6E19184020EAAF8401923B952F3C484FBC251622F35011A7D501`。

实际 `aapt dump permissions` 只列出 `INTERNET`、`ACCESS_NETWORK_STATE`、`REQUEST_INSTALL_PACKAGES` 三项，尚无通知功能需要的声明。源码与真实 Gradle 合并清单则包含 `POST_NOTIFICATIONS`、`FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_REMOTE_MESSAGING`，共六项。

因此，“现有 APK 没有新通知授权流程”与“源码未声明通知权限”是不同结论。前者已由包内容确认；后者不成立。没有连接手机，不能认定手机安装的就是此文件。版本显示同为 0.0.1，判断时应同时检查构建时间与摘要。

构建入口的 `-CheckOnly` 已返回 `NeedsBuild=true`，原因是 Android 内容较上次正式构建发生变化。后续正式构建会包含这些修复；本次只执行了验证编译。

## 功能与权限

| 功能 | 当前声明与申请方式 |
| --- | --- |
| 通知事件 | Android 13+ 在开启“接收通知”且尚未获准时申请系统通知权限；较低版本读取系统通知开关。拒绝、取消或关闭系统通知后，显示当前不能接收并保留设置入口。 |
| 应用更新安装 | 安装前检查允许本应用安装未知来源应用的特殊访问；需要时进入本应用来源设置，返回后再次核验，再交给系统安装器。 |
| 图片选择 | 系统选择器按选中 URI 授权，无需全相册、公共存储或相机权限。 |
| 交互触觉 | `View.performHapticFeedback(..., 0)` 遵循系统触觉设置，无需 `VIBRATE` 或运行时授权。 |
| 网络与后台连接 | 网络及 `remoteMessaging` 前台服务权限声明齐全；类型本身没有额外运行时授权。当前产品用于手机继续桌面上的同一会话，按跨设备会话连续性用途采用此类型。 |

权限核对范围覆盖当前 Android 原生功能，没有因“权限页看不到某项”添加额外权限。实际投递仍检查系统权限、应用通知开关、事件偏好和系统频道。

## 本轮修复

1. **取消授权误报拒绝**：改为“系统通知尚未获准或已关闭”，不以曾经发起过请求推断用户明确拒绝。开启总开关时的请求流程、重试和实际系统权限回读不变。
2. **保存失败提前改变通知行为**：使用进程内已确认偏好快照；写盘期间继续读旧值，成功后才发布新值，失败还原 SharedPreferences 内存。通知线程不会因失败写入的暂态关闭值退出。失败不发送成功状态推送，页面清理本次在途旧状态并保留原值及错误。
3. **系统恢复频道后丢失 pending 提醒**：在有效通知点击入口记录具体提醒已被用户查看，保留已有划掉记录；未被用户处理的 pending 可在系统撤下后恢复，已查看或划掉的身份保持静默，新身份仍可提醒，历史完成/失败不回放。
4. **系统频道关闭不易定位**：状态提示列出已启用但被系统关闭的类别；已支持的通知页面始终显示“打开系统通知设置”，不把单频道关闭改写为全局权限被拒绝。

完整原始审计和官方 Android/AOSP 依据见 `notifications-audit.md`、`other-permissions-audit.md`；前者保留修复前行号与初始发现，不代表最终未修复状态。
