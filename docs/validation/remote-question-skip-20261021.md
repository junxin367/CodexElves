## RCA 结论

- 状态：已确认原生跳过状态与远程问题投影之间的缺口，完成代码对照、隔离原生探针和事件验证；未对用户真实业务问题执行跳过或回答。
- 现象：电脑端 Codex 已跳过问题，远程仍显示待回答卡片。
- 直接原因：跳过不会产生回答消息，旧远程读取器仍将原 `agentMessage.questions` 投影为待回答问题。
- 根因：旧读取器只排除已接受的回答，没有读取原生逐题状态中的 `isSkipped`。
- 系统性根因：远程问题投影的完成判定只覆盖回答消息与轮次结束，没有将原生面板的跳过状态纳入同一同步路径；原验证也没有覆盖跳过后轮次继续执行的场景。
- 关键因果链：电脑端跳过 → 原生逐题状态写入 `isSkipped:true` 并隐藏通知 → 不产生回答消息 → 远程原有完成判定仍返回问题 → 卡片残留。

## 已排除解释

- 仅为轮次结束同步慢：隔离用例保持轮次进行中，仅修改 `isSkipped` 即可复现旧版本残留，并由修复后的读取器清除。
- 跳过也会产生可识别回答：当前原生函数只更新逐题状态和通知；真实问题没有对应回答消息。
- 问题 ID 相同就能直接清除：修复同时核对会话、原生轮次实体、问题 ID 和标题，旧轮次或其他会话的同名问题不能清除当前问题。
- 只是网页本地隐藏：远程操作调用原生跳过函数；原生隔离探针确认同一状态确实变为已跳过。

## 异常状态溯源

- 适用约束：在同一会话、轮次和问题的原生状态已标记跳过时，远程不得继续将该问题显示为待回答；同一卡片剩余未跳过问题仍应保留。
- 约束依据及状态：用户本次修复要求；已确认。
- 本次运行前提命中判定：命中。真实原生只读检查取得已跳过状态，进行中隔离轮次验证覆盖残留场景。
- 值判断：`isSkipped:true` 是原生合法终态，不属于非法输入。缺陷位于远程消费者的完成判定。
- 实际来源与传播：原生跳过入口写入逐题状态 → 远程投影未读取该字段 → 已跳过问题继续显示。
- 最后满足约束的状态与首次违反点：不适用非法值溯源；首次行为违反发生在远程将原生已跳过的问题重新投影为待回答时。
- 调查边界：核对当前安装版原生模块及隔离运行；不保证未来 Codex 内部模块结构不变，也没有捕获 Android 真机的执行过程。

## 修复与防复发

- 原生适配器升级为 `61`。唯一识别跳过函数并探测其逐题状态族，复用原生状态和通知隐藏逻辑。
- 按会话、轮次实体、问题 ID、标题确定原生问题身份；身份不确定时拒绝修改。
- 读取问题时过滤原生跳过状态；复用事件读取同步已跟踪的问题和通知，不增加轮询。
- 网页仍通过 `/api/action/answer` 和稳定回执发送，跳过参数为 `response:{skip:true}`。普通提交保留 `response:{answers}`。
- 多问题卡片跳过全部尚未完成问题，不发送预选项或输入草稿。部分题目已在电脑端跳过时，只显示剩余问题。
- 提交中、未知结果和重复请求继续受原有保护；未知结果只核对状态，不自动重发。
- 只读时隐藏操作按钮；离线或没有问答回复权限时禁用操作。
