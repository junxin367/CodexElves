# 原生 Fast 菜单不显示修复验收

日期：2026-10-21。

## 原因与修复范围

对本机 Codex `26.1013.4894.0` 进行只读检查，确认增强总开关和原生 Fast 开关均已开启，原补丁 `v2` 已执行，账号为 API Key，`gpt-6.1-sol` 的模型目录声明了 `priority / Fast`。

真实模型菜单组件同时读取当前模型的服务等级选项和账号能力。前者已得到 Standard、Fast 两项；后者只传入 `hostId`，被旧补丁新增的必填模型检查判断为未知模型，返回 `null`。菜单要求账号能力非空且当前模型选项超过一项，因此隐藏了 Fast。

本轮恢复原生账号能力钩子的可选参数契约：

- 没有 `model` 字段时，仅读取账号能力，继续遵守认证、增强开关和原生 requirements。
- 明确传入 `model` 时，按解析后的实际模型及别名检查 GPT；空值、未知和非 GPT 保持关闭。
- 当前会话或草稿的模型设置入口始终显式传入 `modelSettings.model`，所以账号能力可用不会让不支持的模型产生 Fast 选项。请求和两类队列的模型门禁保持原有规则。

补丁执行标记及启动探测升级为 `v3`，失败恢复键同步升级；资产发现兼容 `v2`、`v3`，避免升级期间丢失原生模块路径。没有修改产品版本号。
