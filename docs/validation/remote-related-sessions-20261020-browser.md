# 远程相关会话浏览器验收报告

日期：2026-10-20

## 验收边界

- 使用 Chrome 浏览器，通过 CUA 打开隔离页面 `http://127.0.0.1:57160/#thread=main-1`。浏览器页面是真实渲染的产品 UI；会话、历史、创建、发送、关闭和状态更新均由 `temp/related-threads-20261020/server.mjs` 的模拟 API 提供，不连接真实 Codex 会话或公网服务。
- 桌面默认视口和 `390×844` 移动视口均已检查。移动视口通过文档化的 viewport capability 设置，结束前已 reset 回默认尺寸。
- 没有修改产品代码，没有停止 QA 服务，也没有清理已有临时目录。新增文件仅为本报告及下方两张验收截图。

## 浏览器 UI 结果

- **主会话菜单通过。** 菜单依次显示“工具、子代理、侧边会话”；分组标题字号较小且左对齐。初始状态显示“代码检查代理、界面实现代理”及各自更新时间、“已完成 3 个”；“新建侧边会话”位于既有“侧边讨论一”之前。原有“变更”入口可打开，点击“返回会话”回到当前主会话。
- **子代理页通过。** 页面正文按主会话消息样式渲染；顶栏只保留右上“返回”。页面没有输入框、发送、停止、编辑、审批或 queue 控件。移动视口下可上下滚动；刷新子代理页后仍显示返回按钮，返回后定位到主会话。
- **主会话草稿与滚动恢复通过。** 在主会话填写未发送草稿并滚到中段，进入子代理后返回，草稿内容和中段阅读位置都保留。后续刷新和移动视口往返也没有覆盖主会话草稿。
- **侧边会话隔离通过。** 对既有 `side-1` 发送一条合成验收消息后，正文与夹具请求记录都显示发送目标为 `side-1`；主会话历史保持 4 条，`side-1` 历史从 2 条增至 3 条。离开并重进后侧边草稿保留，主会话草稿仍未改变。
- **新建侧边会话通过。** 从 `main-1` 创建 `side-2` 时仅记录一次 `createSideThread` action；页面进入新 ID 并展示继承的 4 条主会话历史。`side-2` 草稿重进后仍保留，主会话历史仍为 4 条。
- **关闭侧边会话通过。** 对“侧边讨论一”右键只出现“关闭会话”一项；选择后该项从菜单移除，夹具中 `side-1` 仍保留 3 条历史，未删除消息。随后菜单仍能正常打开。
- **长按关闭入口通过（桌面视口）。** 在 `main-1` 菜单中对 `side-2`（“新建侧边讨论”）执行 CUA 指针按下 3000ms；按下约 650ms 后、尚未释放时抓取截图并读取 AX 树，均显示该行已展开且出现“关闭会话”。释放后 URL 仍为 `#thread=main-1`，没有进入 `side-2`；随后夹具状态确认 `side-2` 仍开放且保留 4 条历史，未执行关闭。该次补验使用默认 `1920×1080` 视口；本轮 CUA 接口未提供 viewport 覆盖或页面 CDP 能力，因此未在 `390×844` 下重复长按验证。
- **浏览器历史与主会话隔离通过。** 浏览器后退从侧边会话回到 `main-1`，前进回到原侧边会话。切换 `main-2` 后菜单显示“暂无运行中的子代理、已完成 0 个、暂无侧边会话”，没有带入 `main-1` 的子代理或侧边项。
- **原有分组流程通过。** 侧边“历史”分组可折叠、重新展开；恢复后仍可切换会话。最新源码下再次打开“变更”页并返回，也回到原主会话。
- **完成状态及计时请求通过。** 对夹具 POST `/qa-config` 设置 `agentDone:true` 后，菜单更新为“已完成 4 个”，菜单仍可用。4 秒采样内 `/api/read/relatedThreads` 数量保持 `13→13`；同期所有 `/api/read/*` 总量增加 1，检查日志为 `/api/read/sidebar` 周期请求（约每 15 秒一次），没有证据表明菜单的每秒更新时间触发了重复相关会话读取。夹具日志没有任何 `threadId=agent-*` 的 `/api/action/*` 请求。

## 未覆盖范围

- 本验收证明 Chrome 中产品 UI 与本地模拟 API 的交互；不证明真实 native 接入、真实 Codex 会话读写、安装包或设备行为。
