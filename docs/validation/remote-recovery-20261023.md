# 远程会话线路与媒体恢复修复

日期：2026-10-23，北京时间。修复基线为 `c31606ee40589c87ba1c2ab1ad48b4d9727e934f`。

## 修复范围

- 连接测速按授权代次、Origin 和通道凭证复用仍在途的请求。最快线路仍可立即返回；慢线路最多观察 15 秒，不再因新的状态轮询重复发起同一路测速。每个调用者分别执行响应校验；单个调用者取消不影响其他调用者，退出授权后不接受迟到结果。
- 只读请求顺序恢复：会话状态、通道发现、事件补读、回执查询、`/api/read/*` 和工作区只读接口在存在可用备用线路时，当前尝试超过 8 秒，或测速确认当前线路失效，即尝试另一条授权线路。每个操作最多尝试两个不同 Origin。
- 备用线路在请求期间恢复时，也会重新检查候选和原请求已经等待的时间。只有一路可用时仍使用调用者原有截止时间。
- 用户主动取消、授权切换、HTTP 权限拒绝及服务身份校验失败不触发上述自动恢复。问答、审批、消息等 `/api/action/*` 仍只提交一次，继续保留幂等键与未知结果保护。
- 事件补读和通道发现的定时器明确使用 `TimeoutError`，避免把超时记录为主动取消。
- 视频封面在授权候选线路间有限尝试，成功后恢复显示；普通附件图片按缩略图候选、原图候选的顺序回退。
- 视频播放遇到网络错误，或连续 15 秒无播放进度时，切换未尝试的候选线路并保留播放位置和用户播放意图。暂停、后台、关闭、取消和格式错误停止恢复；不自动启动用户尚未要求播放的视频。
- Android 原生媒体读取失败生成的本地 502，仅对已经通过媒体来源校验的当前页面 Origin 附加 CORS 响应头，避免把本地读取异常掩盖为远端 CORS 配置故障。
- 会话读取超时文案同时提示线路与桌面就绪状态，不再只提示桌面未启动。
