## 实际使用中发现的设置及恢复问题

首次请求明确传递 `gpt-6.1-sol` / `max`。随后普通排队消息省略
`reasoningEffort` 时，服务端将它清空，导致原生后续请求使用 `high`。

修复：

- 同一模型的后续消息省略等级时，保留当前等级。
- 显式空字符串仍可恢复默认；切换模型时不继承旧模型的等级，显式设置仍按原生能力校验。
- 从默认空值切换到 Max 时，也发送原版 `/effort max` 命令。

修复后的原生请求日志在 `08:18:46Z`、`08:19:24Z`、`08:20:19Z`
均记录 `model=gpt-6.1-sol`、`output_config.effort=max`。
网页刷新后追加消息，同一会话保存的等级仍为 `max`。

重启独立验收服务时还观察到 WSL 原生后台退出。直接执行
`--bg --resume` 会因原生运行标记产生副本，接入层拒绝绑定并停止了该副本；
原会话没有接收这次失败的继续消息。使用原版 `respawn 38515c78` 验证可恢复
同一原生 UUID 后，才继续网页消息。

修复后的连接端在已有后台身份失联或结束时使用原版 `respawn`，
核对同一 UUID 和后台 ID，恢复所选模型及等级后只提交新消息。
查询超时或协议错误不视为原任务已结束，不据此重启或重发。
该修复用于原生恢复，不承诺 WSL 发行版在所有服务退出情形下都保持执行存活。
