# 远程工具授权与多请求验收

日期：2026-10-18。

用户已确认，多项请求未全部显示发生在同一个聊天内。本次验收覆盖该范围，不扩大到其他聊天或子代理会话的请求聚合。

## 处理结果

- 截图中的 Chrome Developer Tools 授权按本机 Codex 的 MCP 工具授权合同识别，显示“允许一次”“拒绝”；只有原请求声明支持时显示“始终允许”或会话范围选项，不再要求填写 JSON。
- 同一会话的多个授权、阻塞问答及异步问答分别保留卡片和提交状态。多项同时存在时显示待处理数量，内部可滚动查看；新增请求或处理另一项时保留未提交输入和焦点。
- 原生桥接经核对会完整枚举当前会话的待处理请求及当前进行中轮次的异步问题，本轮没有修改 `native.js`、会话归属或审批权限策略。

## 原因与证据边界

| 问题 | 直接原因与修复依据 | 已验证范围 |
| --- | --- | --- |
| 高风险授权要求 JSON，按钮显示提交 | 网页只按 `mcpServer/elicitation/request` 的 form 模式进入通用 JSON 表单，未像本机 Codex 一样识别 `_meta` 中的工具授权标记。原生生产者、解析器、卡片及响应构造函数已交叉核对。 | 原生“允许一次 / 始终允许 / 拒绝”的字段映射；普通有字段表单不被误判为批准卡 |
| 多项请求交互不稳定 | 原网页重绘会清空根节点并重建异步卡片；阻塞输入只在 DOM 保存，部分状态变化后丢失；没有待处理总数提示。 | 新增请求、逐项提交、独立禁用、输入与焦点保持、单项包含多个问题 |
| 用户当时只看到一项 | 当前原生缓存没有待处理请求，无法完整回放截图当时的全部事件顺序。对现行原生集合枚举未发现首项截断。 | 不宣称已复现原生丢失请求，也不把其他会话或已结束轮次混入当前会话 |

此前实现将普通 MCP 表单和工具批准共用一个网页分支，缺少针对原生自定义授权元数据以及“多卡片重绘时输入保持”的契约验证，是已确认缺陷进入远程界面的实现与验证缺口。新验证覆盖这些分支，但不代表其他未列出的原生表单类型都已适配。

## 完整网页浏览器验收

使用本地端口 `1473` 的隔离服务，运行实际 `app.js`、样式和事件客户端；API 仅操作内存合成数据，不转发到真实 Codex，也不实际授予任何浏览器权限。

1. 首屏同时存在 6 项：两个工具授权、一个包含两题的阻塞问答、两组异步问答、一个命令审批。
2. 工具授权没有 JSON 输入框；有持久权限的请求显示“始终允许”，另一个不显示。
3. 在三处问题输入草稿后，通过事件新增文件审批；待处理数从 6 变为 7，输入值、焦点和滚动位置保持。
4. 依次完成工具持久授权、请求 ID 为数字 `0` 的单次授权、一组两题异步问答、两题阻塞问答、另一组异步问答、命令拒绝、文件允许。
5. 最终待处理数为 0，共收到 7 条互不重复的请求响应；每次只移除对应项，其余问题及草稿保留。
6. 单独验证工具授权“拒绝”，响应为 `{"action":"decline","content":null,"_meta":null}`，仅移除对应项，其余 5 项保留。
7. 最终显示复核确认 `tool_params_display: []` 时没有参数详情、JSON 输入或重复网站信息；有、无持久授权能力分别显示三、两个按钮。
8. 浏览器控制台没有脚本错误。

详细状态与实际请求体见 `browser-integration.json`、`browser-deny.json`、`browser-final-display.json`。最终移动端截图为 `approval-multi-mobile-final.jpg`。

原生源码契约检查 11/11，网页源码检查 20/20，最终参数显示检查 5/5；结果分别见 `native-contract-results.json`、`ui-source-checks.json`、`ui-display-checks.json`。检查均在隔离环境中执行，不属于真实原生授权往返。最终 `node --check` 与 `git diff --check` 通过。

## 授权范围

“始终允许”使用原生响应 `_meta.persist`，不向 `content` 填入自造字段，也不添加 `all-sites` 等扩大范围的选项。截图中的 raw CDP 请求仍绑定其原始资源与 origin。断线、只读、未开放远程审批、请求已结束及重复提交的门禁保留。

数据库执行绑定等专用原生合同本次没有实现，明确提示在桌面处理；具体边界见 `ui-validation.md`。本次没有处理真实待授权项、安装、重启正式服务、提交或推送代码。
