# 远程侧边会话与 Codex 桌面主列表隔离修复

日期：2026-10-21（北京时间）。

本报告记录的持久分支及桌面目录过滤方案已按用户后续要求撤回。当前实现直接共用 Codex 原生临时侧边会话及标签状态，不再使用本报告中的目录过滤组件。以下内容仅作为此前调查记录。

## RCA 结论

- 状态：已确认，适用于本机 Codex `26.1013.4894.0`。
- 现象：远程新建的持久侧边会话会出现在 Codex 桌面左侧会话栏，即使原生 `sideConversation` 标记已正确设置。
- 直接原因：桌面侧栏从持久目录取得条目后重新生成会话入口；这个目录中的条目不带内存中的侧边会话标记。
- 根因：项目将侧边会话持久化为 `ephemeral:false` 的原生 fork，同时只在远程列表和原生会话管理器中恢复侧边标记，遗漏了独立的桌面持久目录。
- 系统性根因：侧边会话的持久登记没有用于桌面目录的查询、分页、缓存及合并入口；仅从内存会话的身份判断是否隐藏，无法保证两套列表来源的一致性。
- 关键因果链：持久 fork → 持久目录收录 → 原生管理器已过滤该会话 → 桌面目录仍返回该条目 → 桌面侧栏通过目录入口显示。

## 已排除解释

- 创建时遗漏 `sideConversation`：修复前真实会话已为 `true`。
- 远程菜单过滤错误：真实会话已从原生最近列表和摘要列表排除，漏显来自桌面的另一目录来源。
- 只需刷新最近会话：修复前刷新后桌面节点数量仍为 1。
- 必须改回临时会话才能隐藏：修复后保持 `ephemeral:false`，继承上下文及可写身份均正常。

## 异常状态溯源

- 适用约束：远程创建且已登记的侧边会话，无论是否从远程菜单关闭，都不得进入 Codex 桌面主会话栏。
- 约束依据及状态：用户本轮要求，以及此前“关闭时仅从侧边列表移除”和持久保留的明确约定；已确认。
- 本次运行前提命中判定：命中。
- 场景命中证据：真实创建结果及持久登记的父子关系均已确认。
- 值判断：目录向主会话栏提供已登记侧边会话，违反约束；`ephemeral:false` 本身符合持久保留约定。
- 值的实际来源与传播路径：原生持久 fork → 原生目录分页 → 目录控制器及合并索引 → 桌面会话栏。
- 最后满足约束的状态 → 首次约束违反点：原生最近列表已排除侧边会话 → 独立目录再次将同一 ID 提供给主会话栏。
- 调查边界与未知上游：原生目录允许列出持久会话属于合法行为；本项目负责把侧边登记落实到主列表排除条件，不要求修改 Codex 的磁盘数据或归档状态。

## 修复与防复发

- 新增共享隔离组件 `assets/inject/remote-side-threads.js`，由桌面增强脚本和远程原生桥共同加载。
- 桌面目录查询使用原生 `excludeThreadIds`，保留原来的项目、手动顺序及其他筛选条件；只过滤 `local` 环境。
- 已加载的分页缓存和合并索引同步排除侧边条目，保留稳定的数组引用；目录后续发布也不会把条目重新加入。
- 原生目录服务为不可写 RPC stub，因此在目录控制器上安装转发层，不向 RPC stub 写属性。
- 创建前确认隔离组件就绪，原生创建回调取得 ID 后立即排除；持久登记完成后继续使用同一身份。
- 桌面启动按持久登记恢复，并监听原生全局状态成功更新；关闭的侧边会话继续隐藏。
- 目录控制器替换及组件卸载时恢复原有方法和订阅；原生桥版本升级为 `56`。
- 未改动上下文继承边界、独立标题、远程菜单数量缓存和关闭时保留历史的约定。
