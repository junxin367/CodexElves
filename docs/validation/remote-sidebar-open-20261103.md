# 手机会话栏刚展开即收起：修复与验收

日期：2026-11-03。

## RCA 结论

**已确认本次复现的初始化路径。** 首次连接先展示页面，再等待目录；等待期间用户可展开侧栏。目录完成后，自动进入新建页复用了手动新建的`startNewChat`，其中无条件调用`closeMobileSidebar`，覆盖了用户刚完成的展开。

另外两条源码时序也已通过失败回归验证：切换会话等待缓存、新建会话等待项目读取之后才关闭侧栏，同样可能覆盖等待期间的较新展开。原设计已有“自动恢复不收起侧栏”的约定，自动新建路径未落实；既有导航测试把关闭操作设为空函数，无法发现这类时序错误。

## 修复

- `startNewChat`增加`closeSidebar`选项，缺省保持手动入口关闭。
- 自动欢迎/新建流程传入`closeSidebar:false`。
- 显式新建和选择会话的关闭动作放到异步等待前，不在读取结束后再次关闭。
- 未增加防抖、定时器、额外状态锁；没有修改触摸、焦点、断点或遮罩逻辑。

## 回归与排除项

三个新增时序测试在旧码均按“展开被错误覆盖”失败，修复后完整前端回归115/115通过；JS语法、定向差异检查通过。

按钮和遮罩属于兄弟节点，同一按钮click不会按正常冒泡路径到遮罩；打开按钮仅有一个onclick。焦点处理不直接关闭侧栏，普通`thread`响应后也没有无条件关闭。宽度跨760px的布局切换、进入真实子会话后的隐藏仍按原交互保留。

## 验证边界与收尾

新标签首次未应用手机尺寸，随后调整宽度时准备请求超过了有效拦截窗口；该次不计通过。正式对照在390px下、有效请求窗口内重新完成。测试地址旧静态缓存已清理并关闭旧标签，修复版实际脚本经过核验，不能用服务端文件存在代替页面身份。

本轮没有手机真机事件轨迹，结论限于上述真实浏览器可重复路径；缓存/项目等待的另两条时序由行为回归覆盖。没有操作Windows桌面、发送测试消息、重新打包、安装、提交或发布。专用浏览器已退出并确认登录框可见，拦截及视口恢复，标签关闭；测试服务正常停止。未操作用户原45222服务或更换原生运行适配器。
