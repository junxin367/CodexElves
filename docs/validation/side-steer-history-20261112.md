# 侧边会话引导正文重复与重进丢失修复

日期：2026-11-12。网页资源：`2026111207`。原生桥：`141`。

## 真实问题与原因

截图对应侧边会话 `01a1cb76-3c39-7400-8fd1-6ec0721fb845`，父会话
`01a1c853-aacc-71d1-81ce-fb7f0be1bf78`。出问题的原生轮次为
`01a1cb84-fe85-7423-a808-1a46de6d13bb`。

修复前的正式接口完整分页中，该轮只有初始用户消息，以及 5 个 `steered` 状态项；
已接受的引导正文没有返回。页面重新进入后也只显示初始输入和过程中的引导状态。

原因有两处：

- 原生 `steeringUserMessage` 被投影为 `userMessage` 后使用服务端消息 ID，
  原生 `steered` 确认也使用同一个 ID。侧边历史的 Map 按 ID 合并时，后出现的状态覆盖正文。
  元数据来源表中也有相同覆盖问题。
- 成功回执把 `pendingSteer` 换成新对象，后续异步历史读取仍用原对象作身份比较，
  导致本次预览无法清理。原生正文早于 HTTP 回执时，也缺少跨轮次的逻辑消息身份确认。

## 修正

- 原生执行中完整读取和结束后分页统一投影，同 ID 的确认状态保留正文。
- 原生时间与逻辑消息元数据同样优先保留正文来源。
- 网页的完整轮次、单项实时事件、历史合并及迟到旧状态均遵守相同规则。
- 引导预览沿用同一对象，以原生队列 ID 或逻辑消息 ID 确认送达，不依赖文字比较；
  异步读取只清理自己的预览，不能清掉后续操作。
- 保留相同正文但不同原生身份的合法消息，以及暂时没有关联正文的状态记录。
