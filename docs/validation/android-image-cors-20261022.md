# Android 图片双线路加载检查与修复

日期：2026-10-22，北京时间。

## RCA 结论

- 状态：**部分确认**。跨线路图片加载缺陷已由真实 Chrome 反事实验证，修复并热更新；手机截图当时的失败请求尚未捕获，不能据此认定所有图片失败均已闭环。
- 现象：Android 新 APK 已安装并重开，同一会话出现四张缩略图重试占位，或缩略图可见但点击后显示“图片不可用”。用户此前确认同手机同网络浏览器较少发生，ngrok 有延迟且消息正常。
- 直接原因：图片加载触发 `onerror`；缩略图只回退原图，大图直接显示不可用。
- 根因：网页按延迟选中第二入口后，图片变为跨源请求；图片元素未启用 CORS，服务端响应仍有合法的 `Cross-Origin-Resource-Policy: same-origin`，导致浏览器拒绝使用响应。缩略图与独立大图分别遗漏了 CORS 设置。
- 系统性根因：既有双线路图片回归仅用 HTTP 客户端验证状态和类型，缺少浏览器是否实际显示图片的验收。
- 关键因果链：第二域名图片地址 → `no-cors` 图片请求 → CORP 拦截 HTTP 200 → 图片错误事件 → 重试占位或大图不可用。

## 已排除解释

- Android 静态资源存储直接导致图片 API 读取失败：资源清单拒绝 `/api/`，API 图片交回 WebView 网络。
- 旧 APK 没有新图片路由能力：用户已确认安装新包；但未直接读取手机当次能力和网页资源版本。
- 当前 App CSP 单独禁止 ngrok 图片：原生和服务端 CSP 均允许现有 zrok/ngrok 媒体域名。
- 单纯放宽 CORP 才能修复：真实 Chrome 对照表明，通过现有 CORS 授权即可显示。

## 异常状态溯源

- 适用约束：在设备已授权、线路属于同一服务且媒体令牌有效时，图片应能沿支持的可用入口显示；远程会话文档“图片、封面及视频地址沿当前延迟较优的可用入口读取”及用户双线路要求为依据。
- 本次运行前提命中判定：隔离 Chrome 复现命中；手机截图当次无法判定。
- 值判断：CORP `same-origin` 本身合法，问题在图片消费者未使用现有 CORS 契约。
- 来源与传播：注册图片路径 → `remoteMediaUrl()` 第二域名及媒体令牌 → `img.src` → 无 CORS 请求 → 浏览器执行响应策略 → `onerror`。
- 调查边界：没有手机截图当次 HTTP 状态、响应类型、失败地址或 WebView 错误；源文件删除、引用过期、网络波动或隧道提示页仍可能独立产生图片错误。

## 修复与防复发

- `loadAttachmentThumbnail()` 对远程图片在设置地址前设置 `crossOrigin="anonymous"`，覆盖附件、队列、图片查看记录、Markdown 及原图回退。
- `openImagePreview()` 对远程原图在设置地址前启用同样的 CORS，覆盖 Android 和浏览器的独立大图。
- 保留服务端 Origin 白名单、媒体令牌、授权复核与 CORP。内联图片行为不变。
- 未叠加自动换线路重试；`img.onerror` 无法判断网络、授权、文件缺失或格式错误，不能据此认定另一线路一定成功。
- 今后双线路图片验收应包含真实浏览器自然尺寸和错误事件，不能仅根据 HTTP 200 判断显示成功。
