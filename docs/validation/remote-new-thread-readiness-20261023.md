# 远程新建会话初始化读取恢复

日期：2026-10-23，北京时间。

## 问题证据

截图对应会话为 `01a168e5-35bd-7f30-97aa-e164ba877fb4`。

- 原生日志记录首轮 `turn/start` 在 21:13:36.149 成功。
- 21:13:36.376、21:13:36.496、21:13:36.501 的 `thread/read` 返回 `-32603`，具体错误为 `failed to read session metadata … rollout at … is empty`。
- 会话文件首条 `session_meta` 的时间戳为 21:13:36.510。该时间戳是元数据记录时间，不作为刷盘完成时间。
- 21:13:49.626 起，同一会话的设置及历史读取成功；创建回执为 `completed`，首轮为 `accepted`。本轮实时只读检查也能取得会话和正在运行的首轮。

已确认新建后的读取遇到了短暂空文件状态；原生存储内部的写入与刷盘机制未被直接观察。本次修复针对远程读取恢复，不修改原生存储文件。

## 修复行为

修改 `assets/remote-access/native.js`，原生适配版本从 70 升至 71。

- 设置和历史继续共用原生 `thread/read`。仅当原生内存记录表明会话创建不足 15 秒时，才允许恢复初始化读取；支持原生秒级和毫秒级创建时间。
- 错误必须同时匹配 `-32603`、会话元数据读取、`rollout at`、当前会话 ID 的 `.jsonl` 文件和 `is empty` 结尾。其他错误不重读。
- 最多额外读取 5 次，间隔为 100、200、400、800、1000 毫秒；同时受创建时间加 15 秒的截止时间限制。持续失败保留原错误，不返回伪造的会话或空历史。
- 同一管理器、同一会话的并发设置和历史读取共用在途请求；不同会话不共用结果。正常读取没有额外等待，也不保留读取结果缓存。
- 管理器替换、释放、桥接释放或会话永久删除时停止后续重读；删除仍返回 404。
- 创建、首轮提交、目标设置及操作回执的代码不变；恢复过程只调用读取接口。
