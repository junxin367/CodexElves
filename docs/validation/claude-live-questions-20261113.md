# Claude 实时问答验收

日期：2026-11-13。

## 修复内容

原生 Claude 等待用户回答时，问题可能只存在于后台实时 `block.questions`，尚未写入 JSONL。此前连接端只从未完成的历史 `tool_use` 生成请求，因此网页没有问答卡片，并继续显示执行计时。

- 实时连接和历史会话首次打开均从同一原生会话的实时问题生成 `item/tool/requestUserInput`，复用 Codex 已有问答卡片、草稿、审批权限和提交回执。
- 单问、多问、选项和自由输入均保留原生语义。等待问答使用 `waitingOnUserInput`，不继续显示工具运行计时。
- 问题身份绑定原生会话、后台任务、等待代次和完整问题内容。重新读取不会重复弹卡；问题变化、已结束或已提交时拒绝迟到回答。
- 原生后台 `reply(text)` 只回答第一问，因此多问通过原版问答面板逐题填写，再核对完整汇总后一次提交。单问单选沿用原生直接提交行为，不把回答发送成新聊天消息。
- 自由输入在核对焦点后的原生回答框内使用粘贴，终端控制字符被拒绝。遇到不认识的面板或答案汇总不匹配时不提交，也不取消原任务。
- 当前 CLI 实时问题摘要不提供多选属性。连接端只按同一原生问题实际显示的复选框补齐；属性补齐时保留网页已填写答案。未提供完整问题数据时显示需在原版 CLI 回答的提示。
- 只读发现缓存仅保留问题、选项等必要字段，不引入 `providerEnv` 或原生任务中的其他私有配置。

## 验证

使用独立测试 WSL、原版 Claude Code 2.1.323，模型 `gpt-6.1-sol`，推理等级 `max`。测试使用临时项目和 `CLAUDE_CONFIG_DIR`；测试提示只要求调用问答工具、复述答案，不执行文件或命令操作。

| 验证项 | 结果 |
| --- | --- |
| 双问选择选项 | 两项答案在同一个原生问答结果中出现一次，原会话继续 |
| 双问自由输入 | 自定义文字完整到达原生结果，包含 `/` 的文字未被执行为斜杠命令 |
| 单问选择选项 | 原生直接提交成功，没有多发一次汇总确认 |
| 单问自由输入 | 原生结果与网页输入一致，仅出现一次 |
| 多选预设选项 | 按原生复选框提交完整集合，不误当成带引号的一项自定义回答 |
| 多选自由输入 | 正确退出文字焦点、保留 Other 勾选并进入原生汇总，原会话继续 |
| 已有会话只读发现 | 恢复同一实时请求身份，不启动 CLI 或新会话 |
| 原生记录尚无问答工具 | 无历史工具调用的夹具仍生成完整实时问答卡 |
| 草稿、重复提交、问题更换 | 缺答保留草稿，已提交不重发，迟到答案不进入新问题 |
| 等待显示 | 原生等待回答时不继续显示工具运行计时 |
