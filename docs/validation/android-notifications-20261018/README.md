# Android 通知功能交付验证

2026-10-18，源码实现与本机验证：**PASS**。通知与设置入口仅在 Android App 开启；普通手机网页没有可见入口，也不会发出通知桥接请求。

## 已实现

- 设置“字体大小”下方的“通知事件”入口，同一弹窗切换到二级页面；左上标题同步变化，右上关闭图标替换为返回图标。
- 原生私有通知偏好：总开关默认关闭，授权、问答、执行完成、执行失败四类默认开启。
- 系统权限申请、拒权提示和系统通知设置回读；异步保存失败不伪造成功，迟到回复不重开旧页面。
- 原生后台通知连接、四类事件频道、安静的连接状态频道；仅接收会话标题和事件元数据，不再次下载正文或附件。
- 同会话多个请求、数字 ID 0、异步问答、实时完成/失败、重连补读、撤下与去重；已知子代理不产生主会话提醒。
- 通知点击只打开目标会话；退出、权限或身份变化使旧连接失效。用户划掉和程序撤下的待处理通知分别记账。

## 浏览器验证细节

浏览器读取完整生产网页，原生桥和系统权限使用本机隔离服务。它验证实际页面行为和桥接字段，不等于 Android 系统权限弹窗、状态栏通知或真实后退手势验收。

- 普通手机网页：通知入口隐藏，通知桥请求和桥监听器均为 0。
- Android 默认页面：入口紧随字体大小，二级页标题为“通知事件”，右上为“返回设置”，四类开关齐全；外观恢复默认与版本按钮在二级页隐藏。
- 6 次设置写入均为严格的五布尔字段；2 次权限请求和 1 次打开系统设置请求均正确关联原请求。
- 保存失败立即显示中文提示、解除忙状态并保留上次设置，重试后可正常保存。
- 拒权保持用户开启意图，但明确提示当前不能接收通知；系统设置返回的原生状态更新能刷新页面。
- 返回按钮和 Escape 回到原设置页，20px 字号保持；320×360 下原设置页滚动位置前后均为 127px。
- 模拟原生返回先回设置首页，再关闭弹窗，两次均确认由网页接管。
- 返回后迟到的读取回复不重新打开二级页面，入口恢复可用。
- 模拟通知点击关闭弹窗、打开目标会话；切回后“通知跳转前的草稿”仍完整存在。
- 旧 App 不响应新协议时显示更新提示，不生成虚假开关状态，仍可返回和关闭。
- 最终桥监听器为 0；所有会话动作写请求为 0。

部分初始样本使用文案精简前的“接收偏好/外壳”措辞，最终仅替换为“通知/App”，未改协议或条件；最终页面与旧 App 提示已重新加载核对。异步受控开关的失败回滚使 `setChecked` 的即时断言失败，改为真实点击并观察后续状态验证；旧 App 的 5 秒超时恰好超过首次定位等待边界，随后状态核对正常。侧栏遮挡时改用实际可见的当前会话项导航，没有为这些验证操作问题修改产品。
