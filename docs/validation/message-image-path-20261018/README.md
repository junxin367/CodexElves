# 会话消息中的本地图片渲染修复

本次仅修改 `crates/codex-elves-core/src/remote_access.rs` 的 `eligible_image_path`，增加 5 行 Windows 路径兼容逻辑。前端、Android 源码和既有未提交修改保持不变。

## RCA 结论

- 状态：已确认，范围为真实消息重放、生产服务端函数及隔离浏览器验证。
- 现象：用户截图中已发送回复的图片显示为 `[附件：手机登录页效果]`。
- 直接原因：该消息没有获得 `remoteImages` 注册项，前端找不到对应的同源图片地址，进入附件占位分支。
- 根因：原消息中的 `/E:/.../mobile-login.jpg` 在 Windows 下不能直接通过 `PathBuf::is_absolute()` 和本机盘符前缀检查；同一文件的 `E:/...` 路径可以正常读取。
- 系统性根因：图片注册边界直接将 Markdown 展示引用当成文件系统路径，没有处理两者对 Windows 盘符前导斜杠的表示差异。缺陷位于这次表示转换；未将其扩大归因为未经调查的开发流程或历史测试问题。
- 关键因果链：真实 Markdown 引用 `/E:/...` → 路径校验拒绝 → 注册数为 0 → 前端按原引用查不到图片 → 显示附件占位文字。

## 已排除解释

- 图片不存在或损坏：本机文件可读，生产读取函数、HTTP 响应及浏览器均验证同一 JPEG。
- 手机相册权限不足：该图片属于助手引用的电脑本地文件；旧实现在服务端注册阶段就已拒绝路径，尚未向手机提供图片地址。
- 前端图片加载样式或预览按钮失效：前端代码未修改，补齐生产注册结果后即显示并支持点击、Enter 打开及关闭按钮、Escape 关闭。
- 外部图片请求受限：此次图片来自本机固定磁盘，没有发起外部图片请求；网络图片和 `file:` 地址仍被拒绝。

## 异常状态溯源

- 适用约束：当助手消息引用可读取且通过现有格式、大小、固定磁盘检查的本地图片时，远程消息应提供对应的受鉴权图片显示；不得直接向浏览器开放任意本地路径。
- 约束依据：用户本次明确要求显示截图中的附件图片；`docs/remote-access.md` 的本地图片同源注册和预览约定。
- 本次运行前提命中：原文件存在、内容有效且位于本机固定磁盘；路径表示差异由真实消息和 Windows 运行结果共同证实。
- 值判断：`/E:/...` 是本次需要兼容的展示引用，不能直接视为 Windows 原生绝对路径；文件系统输入需要归一化，前端匹配键仍须保留原值。
- 来源与传播：会话原文 → Markdown 图片提取 → `eligible_image_path` → 注册列表 → `markdown-renderer.js`。
- 首次不满足需求的位置：`eligible_image_path` 将展示引用直接交给 `PathBuf` 校验，拒绝了对应可读本地图片。
- 调查边界：没有修改原消息、历史或引用格式，没有调查与此次路径差异无关的图片生成及上传流程。

## 修复与防复发

- 直接修复：仅在 Windows 下，将严格匹配单个 `/`、ASCII 盘符、冒号和根分隔符的引用转换为本机绝对路径。
- 根因修复：区分文件系统读取路径与消息引用身份，`remoteImages.source` 保留原值，因此前端仍能按 Markdown 原始引用准确匹配。
- 系统性防线：转换之后继续走已有绝对路径、固定磁盘、图片内容和鉴权检查；不增加网络访问、URL 解码或路径猜测。
- 验证范围：生产函数前后对照、真实 JPEG、隔离 HTTP 鉴权、最终 `cargo check -p codex-elves-core --lib`、修改函数格式检查、差异检查、独立只读复核和 Chrome 显示/预览。
