# Claude 原生目标与压缩接入验收

## 本次实现

- 沿用现有 WSL 原版 Claude CLI 后台连接与原生会话身份，目标使用 `/goal <条件>`、`/goal clear`，压缩使用 `/compact`。
- 网页复用现有目标栏、编辑弹窗和压缩入口；目标支持创建、替换、清除及原生状态同步，不提供没有接通的暂停、恢复或 Token 预算控制。
- 命令受理和执行完成分开处理。已受理命令不提前插入正文；目标依据 `goal_status` 更新，压缩依据原生运行画面及 `compact_boundary` 更新。
- 用户清除目标也会产生 `met=true` 的 sentinel；该记录仅表示目标结束，不能显示为目标达成。
- 原生目标评估暂停、重试等通知单独展示，不返回 hook stderr、认证信息或请求诊断。
- 压缩后的容量占用采用原生 `postTokens`；下一次真实请求接替。历史旧压缩边界不能清除新请求的等待状态。
- 普通消息沿用真实执行状态决定是否入队，目标、压缩回执不拦截聊天发送。
- 完整模型目录同时保存实例的原生命令能力，缓存格式升级为 2；执行前再次核对 CLI 的 `initialize.commands`。

## 实际 CLI 验证

环境仅为独立测试 WSL，Claude Code `2.1.322`，主模型为 `gpt-6.1-sol`，推理等级 `max`。验证期间没有调用执行工具或修改项目文件。

1. 原生初始化返回 `goal`、`compact` 命令。
2. 原生手动压缩完成：`preTokens=10139`、`postTokens=2251`，并生成稳定 UUID 的压缩边界记录。
3. 使用本次实际 `NativeSession.native_command` 适配器，验证受理 → 等待 → 压缩中 → 停止 → 空闲；受理约 4.3 秒，包含恢复已停止的原生后台，不等待压缩生成结束。
4. 压缩开始和停止前后保持同一个原生会话 UUID。恢复过程中重读旧历史，不再短暂回退为空闲。
5. 使用实际适配器设置目标，确认原生目标记录；随后清除目标，确认清除完成及同一会话身份。两次受理回执均先返回 pending，没有假报目标已完成。
6. `/goal` 无参数会打开 CLI 交互面板，因此网页状态读取只使用原生日志，不轮询执行此命令。

## 正文渲染适配

- 压缩说明使用统一中文文案，Claude 会话不再出现写死的 Codex 名称；自动压缩来源统一映射为 `automatic`。
- 仅受理、排队的命令继续留在等待区。原生开始后创建一条稳定 ID 的正文状态行，完成、中断、失败、无需压缩或结果待确认均原位更新。
- 完成边界与先前的运行条目合并，重连或下一次压缩不会删除已确认的中断、失败记录；事件仍留在发生时的原生消息位置。
- 压缩是独立于回复轮次的活动：回复已结束不能让后续压缩提前显示完成；状态补齐不重新标记会话未读。
- 输入区合并重复的压缩确认提示，不保留已结束压缩的常驻提示。目标异常显示中文摘要，原生原因折叠展示，刷新时保留展开状态。
- 目标统计映射原生 `tokens`、`durationMs`、`iterations`，复用目标详情中的统计布局；缺失或非法值隐藏，等待评估期间不自行累计耗时。
- 本轮仅补充数据映射与展示验证，复用上方真实 CLI 记录；未重新调用模型，未修改现有样式和间距。
