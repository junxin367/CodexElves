## 审查闭环

1. 原生拓扑在已删除子代理仍被旧正文引用时可以不完整。读取现在保留可确认归属的原生行，并返回完整性标记，不再阻断侧边会话。
2. 某条侧边登记对应线程已明确删除或返回 404 时，仅跳过该条；超时及其他读取错误仍正常报告。
3. 孙级子代理的原生直接父关系不再覆盖打开来源；完成、刷新及历史导航后仍返回原主会话。
4. fork、来源和登记已经确认成功、但后续原生设置同步失败时，返回已创建结果和警告，不再把创建回执永久标为未知。真正创建或登记未知时仍不自动重复 fork。

## 真实运行接入修正

首次部署时，真实 `relatedThreads` 返回 503。现场检查发现 `initial` 未出现在当前页面的 modulepreload 和 Resource Timing 中，但已观察到的 `app-main-c57bbbd6c7c5.js` 明确静态导入 `app-initial-5851df3f6cb1.js`。适配器改为只沿这个可信静态依赖补定位，仍严格限定 `app://-/assets/`、模块名及路径。

继续真实读取时，发现原生 `readGlobalState/updateGlobalState` 对顶层键有枚举限制。侧边登记读写统一改为合法 `persisted-atom-state` 容器内的命名空间字段，并以 functional updater 保留其他偏好。此前模拟环境没有覆盖这两项运行约束；本次补充了真实只读验证和相应隔离检查。原生适配器最终版本为 `50`。
