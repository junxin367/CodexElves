## 收尾发现的队列完成确认边界

八图实机验收发现，原生“引导”追加的中断提示轮次会承载完成回执：
先前受理请求本身没有 `_nativeDone`，后续提示轮次却已有真实完成标记，
导致 `awaitingTurn` 一直等待，新增消息只能排队。八图验收先通过网页引导执行，
没有重发重复消息。

协调端在原生开发结束后补了这一接入边界：顺序历史中，当前受理请求或后续轮次的真实完成回执
都可释放该等待；更早的回执不能释放当前请求，既有暂停不被解除，没有完成回执的中断仍保留暂停。
这是一处队列完成确认修正，没有改变并发队列的存储或调度策略。新增针对回归，完成后重新编译安装包。
