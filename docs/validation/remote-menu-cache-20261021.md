# 会话菜单缓存与静默更新验收

日期：2026-10-21。

## 实现

菜单的原实现只保存当前主会话数据，切换主会话会清空缓存。现在按设备授权和主会话 ID 分开保存子代理列表、执行时间、已完成数量、侧边会话标题及未读标记。

内存最多保存 32 个主会话菜单，页面重开后复用现有 IndexedDB 的只读快照。切换回来先展示缓存；事件触发后台核对，成功读取后的 30 秒内没有新事件时不重复查询。相同结果保留原 DOM，只更新执行时间；更新失败保留已有内容，不显示后台加载或错误提示。首次完全没有缓存时仍正常读取。

创建、关闭及已读操作在确认成功后更新缓存；晚到的查询不能恢复旧条目或旧蓝点。采用缓存时补齐打开和关闭所需的关系元数据；删除已完成子代理会重新核对完成数量。只读快照不替代当前权限或原生写操作验证。

## 定向验证

对实际 `session-menu.js` 使用可控请求及本地存储验证以下 10 类行为：

1. A/B 切换立即恢复各自缓存，30 秒内不重复读取。
2. 只有执行时间变化时保留同一列表节点。
3. C 的迟到响应只写入 C 的缓存，不污染当前 B。
4. 持久快照先展示，并调用关系登记回调，网络读取不阻塞展示。
5. 后台失败保留原数量和列表，不弹提示。
6. 晚到的旧持久快照不能覆盖较新的网络结果。
7. 已读与关闭同步写入持久缓存，旧查询不能恢复已清除标记。
8. 请求期间收到变动事件时合并更新，并补读最新状态。
9. 授权变更隔离内存、持久缓存及旧请求回执。
10. 本地数据库不可用时正常通过网络读取。

上述检查全部通过。独立复核另验证：缓存恢复后的关闭实际发出一次请求，只有确认成功后移除；删除完成子代理后，菜单即使关闭也会后台刷新完成数量；请求发出前授权已变化时，旧任务不会发出读取。
