# CDP 子代理列表兼容修复验证

日期：2026-11-12，Asia/Shanghai。范围：CDP 模式的原生子代理列表识别与绑定。

## RCA 结论

- 状态：已确认截图中“原生子代理列表无法识别”的代码断点；修复已完成源码与绑定验证。
- 现象：远程菜单的侧边会话仍可显示，子智能体分组返回读取失败并保留上次结果。
- 直接原因：旧识别条件要求 `getIndexedSubagentProgress:`，当前原生模块已使用 `getIndexedSubagentItems:`，因此没有模块能通过条件。
- 根因：适配器仅支持旧索引字段和行信号直接导出的结构。新版将内部详情保留为私有信号，通过公开行信号返回数组，并使用 Rspack 第三个参数声明固定导出；这两种变化都需要适配。
- 系统性根因：已有子代理读取回归将 `nativeRelatedState` 替换为模拟对象，覆盖了列表处理、父关系和订阅清理，却没有覆盖该对象的真实模块识别与导出绑定。
- 关键因果链：原生模块结构变化 → 旧标记无法匹配 → 绑定初始化抛出 503 → 子代理分组降级显示错误；侧边会话独立读取，仍可用。

## 已排除解释

- 原生模块尚未加载：运行时已加载缓存中存在对应模块。
- 单纯由网页资源缓存导致：运行中的原生桥接使用旧识别条件，而实际原生模块没有该字段；仅刷新网页不能补上绑定兼容。
- 新索引数据本身非法：它是当前原版的合法接口；断点在适配器对旧结构的限定。

## 异常状态溯源

- 适用约束：原生已公开子代理行与发现快照时，适配器应读取真实原生结果并校验父关系；失败或不完整结果不能伪装成完整空列表。
- 约束依据：用户本次修复要求，以及已有只读、父子关系和降级回归。
- 本次前提：命中。运行时模块已加载、公开导出存在，结构及引用均完成核对。
- 值判断：新版索引及包装信号属于合法原生状态，消费者兼容处理缺失。
- 来源与传播：原生状态模块 → 公开行包装信号及快照信号 → CDP 适配器 → 远程菜单。
- 首次不满足约束的位置：旧适配器以已移除字段作为必需识别标记；不存在需要修复的非法原生输入。
- 调查边界：不推断厂商调整私有接口的历史原因；该原因不影响本次适配断点判定。

## 修复与防复发

- 同时识别旧进度索引与新活动索引。
- 支持旧 getter 导出和新版固定值导出；固定值只从本模块加载器对本模块 exports 的声明中解析。
- 新版使用公开行信号，不读取未导出的详情，也不把父轮次 key 列表当作子代理行。
- 排序使用原生行计算模块，名称继续使用原生格式化函数；原有只读、真实父关系、状态验证与订阅清理规则保留。
- 新增模块绑定回归，覆盖新版、旧版兼容、错误结构、歧义拒绝与禁止执行未加载工厂。

验证结果：5 项子代理相关回归、模块入口兼容、图片桥接版本检查、关联读取降级检查，共 8 项通过。23 个网页 JS 文件的语法、import 和路由检查通过。
