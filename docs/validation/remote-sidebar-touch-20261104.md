# 手机侧栏遮罩误触保护

日期：2026-11-04。源码基线：`95de5cb9`。

## RCA 结论

- 状态：部分确认。已复现“展开后快速触到遮罩就立即关闭”，未复现“单次触摸因为接触面积较大而同时点击按钮和遮罩”。
- 现象：手机端点击左上角打开会话列表，紧接着触到遮罩，列表立即收起；期望避免刚展开时的误关闭。
- 直接原因：修复前 `.sidebar-backdrop.onclick` 无条件调用 `closeSidebar`。
- 根因：遮罩没有展开保护期，也不核对关闭手势是否在遮罩开始、正常释放且属于同一指针。快速触摸和独立关闭操作走同一路径。
- 系统性根因：已查到的防线缺口是侧栏回归未覆盖遮罩触摸序列；尚无用户手机的原始事件轨迹，不能把原生触摸分发或设备差异定为原因。
- 关键因果链：按钮 click 展开侧栏 → 遮罩显示 → 66ms 后第二次触摸在遮罩按下 → 37ms 后 click 调用关闭 → 侧栏在展开约 103ms 后收起。

## 已排除解释

- 普通按钮 click 冒泡到遮罩：按钮位于 `.conversation`，遮罩是其兄弟节点；本轮单次触摸的 click 目标仍是按钮。
- 本轮复现由异步目录、缓存或新建页回调关闭：隔离组件没有这些网络读取或导航回调，仍能复现快速遮罩关闭。
- 必须删除正常遮罩关闭功能：修复后保护期结束的独立触摸仍可关闭。

以上排除只适用于本轮对照，不能据此排除用户设备上的其他独立路径。

## 异常状态溯源

- 适用约束：手机端打开列表后，紧随展开的误触不得立即通过遮罩收起列表；正常独立点击遮罩仍应关闭。
- 约束依据及状态：本轮用户要求，已确认；300ms 是本次实现选择，不是浏览器的通用触摸阈值。
- 本次运行前提命中判定：命中本机组件对照场景。
- 场景命中证据：390px 视口、实际按钮触摸展开、约 103ms 内遮罩触摸关闭。
- 值判断：快速遮罩操作使展开状态立即回到关闭，违反上述交互要求；用户真机是否以同一事件路径触发仍无法判定。
- 值的实际来源与传播路径：`open-sidebar.onclick` → `setSidebarOpen(true)` → `sidebar-open` → `sidebar-backdrop.onclick` → `closeSidebar` → `setSidebarOpen(false)`。
- 最后满足约束的状态 → 首次违反点：按钮点击后列表展开 → 早期遮罩 click 无条件关闭。
- 调查边界与未知上游：未采集 Android 真机事件，接触面积造成的目标重定向、WebView 差异及用户是否发生第二次触摸均未确认。

## 修复与防复发

- 直接修复：在 `assets/remote-access/app.js` 的遮罩交互中增加 300ms 保护期，按触摸事件的发生时间判断；慢设备延迟派发的早期事件也不接受。
- 根因修复：要求主指针在保护期结束后从遮罩按下、同一指针在遮罩释放，再消费 click。取消、多指干扰、无按下的迟到 click、跨次展开残留不触发关闭。
- 系统性防线：本轮临时行为检查覆盖 299/300ms 边界、保护期内按下后长按释放、延迟派发、取消、不同指针、鼠标兼容、重新展开、断点切换和主动关闭。按仓库规则清理临时检查文件，未新增长期测试资产。
- 数值依据：当前最终生效的侧栏过渡来自 `style.css` 的 `--duration-popup:200ms`；300ms 为动画时长加 100ms 触摸余量。代码旁已注明联动约束。
- 保持原交互：主动选择会话、新建、Escape 等调用原有关闭入口，不经过遮罩保护；桌面展开收起逻辑保持原样。
