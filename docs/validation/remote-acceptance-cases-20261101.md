## 4. 独立判定方法

### 4.1 对象、次数和时间

- 三轮分别使用新的 `runId`，例如 `RA-20261101-R1/R2/R3`，实际执行时登记。`M`、`C` 是本轮专用主/控制会话，`P` 是本轮专用项目，`S1/S2` 是 M 的原生临时侧边；它们必须被替换为创建原始回执中的真实 ID，不能按同名标题选中。普通网页没有创建项目入口，项目由已授权桌面 UI 准备。
- `T` 是操作发生前捕获的真实活动 turn ID；`Q1/Q2/Q3` 是准确队列对象，另记其客户端消息 ID；`ED` 是原生队列编辑事务 ID；`G` 用原生目标身份（没有独立 ID 时使用 threadId+createdAt）识别；`A` 是操作请求 ID；`R` 是原生/服务回执 ID。问答另记 threadId、turnId、itemId、questionId、entityKey。
- 写操作一次指**用户动作对应的原生变更派发一次**。状态读取、轮询和查回执可以多次；未知结果后变更派发次数仍不得增加。UI 双击不能造成第二次接受。计数对象是这次逻辑操作，不是全服务 HTTP 请求总数。
- 队列编辑恢复可能由原生返回新物理 ID。成功要同时证明 `原 Q → ED/恢复令牌 → 返回 Q'` 的对应关系、未丢失的真实输入、正确位置以及只有一个可执行逻辑对象。不能无依据要求 `Q'=Q`，也不能只凭同文认定二者相同。
- 快照比较必须处于同一个服务实例、授权和对象；异步阶段分别留文件、读取标识和时间。比较期间有原生事件时记录变化并重新建立一致截面，不能从多个会话或不同时刻拼字段。
- 测试等待上限用于判定该轮是否完成，不等于产品性能承诺。现有产品文档记载 session 读取 15 秒、会话读取 60 秒及原生执行期限 45 秒；运行版本需要复核。正常网络恢复若出现本次用户报告的超时，不能因稍后刷新成功就抹去该失败阶段。尚无明确的首屏/重连耗时目标，单独记录实际耗时，不自定“秒开”指标。

### 4.2 证据类型与状态

表中 `B`=真实浏览器 DOM/可访问性树、原始截图、导航和请求时序；`N`=同 ID 的原生只读 RPC/bridge/状态/事件；`R`=真实请求与完成回执；`D`=真实 Codex 桌面 UI；`A`=实际 Android 设备 UI、生命周期及版本/日志；`W`=Windows 窗口事件、进程树和屏幕录像。原始证据记录时间、路径、摘要和精确 JSON Pointer，截图与布尔成功标记不能替代 N/R。

`passed` 只允许正常、失败及恢复分支都取得本轮证据后使用；某一分支未执行就注明该分支 `not_run`。条件不具备为 `blocked/受阻`，出现可复核不符为 `failed`，尚未执行为 `not_run`。下面所有新用例的本轮状态均为 `not_run`；历史反例作为旁注保留，不冒充修复后的失败或通过。

### 4.3 预期适用范围

1. 只读子代理页的限制独立于设备写权限，不能变成可发送主会话。读取失败只影响对应能力，不应把所有普通会话扩大为只读。
2. 当前原生目录、标签和列表行分别是关系、临时名称和运行分类的权威观察对象；本次原生恰好返回什么不能直接成为永久产品规则。
3. 客户端偏好指分组、视图、排序方式等显示选择；项目/会话的真实置顶、原生手动排列数据仍是另一类对象。选择“各客户端独立保存”不代表各客户端能产生独立的服务器置顶记录。
4. 目标标签是编辑器结构，不属于目标正文；全选替换或删除标签应取消草稿目标模式。既有目标的取消需要与原生目标清除区分；当前远程明确可见的是草稿取消、目标编辑取消，未见独立的“清除服务器目标”入口，不能虚构一个远程按钮。
5. 模型与思考深度按当前会话下一轮设置及原生能力生效，不预设每条排队消息冻结独立模型配置。实际协议还需对应供应商/代理请求证据，不能仅从显示名猜测。

## 7. 仍需进一步真实取证的产品约束

以下不阻止制定已有明确要求的用例，但阻止相关分支宣告通过：

1. **问答原始来源与实时通知**：事故时原生实际 item/turn、问题实体及 request-client 会话更新是否含该字段；远程读取、事件和本地面板分别在哪一步丢失。不能将 `requests=[]` 当作“没有异步问题”。
2. **Android 超时时序**：设备实际安装资源、visibility/暂停/恢复/系统回收时间、旧在途读取结束情况、前台首次读取与原生响应。浏览器缩窄视口、源码中的超时常量和桌面刷新成功不能替代真机。
3. **队列两条真实契约**：server/local 的原始消息与准备结果、恢复令牌、恢复后实际 ID/客户端 ID/输入、是否已经接受。报错不能自动证明原生返回非法，也不能为绕过报错放松身份校验；先明确当前 installed shape 与有效身份映射。
4. **目标标签与完成枚举**：保留行内 token 的真实键盘操作；原生 `complete` 与通用回执 `completed` 的字段分工；新建目标部分成功的实际回执。既有目标的远程清除入口未有明确产品定义，先验收草稿取消、编辑取消和原生 clear 的远程同步。
5. **子代理分类和名称**：当前原生列表行的状态、顺序、名称/agent_path 格式，以及父/孙关系发现的完整性。E1 的 9 个拓扑对象不提供全部原生 UI 分类，不能据此硬编码完成数量。
6. **独立客户端偏好边界**：用户已决定客户端独立，桌面不覆盖远程。一个浏览器同源多 tab 是否共用同一客户端、首次无本地记录的默认偏好、重授权及不同服务范围如何迁移，需要保留实际作用域记录并补齐产品定义，不能继续沿用桌面强制跟随测试。
7. **侧边命名与生命周期**：原生标签权威和自定义名保护已有要求；固定十字符自动名有文档冲突，需依据最新用户约定核定。当前临时会话不能强制走普通 metadata 改名或重启后持久恢复。
8. **停止/失败后的队列恢复、CLI 资格**：需当前原生真实行为和源版本；不得把“当前实现这样处理”升级为所有版本的产品必要条件。未知 native 结果不得 CLI 重放的约束已经明确。
9. **Windows 启动无闪窗**：需实际运行文件、窗口创建事件/录像与进程树关联。静态隐藏标志、退出码成功或进程一闪而过不能证明用户看不到控制台。
10. **性能门槛**：功能恢复必须通过；首屏、切换和前台恢复耗时分别留实测分布。当前没有明确验收上限时不编造指标，也不能用“最后恢复了”掩盖实际超时。
