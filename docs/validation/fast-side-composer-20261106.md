# 侧边会话 Fast 入口缺失修复

日期：2026-11-06。

## RCA 结论

- 状态：已确认代码原因，并通过修复前后对照验证；安装后的界面点击验收尚未执行。
- 现象：侧边会话打开默认模型菜单时，没有 Fast 闪电入口。
- 直接原因：`codexFastModelMenu` 检查菜单触发按钮，发现所属输入区不是 `main` 就跳过菜单。
- 根因：Fast 的菜单、会话身份和模型名称定位复用了主输入区限制，不能表达“当前模型菜单属于哪个输入区”。只删除菜单过滤仍会把侧边开关绑定到主会话。
- 系统性根因：已有 Fast 归属回归只提供单个输入框，缺少主、侧输入框同时可见并分别打开菜单的场景；通用主输入区限制因此进入了需要支持侧边会话的 Fast 适配层。
- 关键因果链：侧边触发按钮位于 `right-panel` → 菜单被主输入区过滤条件排除 → Fast 渲染拿不到菜单 → 不创建按钮。

## 已排除解释

- 非 GPT 模型导致入口隐藏：本次主、侧按钮均实际显示 `6.1 Sol`，只读识别均解析为 `gpt-6.1-sol`；回归另验证侧边未知或非 GPT 模型不会借用主会话模型。
- 仅为账号能力读取失败：渲染代码在能力不足时禁用按钮；本缺陷在能力判断之前就因菜单为空而不创建按钮。原生账号、管理员及 Copilot 约束继续由既有 Fast 回归覆盖。
- 应取消所有主输入区限制：上下文用量等其他功能仍需要主输入区边界；对应的两项 service tier 回归继续通过。

## 异常状态溯源

- 适用约束：启用 Fast 快捷开关并选择 GPT 模型时，主会话和侧边会话的默认模型菜单均应提供入口；设置只能作用于菜单所属会话，账号及模型能力继续决定按钮是否可用。
- 约束依据及状态：本次用户反馈及 `AGENTS.md` 的 Fast UI、会话交互约束；已确认。
- 本次运行前提命中判定：命中；Fast 已启用，两个输入区均选择 GPT 模型。
- 值判断：`right-panel` 是实际侧边输入区标识，不是非法状态；缺陷位于只接受 `main` 的消费者。
- 值的实际来源与传播路径：原生侧边输入区的 `data-app-shell-focus-area` → 菜单触发按钮的最近输入区 → Fast 菜单过滤条件。
- 最后满足约束的状态 → 首次约束违反点：标识值本身合法，不适用；入口在菜单归属过滤时丢失。
- 调查边界：未改变原生输入区标识或原生会话状态，未追溯这些合法标识的上游实现历史。

## 修复与防复发

- 按默认模型菜单的 `aria-labelledby` 找到原生触发按钮，以该按钮读取会话身份；归属未知时不借用主会话。
- 菜单关闭时按输入区焦点识别目标；主输入区通用定位函数保留原有边界。
- 主、侧输入区分别读取模型、会话偏好和名称节点，各自更新蓝色状态。
- Fast 注入模块版本由 `7` 更新为 `8`，使后续注入能够替换旧模块。
- 扩展既有测试文件，覆盖侧边菜单、焦点切换、主侧模型不同、未知归属、开关隔离、请求等级隔离及独立名称颜色。未新建测试文件。
