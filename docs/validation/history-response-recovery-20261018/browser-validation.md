# 历史响应中断的浏览器验证

结果：**PASS**。Chrome 扩展加载完整生产网页；本机隔离 HTTP 服务发送 `200` 响应头和部分 JSON，然后主动中断长度未满足的响应。未替换浏览器 `fetch` 或 `Response.json()`，因此验证包含浏览器实际的响应正文读取失败。会话、WebSocket 和回执为本机模拟数据，未写入真实聊天。

## 当前运行版本

只读访问 `127.0.0.1:45222`，确认运行服务的 `app.js` SHA-256 为 `aef2cac877935c70ccb11f59be6d815e41151ce8b51a008f05e2dd2d64b35050`，与当前未部署工作区不同，但 `api()` 函数文本与修复前工作区一致。运行版本同样会吞掉成功响应的正文异常，然后触发历史格式错误。

`runtime-manifest.json`、`runtime-source.json` 和 `runtime-correlation.json` 保存资源清单、进程信息、源码摘要及函数一致性结果。可用诊断日志中没有 `action=history` 的 `remote_access.native_read_failed` 记录；这不等于已经证明手机网络故障。未读取手机原始响应，仍不能断言用户截图一定由正文中断、解码失败或隧道异常造成。

## 实际浏览器与 HTTP 结果

| 场景 | 历史读取次数 | 结果 |
| --- | ---: | --- |
| 修复前：200 正文中断 | 1 | 出现与截图完全一致的“会话历史返回格式无效” |
| 修复后：第一次中断，下一次正常 | 2 | 原会话、原游标补读一次后恢复；不出现格式误报 |
| 修复后：两次都中断 | 2 | 停止补读，提示“响应读取失败，请检查网络后重试”；已有历史和草稿保留 |
| 网络恢复后点击原有重试按钮 | 1 | 正常读取，错误入口消失 |
| 完整 JSON 的 `data` 为对象 | 1 | 明确报告协议格式错误，不自动重试、不清空历史 |
| 读取未完成时切换会话 | 1 | 原连接关闭且没有旧会话补读；新会话内容不被覆盖 |

前后两次历史补读的请求正文逐字段一致。错误期间已有正文仍可读，原草稿始终为“这份草稿需要保留”；切回原会话后草稿仍存在。历史请求失败未将正常事件连接改成全局断线。

另用同样的真实正文中断方式验证写操作：隔离 `/api/action/send` 仅收到 **1 次**提交，随后 `/api/receipts/<原ID>` 仅读取 **1 次**。回执返回前，页面保留待确认提示和完整输入；原回执确认完成后才清空输入，没有重复发送。

## 证据

- `browser-server-baseline.json`：修复前真实 HTTP 请求记录，两次报错复现各 1 次读取。
- `browser-server-after.json`、`browser-request-checks.json`：修复后的请求次数、同游标补读及唯一写入核对。
- `browser-results.json`：DOM 状态、正文、草稿、错误提示及回执前后观察。
- `after-recovered.png`：全部故障检查后，切回原会话时单独采集的稳定画面，显示正常历史和保留的原草稿。

初始化阶段的普通历史文案不用于判断自动恢复；恢复结论依据故障请求记录、补读次数及成功后的页面状态。早期同调用截图捕获了更新前画面，已删除，不作为错误状态证据。
