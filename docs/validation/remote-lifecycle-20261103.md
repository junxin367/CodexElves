# 导航未离开页面后远程会话停止更新：修复与日志补充

日期：2026-11-03。

后续交付：用户随后要求热更新远程会话并重新构建 Android。独立远程服务已切换至本轮修复，26 项本机资源及公网关键资源校验通过，32 台设备授权和访问密钥保持不变。Android 0.1.0/code24 正式构建与 lint 通过，既有正式证书保持一致，包内资源与热更新服务版本 `5f50385520778112f4d9dad6e021b24be17ba62c95b958937b2bf84a9d3b23cf` 一致。交付记录见 `dist/validation/remote-hot-update-20261103/`；APK 已由 ngrok 提供下载并完整核对哈希，未代为安装手机或发布 GitHub Release。

## RCA 结论

- 状态：**部分确认手机现场；已复现并修复同类浏览器路径**。
- 现象：手机发送后停留旧内容，之后切换会话或编辑草稿时发送置灰，杀掉 App 重开才恢复。
- 直接原因：复现页面保留旧 `connected=true`，但 `pageLeaving=true` 已停止事件流、连接轮询和当前会话读取。切换会话后只能显示缓存，无法取得可写的当前 `thread`。
- 根因：`beforeunload` 直接调用完整的 `suspendPage()`，把准备导航当成页面已经离开。下载、取消导航或 App 接管导航后，原文档仍然存在；可见性恢复入口没有清除该标记。
- 系统性根因：原生命周期验收直接调用 `resumePage()`，跳过实际的 `beforeunload` 和 `visibilitychange` 事件组合，未覆盖“没有 `pagehide/pageshow` 的导航”。
- 关键因果链：准备导航 → 提前停止连接 → 原文档未离开 → 恢复入口继续提前返回 → 只剩旧显示；切换会话后缺少可写对象，发送禁用。

手机上传记录没有采集 `beforeunload` 或发送禁用原因，且在第二张截图对应问题之前结束，不能认定手机两次异常均已完整归因。

## 异常状态溯源

- 适用约束：原文档仍存活且可见时，访问有效的会话应能继续读取和接收更新；准备导航不代表文档已离开。
- 依据：用户要求正常返回后继续使用，不依靠杀掉 App；下载或取消导航保留原页面。
- 浏览器复现场景命中：真实下载后 URL、文档及草稿保持，只有 `beforeunload`。
- 最后满足约束 → 首次违反：有效连接及已加载会话 → `beforeunload` 内设置 `pageLeaving=true` 并关闭连接。
- 传播：连接轮询、重试和会话读取的现有离页判断均提前返回；选中会话被重置后没有取得新的 `thread`，发送按原规则禁用。
- 手机现场边界：日志未记录该标记；截图中的具体禁用条件只能等待新增日志核对。

## 已排除解释

- 不能将这次问题归为用户未安装新版：现场资源版本与刚交付的 APK 一致。
- 不能用整体断网解释：故障窗口内发送、队列和其他读取仍成功。
- 持续 IndexedDB 串行阻塞不符合已有成功发送：可靠发送在 HTTP 前也必须等待同一恢复库。
- 上一次“在线但读取失败后不补读”的修复已经存在；本次停机标记使轮询本身无法启动，不能靠重复补读修复处理。
- 早期重启期间的 relatedThreads 503 不能单独解释后续完全没有 session/thread/history 请求。

## 修复与防复发

1. `beforeunload` 只保存输入及显示状态；实际停止事件和读取留给 `pagehide`。
2. 可见性恢复时，若仍持有离页标记，复用既有 `resumePage()` 恢复，不增加新的轮询。
3. 发送禁用条件保持原有语义，记录具体 `blockedBy`；没有绕过会话身份、回执或压缩保护。
4. 新增 `page.beforeunload`、`page.visible`、`page.resume` 和 `composer.state` 诊断。记录会话 ID、连接状态、离页标记、事件流状态、代次、草稿字符数和附件数量。发送状态仅在变化时记录，不逐键记录正文。
5. 网页、Android 和电脑接收端同步校验上述字段；修复 Android 不接受数字 `readyState` 导致整条诊断被拒绝的问题。保留旧字符串状态兼容。
6. 没有记录消息正文、图片内容、密钥或 URL 查询参数；没有增加新的权限、重发或接管逻辑。

验证结果：

- 新增五个生命周期场景：修复前 3 失败、2 通过；修复后全通过。覆盖实际事件入口，不再用手动调用恢复方法替代。
- 前端状态回归 **121/121** 通过，包含发送禁用原因与诊断去重；相关 E2E 证据/环境/回执测试通过。
- Web 诊断合同检查 **88 项**、Android `DiagnosticsPolicy` JVM 检查 **295 项**通过。JVM 验证使用临时 `Uri` 桩，不是 Android 真机验收。
- Rust 诊断原有 **3 项**扩充后通过，语法、Rust 格式和差异检查通过。
