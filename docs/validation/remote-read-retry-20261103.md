# 缓存消息可见但发送长期置灰：恢复修复

日期：2026-11-03。用户反馈手机偶尔停在较旧消息，草稿可见、发送置灰，需杀掉程序重进。截图仍显示“正在读取会话设置…”。

## RCA 结论

- 状态：**部分确认**。当前源码缺口及真实浏览器同类卡住路径已复现并修复；未取得用户手机故障时的资源版本和请求日志，不能把全部手机现场归为同一原因。
- 直接原因：缓存可恢复消息、模型显示和草稿，但不会把缓存冒充当前可写会话；当前`thread`尚未取得时，发送按既有规则保持禁用。
- 根因：成功的在线连接探测原先只在“断线→在线”时补读会话。若设置/历史失败而连接一直在线，后续只检查连接及侧栏；再次选同一会话还会因`historyInitialized`或缓存存在直接返回。静默历史失败没有单独保留后续恢复依据。
- 系统性原因：已有回归验证了正常持续在线不重复全文读取、真正断线后恢复；缺少“线路一直正常但功能读取失败”和“首次恢复补读失败”的反例。
- 因果链：先展示缓存及草稿→设置/历史读取失败→连接仍在线→没有补读→可写会话对象缺失→发送持续禁用。重新进入整页会重新读取，所以可以暂时恢复。

## 证据

## 已排除解释

- 不是通过取消只读/发送保护让按钮强行可用：发送门禁没有修改；恢复时真实会话ID、`readOnly=false`和有效设置均已取得。
- 不将Android直接缓存旧API响应作为结论：Android不注册此PWA Service Worker，网页SW也直接透传`/api/*`。
- 不新增Android强制reload或未经证实的前台事件逻辑。既有读请求已有60秒上界；本轮缺口是失败后缺少重读，而非已证明底层请求永久无超时。

## 修复与防复发

1. 为会话设置和最新历史分别保留失败标记，成功读取或切换视图时清除。
2. 复用既有15秒连接探测，只补当前失败/未完成且没有在途请求的读取；正常会话不额外读取全文。
3. 同一会话只有缓存、未读完整时允许重新读取。
4. 保留草稿、历史、原未决写回执，不自动重发消息；已删除/过期会话不进入补读。
5. 新增四类行为回归：在线缓存缺设置、首次补读失败后再恢复、静默历史失败保留恢复依据、同会话重新选择。

## 未闭环项与测试边界

- 手机具体触发于后台返回还是侧边切换、现场资源版本及请求失败原因尚未取得。已确认的浏览器路径与用户现象一致，但不代替手机现场根因认定。
- 测试浏览器曾执行旧PWA资源，首次“修复版”尝试保留为`stale-asset-attempt.json/jpg`，不计通过。仅清理了独立测试地址`127.0.0.2:45430`的静态缓存，随后核对真实执行源码。
- `recovery-in-progress.json`保留修复版较早仍禁用的观察。最终取证时间包含后续诊断，不是精确恢复耗时；没有宣称15秒内必定恢复或已完成性能验收。
- 并行工作随后修改了队列按钮展示，因此当前整份`app.js`摘要不同；差异不涉及本轮读取恢复函数，不据本轮结果声称这些队列改动已验。
- 临时服务复用此前隔离环境，测试结束已写停止标记，PID36188退出、45430无监听；浏览器拦截/视口已恢复、标签关闭。没有修改原生运行适配器、操作桌面窗口、重新打包、安装、提交或发布。
