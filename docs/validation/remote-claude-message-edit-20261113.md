# Claude 历史消息编辑与原生回退验收

日期：2026-11-13。

> 本文记录的是通过按键操作原生 `/rewind` 菜单的早期实现。该方式依赖画面识别，曾因回退面板遗留导致远程会话无法继续，现已改为交接方式（停止 → 结构化回退 → respawn），行为与验收见 [Claude 编辑交接验收](claude-edit-handoff-20261113.md)。下文中关于“通过原生 `/rewind` 选择 Restore conversation”和“不为编辑停止任务”的描述已不再适用。

## 行为

- 共享 Claude 会话的历史用户消息提供“编辑并再次发送”，不局限于最后一条。是否可编辑来自每条原生消息的元数据。
- 仅在原生明确空闲时允许编辑。提交时再核对原生状态和历史头；执行、审批或原生弹窗等待期间不开放编辑，不为编辑停止任务。
- 仍使用原会话 UUID、原后台 ID、原项目目录和所选实例。执行由原版 CLI 负责，工具、MCP、Skills、Hooks 和权限机制保持原用途。
- 通过原生 `/rewind` 选择“Restore conversation”。不选择恢复代码，不直接改写 JSONL，不创建新的原生分支会话。
- 编辑只修改文字，保留原图；不增加图片增删界面。沿用最多 8 张、单图 5 MiB、合计 12 MiB 的输入限制，原图无法完整恢复时在回退前拒绝操作。
- 内部摘要、原生命令及吸收在工具轮次中的 `queued_command` 附件不伪造为独立回退节点。旧版 print 会话需先沿用已有历史发现流程接入原生共享通道。

## 数据与回执

原生回退修改驻留 CLI 的上下文和终端显示。Claude 会在 JSONL 中保留旧分支；读取端沿原生 `parentUuid` 选择当前分支，隐藏的附件节点也参与连线，压缩边界保持历史连续性。编辑不承担物理擦除旧分支的用途。

网页沿用 `remote/threadReverted` 清理失效正文及持久缓存，逐条元数据不再被“最后一条消息”字段覆盖。新消息只在原生受理证据到达后进入正文。断线或迟到读取不能补回被回退的旧消息。

编辑重发复用现有会话锁、直接发送记录和稳定回执，不进入网页待发送队列。原生回退确认后的失败保持结果未知，只核对原请求，不重复回退或重发。新输入按原生追加偏移关联客户端消息身份，避免回退后序号缩小导致漏认新消息。

当前分支的本轮用量、步数和上下文随原生数据更新。旧分支已发生的用量只保留数字账本，与新请求按原生请求 ID 去重，累计消耗不因历史回退减少。子代理列表排除明确属于被回退调用的记录，原始子代理文件保留。

## 兼容与失败边界

本次验证的原版 Claude Code 为 `2.1.323`。适配器核对原生回退菜单、目标与“只恢复对话”选项；界面不匹配时不猜按键。取消只针对本次已确认打开的回退菜单，不向正在执行的任务发送停止按键。

原生回退会回填旧输入。清理多行草稿后必须确认输入为空，才提交修改后的内容。终端解析器识别 `ESC(B` 等字符集切换，避免把控制序列的 `B` 误显示为残留输入。派发失败保留真实原因，不把普通异常统一改成“授权失效”。
