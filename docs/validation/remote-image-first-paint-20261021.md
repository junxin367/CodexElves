# 图片预览首次绘制偏移修复

日期：2026-10-21（北京时间）。

## RCA 结论

- 状态：已确认共享网页的首帧缺陷，修复和 Chrome 手机尺寸验证通过；没有直接操作 Android 真机。
- 现象：Android 刚打开图片预览时，图片按原始大小出现在视口右下方，随后才变为正常预览。
- 直接原因：图片尚未完成加载时已经可见，但居中和适配视口的 transform 要等 `onload` 才设置。
- 根因：Android 预览图片使用 `top:50%;left:50%` 和不受限的原始尺寸；CSS 默认允许显示，JavaScript 却在加载完成后才计算 `translate(-50%,-50%)` 和适配比例。渐进解码已能绘制、但 `load` 尚未触发的阶段缺少可见性约束。
- 系统性根因：预览的 CSS 可见状态与 JavaScript 布局就绪状态没有关联，已有缩放和适配验证没有覆盖“图像可以绘制但尚未触发 load”的首帧。
- 关键因果链：打开 Android 预览 → 渐进图片产生可绘制内容 → 原始尺寸图片的左上角定位在视口中心 → 用户看到右下方局部 → `onload` 初始化缩放后才恢复居中。

## 已排除解释

- 图片本身空白或损坏：同一测试图片完整加载后正常显示；慢速响应可以稳定触发原始偏移。
- 残留上次拖动位置：首次打开新弹窗即可复现，原代码 x/y 初值均为 0。
- 仅为缩放下限设置错误：适配比例在 load 之后正确；问题发生时 transform 尚未初始化。
- 仅为 Android 原生容器坐标问题：相同共享网页函数和样式在 Chrome 的 Android 预览分支即可复现。

## 异常状态溯源

- 适用约束：Android 图片预览首次向用户显示图像时，必须已完成当前视口的居中和完整适配；缩放和拖动从这个初始状态开始。
- 约束依据及状态：用户本次修复要求及现有完整适配行为；已确认。
- 本次运行前提命中判定：命中。验收使用 Android 预览分支与相同生产函数、样式。
- 值判断：浏览器在 `complete:false` 时绘制渐进图片属于合法行为；消费者让尚未适配的原始尺寸图片可见，违反初始展示约束。
- 实际来源与传播：图片解码得到原始尺寸 → CSS 默认可见且以视口中心为左上角定位 → 首帧显示偏移 → load 才设置正确 transform。
- 最后满足约束的状态 → 首次约束违反点：弹窗尚未显示图片 → 已能绘制的图片在缩放初始化前显示。
- 调查边界：已完成真实 Chromium 渲染时序验证，没有捕获用户原 Android 设备的内部渲染事件。
