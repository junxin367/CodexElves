# Claude 消息渲染排查

日期：2026-11-12。目标网页资源：`2026111206`。

## 结论与依据

在原生会话 `38515c78-cbe6-4961-b5b0-6ee76e81876c` 中确认 6 条
`[Request interrupted by user]`。这些记录来自 Claude CLI 2.1.322 的原始 JSONL，
形态为 `type: user`、单个文本控制块，并带有 `interruptedMessageId` 指向被打断的回复。
它们代表原生执行中断，不能据此断言用户点击了网页中的某个按钮。

旧读取连接端没有传递中断关联字段，轮次投影随后把控制记录当成新的用户提问。
该会话的旧投影因此为 31 轮，其中 6 轮的用户气泡实际是中断标记。
此类错误还会改变后续工具结果的归属。问题属于消息分类和轮次投影。

还发现一条原生 `<synthetic>`、`isApiErrorMessage: false` 的
`No response requested.` 占位回复；它也不应作为模型的正式回答展示。

## 修正

- Python 读取保留 `parentUuid` 与 `interruptedMessageId`。控制记录不再作为待发送消息的确认或流式预览锚点。
- Rust 根据关联回复 ID 确认中断所属轮次，结束该轮并保留原问题、思考、助手正文和工具记录；中断不再创建用户轮次。
- 页面在原轮次下显示“请求已中断”，悬停可查看原生标记。
- 仅过滤明确非 API 错误的原生合成占位回复。真实模型同名正文和错误信息继续显示。
- 用户引用、缺少关联元数据的同名文字，以及包含其他正文／图片的消息继续作为真实消息展示，不按英文前缀过滤。
- HTTP 分页与事件流均核对完整有效轮次 ID，退役旧缓存中的控制气泡并重算数字游标；保留待发送输入和比读取请求更新的原生消息。
- 历史修复沿用已读状态判断，真实新内容继续触发未读。
