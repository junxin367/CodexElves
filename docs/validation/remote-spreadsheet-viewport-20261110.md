# CSV 兼容与表格可视区域回归修复

日期：2026-11-10。

## RCA 结论

- 状态：已确认。两处缺陷均用运行版本、真实解析输出及浏览器前后对照复现；Android 真机交付效果另列待复验。
- 现象：r21 更新后 CSV 显示“文件响应格式无效”；XLSX 表格在底部留下大片空白，没有用完可视区域。
- 直接原因：网页拒绝有数据但 `columnWidths: []` 的响应；独立表格的滚动区受 `min(65dvh,720px)` 高度上限约束。
- 根因：新增列宽校验把“没有原始列宽”与“非空但列宽数量错误”混为一谈；独立工作簿沿用了文档内嵌表格的高度上限，没有使用文件页分配的剩余空间。
- 系统性根因：前端无布局用例省略了列宽字段，未覆盖后台实际序列化的空数组；此前布局验收检查了溢出、间距和对齐，却没有检查滚动区下缘与可视区域下缘的距离。这两个缺口分别让协议不兼容和空间浪费通过了检查。
- 关键因果链：CSV/TSV/ODS → `SheetBuilder::finish` 生成空布局数组 → `validRichFilePreview` 要求数组长度等于非零列数 → `read` 抛出响应格式无效；文件页分配可用高度 → 表格额外套用 65% 上限 → 多余空间闲置。

## 已排除解释

- CSV 编码或解析失败：实际文件能生成 39×10 的结构化内容，且与独立 CSV 读取逐格摘要一致。
- 用户手机缓存旧资源是必要触发条件：无需缓存，仅使用 r21 真实资源和该响应即可在浏览器复现。
- 原文件缺少行导致底部空白：表格仍有大量可滚动行；仅替换布局规则便利用了剩余空间。
- 合并或列宽被本次修复丢弃：XLSX 首表仍为 9 列、标题合并跨度 9，深蓝背景、白色文字和原始列宽保留。

## 异常状态溯源

- 适用约束：用户要求常见表格可在线读取时，无原始列宽的 CSV/TSV/ODS 必须仍能预览；非空布局仍须逐列完整且有界。独立表格应占用标题、信息行、标签和提示之外的可视区域，保留既定 2px 间距。
- 约束依据及状态：本轮用户反馈及前序表格在线预览、2px 间距、30px 信息行要求；已确认。
- 本次运行前提命中判定：命中。实际 CSV 没有原始列宽；XLSX 内容高于可视区域。
- 值判断：空列宽数组符合无布局的语义；消费者处理缺陷。独立表格套用固定视口比例不符合本轮要求。
- 实际来源与传播：分隔文本解析 → `SheetBuilder::finish` → JSON 空列宽数组 → 前端严格等长判断；共享表格 CSS → 独立工作簿滚动区。
- 最后满足约束的状态 → 首次违反点：CSV 源内容和解析响应满足读取需求，前端首次错误拒绝；表格内容本身充足，滚动区高度上限首次闲置可用空间。
- 调查边界与未知上游：不推断 Android WebView 的精确绘制结果；本次原因由本地同资源对照和真实响应闭环，不依赖该未知项。

## 修复与防复发
