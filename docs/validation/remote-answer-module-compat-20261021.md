# 远程问答提交的原生模块定位修复

日期：2026-10-21（北京时间）。

## RCA 结论

- 状态：已确认模块定位缺陷，修复及隔离提交验证通过；用户业务问题没有代提交。
- 现象：Android 点击“提交回答”后提示“未发现原生创建模块”，问题卡片保留。
- 直接原因：`answerAsyncQuestion` 在取得原生提交函数前，调用 `nativeCreationModule` 返回 503。
- 根因：旧定位器把 `modulepreload` 和 Resource Timing 当作原生模块完整清单。当前页面中 `app-initial` 已作为静态依赖加载，却没有出现在这两份记录里；模块实际存在，其问答状态与提交接口也可用。
- 系统性根因：创建、问答等入口使用的旧定位器与关联会话使用的定位器并存，前者没有复用后者沿可信原生入口解析静态依赖的能力；既有问答验证未覆盖“模块已加载但未被页面资源记录直接列出”的场景。
- 关键因果链：Android 问答表单 → `/api/action/answer` → `answerAsyncQuestion` → 旧模块定位器只查页面资源记录 → 找不到 `app-initial` → 在设置提交标记和发送答案之前失败。

## 已排除解释

- 问题已经过期或回答：当前原生问题仍存在，未产生原生提交标记。
- 缺少问答原生功能：正确找到模块后，状态接口验证通过且提交函数唯一。
- 隧道错误导致本次文案：在桌面页面内部直接调用旧定位器即可复现相同文案，没有经过公网请求。
- 需要创建新会话才能回答：失败的是公用模块定位步骤；既有问答仍通过原生提交函数发送到原会话。

## 异常状态溯源

- 适用约束：当原生问答仍有效且当前安装版提供对应状态及提交接口时，远程问答不能仅因静态依赖未在 Resource Timing 中单独列出而判定模块不存在。
- 约束依据及状态：远程问答沿原生机制提交的现有功能合同，以及用户本次修复要求；已确认。
- 本次运行前提命中判定：命中。当前问题有效，实际模块导入及状态接口识别均成功。
- 值判断：页面资源记录中缺少静态依赖不构成非法状态；消费方把这份不完整记录当作唯一发现渠道造成错误拒绝。
- 实际来源与传播：模块作为可信原生入口的静态依赖存在 → 旧定位器仅查询 DOM 与 Resource Timing → 返回未发现错误 → Android 显示错误提示。
- 最后满足约束的状态 → 首次约束违反点：原生模块和当前问题均有效 → 旧定位器因缺少直接资源记录而拒绝。
- 调查边界：已核对当前安装版和当前问题；没有把未来 Codex 内部模块布局视为已保证兼容。

## 修复与防复发

- `nativeCreationModule` 复用 `nativeResource("initial")`，保留可信 `app://-/assets/` 地址、版本唯一性和静态依赖唯一性校验。
- 原生桥版本从 59 递增到 60，确保已打开的 Codex 页面加载修复。
- 不改变答案内容、目标会话、立即发送模式、重复提交保护、桌面问答状态同步或未知结果处理。
- 13 项临时验证通过：静态依赖发现、直接预加载、重复资源去重、多个版本拒绝、外部地址拒绝、歧义依赖拒绝、选项答案、自由输入、重复提交、过期问题、无效答案、定位失败不留提交标记、未知结果不重发。
- 使用当前原生提交函数做取消探针：`isSubmissionCurrent` 返回 false，原生函数在读取会话状态前拒绝；检查结果为守卫调用 1 次、状态读取 0 次，没有发送消息。
- 修复前同一发现用例失败，修复后通过；当前真实页面仍没有直接 `app-initial` 资源记录，但修复后可找到模块。
- JavaScript 语法和差异空白检查通过；临时测试按项目规则在完成后清理。
