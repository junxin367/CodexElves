## 原排序依据与调整

原实现优先按 `recencyAt` 排序和划分「今天／昨天／历史」，且日期列表可能继承桌面的手动顺序；执行完成时间没有直接参与排序。只读核对真实原生数据时，观察到服务端目录的 `updatedAt` 已更新，但 `recencyAt` 及桌面最近摘要仍停留在更早时间。目录读取后再合并旧摘要，也会覆盖已经取得的较新时间。

本轮调整如下：

- 日期分组统一使用原生 `updatedAt`，缺失时依次回退到 `recencyAt`、创建时间；日期按浏览器本地零点划分。
- 三个日期分组内按最近更新时间倒序，不继承桌面手动顺序；同一更新时间按创建时间、会话 ID 稳定排序。
- 原生摘要合并保留目录、桌面摘要、当前目录缓存中的最大更新时间；状态回调使用同一规则，并将更新时间纳入侧栏刷新签名。
- 项目与置顶的手动顺序、优先级分组及主列表过滤规则保留。最近更新时间来自原生数据，不推算或补造执行完成时间。
