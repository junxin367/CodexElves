# Excel 合并、格式、间距及滚动修复

日期：2026-11-10。

## RCA 结论

- 状态：合并及列宽缺陷已确认并修复；首列滚动已完成浏览器对照及修复验证，Android 截图中的原始现象仍待真机复验。
- 现象：Excel 标题没有跨列合并，A 列异常宽；用户同时反馈上下滚动后首列显示异常。
- 直接原因：旧响应只包含单元格文字，客户端按普通单元格布局长标题，未使用原文件的合并范围和列宽；表头与行号使用 sticky，而纵向滚动发生在外层页面。
- 根因：办公预览的协议与渲染器只表达文字网格，遗漏合并、列宽、空行和样式，浏览器的自动列宽因此把合并标题当成 A 列的宽度约束。滚动结构没有为表头和行号提供共同的双向滚动容器及明确的交叉层级。
- 系统性根因：初版检查覆盖了值、行列数量及溢出，没有提供含合并和样式的格式夹具；稀疏行号及总行数检查不能替代原文件布局和滚动验收。
- 关键因果链：原 XLSX 的合并和列定义存在 → 后台仅投影文字 → 前端缺少 colspan/rowspan 和 colgroup → 合并标题被当作普通 A 列文字 → A 列撑宽、标题不跨列。

## 已排除解释

- 后台把不同单元格的值串列：独立 XML 与预览的逐格坐标和值摘要一致。
- 原文件没有合并或列宽：原始 XML 明确包含这些定义。
- 手机使用旧的二进制占位页：截图已经显示工作表选择和表格，当前运行版本为办公预览 r20。

## 异常状态溯源

- 适用约束：当用户打开带合并区域的 Excel 时，在线表格必须按原始行列坐标和合并范围显示；正常单元格的宽度不能由跨多列标题单独决定。
- 约束依据及状态：用户明确要求恢复合并效果及正确表格；已确认。
- 本次运行前提命中判定：命中，实际文件包含 10 个合并区域及逐列宽度。
- 值判断：原始值与合并定义合法；消费者遗漏布局语义，属于协议和渲染缺陷。
- 实际来源与传播：XLSX worksheet mergeCells/cols → 旧 Sheet 投影丢弃 → 普通 td → 自动列宽。
- 最后满足约束的状态 → 首次约束违反点：源文件保留合并和列宽 → 旧投影首次丢弃。
- 调查边界：第三方 Excel 内部布局和 Android WebView 的精确绘制行为；本次未把桌面浏览器验证当作 Android 真机证明。

## 修复与防复发

- 后台返回有界合并区域、列宽、样式表及逐格样式索引，保留原始行号和小表中间空行。
- 列宽按常用 7px 字符宽加 5px 边距近似换算，并限制在 48–480px；小文件不能通过巨大稀疏范围申请整张大表。
- 客户端固定列网格，用 colspan/rowspan 渲染合并并跳过覆盖格；跨页纵向合并延续原左上角内容和样式，不修改原数据。
- 颜色仅接受六位十六进制，字号限制 6–72pt；支持背景、文字颜色、字号、粗体、斜体、下划线、删除线、水平/垂直对齐及换行。样式按绝对坐标读取，字体大小随文件阅读字号同比缩放。
- 表头和行号使用同一双向滚动容器；交叉角、表头、行号和正文各有明确层级。
- 按用户追加要求，表格/文档/PDF 左右预览内边距为 2px，工作表选择区至表格为 2px；工作表选择条隐藏滚动条但仍可横向滑动。
- 行数及翻页控件移入文件大小信息行；按用户最终要求，文件/变更的信息行固定为 30px，即 25px 控件、上下各 2px、1px 边框。表格、文档、PDF、源码及变更使用同一规则，长内容横向滚动而不撑高。文档小表不再单独占用行数信息行。
- 前端检查覆盖合并范围歧义和越界拒绝、跨页合并、样式索引及颜色校验、行数信息挂载位置。
- 后台夹具覆盖合并范围、空行、列宽、重叠拒绝和样式身份；此前稀疏读取及办公格式回归继续保留。
- 6 项办公文件回归及 223 项前端状态检查通过，前端类型/资源、Rust 格式和差异检查通过。
- 浏览器实测表格、文档、PDF、源码及通用变更信息行高度约 29.99px（缩放取整后的 30px），左右留白和选择区至表格均为 2px。三种宽度下的双向滚动仍对齐，实际标题背景 `#17365D`、白色文字和 16pt 字号正确应用。
