# 新建侧边会话响应速度验收

日期：2026-10-21。

## 问题与调整

原流程在菜单中等待原生 fork、上下文继承及侧边登记完成，成功后才切换页面并分别读取会话信息和历史。网络延迟会继续增加点击后无页面反馈的时间。

调整后点击即进入创建中页面，保留右上角返回。服务端完成持久创建和登记后，在同一成功回执中返回新会话首屏快照；客户端直接显示会话设置和空聊天区，省去创建后的两次读取。继承上下文和侧边列表隔离规则保持原有约定。

## 受控浏览器对照

使用相同产品页面和隔离 API，固定创建请求为 3 秒延迟，在 Chrome 390×844 视口测试。以下数字为该对照场景的测量值，不代表公网或 Android 真机速度。

| 指标 | 调整前 | 调整后 |
| --- | --- | --- |
| 点击到页面反馈 | 3038.3 ms | 28.2 ms |
| 点击到新会话可用 | 3589.7 ms | 3070.9 ms |
| 创建后读取新会话信息和历史 | 各 1 次 | 各 0 次 |

第二次成功创建测得页面反馈 10.8 ms、会话可用 3053.1 ms。旧服务没有首屏快照时仍能打开，测得反馈 2.4 ms、会话可用 3594 ms。

## 原生链路测量

在本机 Codex 26.1013.4894.0 中创建并关闭验收侧边会话，确认成功回执包含 `viewKind: side`、`sideHistoryVersion: 1`、父会话身份和模型设置；继承的 25 个 turn 不显示在新聊天区。

调整前原生创建耗时 1534 ms，调整后为 1754 ms。`thread/fork` 分别为 857.7 ms、792.3 ms，原生管理器 fork 流程分别为 1376.9 ms、1406.1 ms。此次改动没有证明原生 fork 本身变快；已验证的收益是即时页面反馈及省去后续网络读取。
