# Android 交互触觉反馈验证

2026-10-18，功能实现与本机验证完成。正式 APK 未重新打包，未安装或进行真机振感验收。

## 实现范围

- 仅 Android App 对真实的按钮点击、选择控件和队列排序发送触觉反馈；普通网页不安装触觉点击监听，不使用 `navigator.vibrate`。
- 队列开始拖动、实际换位和提交新顺序分别反馈。仅长按而不换位不产生结束反馈；取消拖动恢复顺序，不提交、不产生结束反馈。有效键盘换位反馈一次，越界不反馈。
- 原生登录的连接、密码显隐和帮助按钮也接入点击反馈，输入法提交未增加反馈。
- 文字输入、普通正文点击、字体滑块、禁用或 inert 控件、合成事件及自动刷新不触发。原有队列提交逻辑、240ms 长按与移动阈值保持。
- 原生使用 `View.performHapticFeedback`，flags 为 0，遵循系统触觉设置，无新增震动权限。只有前台、可见、附着、启用且窗口有焦点的 View 可以反馈。
- 网页与原生均设 50ms 最短间隔，换位反馈额外限制为 80ms；丢弃过密请求，不延迟补播。桥仅接受四种单字段类型，沿用当前 HTTPS Origin、主 frame、WebView、页面 URL 和连接代次检查。

完整页面验证确认：模型打开和选中各反馈一次；通知开关的文字点击仅反馈一次；有效键盘换位反馈一次；触摸拖动的开始、换位、放下各反馈一次。同一位置移动、取消结束、禁用按钮、输入、正文和队列越界不产生多余反馈。原有菜单关闭、二级页返回、Space 激活、排序及草稿均正常。

普通手机网页执行模型选中和队列换位时，触觉请求增量为 0。共执行 3 次本机模拟排序请求（Android 2 次、普通网页 1 次），另有 1 次模拟通知分类开关保存；没有真实会话写入或系统设置修改。

`touch-hold-without-reorder` 样本的 CDP 输入间隔已超过 240ms，实际触发过开始反馈，不能作为“长按前滑动取消”的浏览器证据。报告已保留该限制；短时取消由 VM/DOM 验证覆盖。

lint 为 0 错误、4 警告：原有 v26 资源目录、登录组合布局、未使用品牌字符串三项提示，以及本次构造器依赖注入产生的 `ViewConstructor` 布局编辑器提示。`LoginView` 由 Activity 显式创建，当前应用编译和实例化入口有效；未为消除提示改变登录布局。
