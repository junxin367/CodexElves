## 结论

建议采用自研轻量网页入口，接入桌面正在使用的 Codex 实例，而不是将整套 HAPI 作为核心依赖。

已使用真实模型回复、真实命令审批和真实等待进程完成本机端到端验证；不是只检查接口存在，也不是用模拟回复代替 Codex。验证网页与桌面共用原生会话 ID `01a13117-27d2-7562-8ad7-edf3256fc07b`，没有启动另一套 app-server，也没有导入或复制会话。

本轮完成的是技术可行性验证，不是正式功能交付：使用 Chrome 的手机尺寸视口，尚未使用实体手机、移动网络或公网入口。正式开发仍需实现部署、TLS、设备授权、兼容性和异常恢复。

## 验证过程中发现的接入约束

### 停止轮次不等于终止命令

初次只调用原生 `interruptConversation`：AI 轮次被标记为 `interrupted`，但 90 秒等待命令仍运行到结束，最终退出码为 `0`。因此不能只看轮次状态就认定整个任务已停止。

临时验证入口改为组合调用 `stopThread(id, "user")` 和该会话的 `cleanBackgroundTerminals(id)`，再读取终端列表确认结果。复测使用 300 秒等待命令，验证了实际进程退出且终端列表清空。该修改仅发生在临时验证脚本中，没有修改产品源代码。

### 历史读取必须适配分页存储

桌面 renderer 缓存中的 `turns` 不等于完整历史；续接过程中也可能暂时只拿到概要。验证入口最终通过 `thread/turns/list` 的 `itemsView: "full"` 读取历史，而不是把缓存中的空数组当作无历史。

### 裸创建接口不能代替完整桌面创建流程

直接调用 `thread/start` 创建空会话后，立即恢复曾返回 `no rollout found`。验证脚本通过一次受控初始化消息落盘后完成续接；正式实现应复用桌面的创建、续接和消息队列流程，不能靠手工拼接 renderer 缓存绕过原生生命周期。

### 网页接口不能直接暴露 CDP

本次临时服务检查请求来源并使用临时 HttpOnly、SameSite Cookie，只允许操作测试会话。它没有开放局域网或公网，不能当作生产安全方案直接发布。

## 建议的正式开发路径

```text
手机网页
  → 具备设备授权与 TLS 的远程入口
  → CodexElves 本地桥接
  → 桌面原生会话管理器及消息队列
  → 桌面已有 app-server
```

- 保持桌面原生会话 ID、模型配置、工作目录及权限归属，不维护第二份执行会话。
- 管理器负责显式启停、设备配对与撤销授权，不直接开放调试端口。
- 对消息提交使用稳定请求 ID 和回执，单独验证重复提交及回执丢失后的恢复。
- 对桌面升级建立兼容性检查；本次验证结果只覆盖上述实际安装版本。
- HAPI 可参考移动交互与远程连接设计，但本轮没有复制或集成其代码。

## 未覆盖的边界

- 实体手机的浏览器、触摸交互、输入法及后台挂起。
- 手机移动网络、跨公网可达性、TLS 证书及长期在线部署。
- 桌面应用重启、操作系统重启和长期断网。
- 同时从两个设备提交消息、丢失提交回执后重试的去重保证。
- 不同桌面版本、不同模型及不同权限配置的完整兼容性矩阵。

上述内容属于正式功能开发与验收范围，不能由本次本机技术验证推定通过。
