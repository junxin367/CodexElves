# 批量文件操作与图片查看测试提示词

使用前先安装本轮生成的 CodexElves 安装包，重新启动本地代理，再在 Claude 新任务中粘贴下面的内容。

```text
执行一轮真实工具测试，只验证批量文件编辑工具（apply_patch_batch）和图片查看工具（view_image）。使用本会话实际提供的工具名称和参数定义，不猜测工具前缀。

核心规则：任一工具首次失败后立即停用，禁止重试。只测试，不修复代理或业务代码。

一、范围与停止条件

1. 写入、修改和清理仅限本轮新建的 temp/tool-smoke-<唯一标识>/ 目录。不覆盖用户已有文件，不修改配置，不安装依赖，不提交代码，不重启服务，不调用子代理或外部业务工具。
2. 允许必要的本地辅助工具准备目录、生成图片、读取文件和核验结果。不能用辅助工具代替待测工具完成测试并宣称通过。
3. 工具首次出现执行错误、参数错误、权限拒绝或超时后，立即记录并停用该工具。不得原样重试、修改参数重试、换别名重试，或通过 shell/脚本变相重复失败操作。已停用工具也不得再用于清理。
4. 继续不依赖失败工具的独立用例；依赖它的用例标记为“受阻”。准备图片失败不等于 view_image 失败。
5. 本轮最多 24 次工具调用，包含准备、读取技能、测试、核验和清理。达到上限即停止并汇报未覆盖项。
6. 只做下面列出的合法用例，不额外构造同一批次重复路径、损坏图片等负例。

二、先核实批量工具说明

从你实际收到的批量工具定义中，引用关于同一批次不能重复操作同一文件的原文。
不得用本提示词、项目源码、历史记忆或其他任务的说明冒充工具定义。
若没有该规则，报告“未收到新规则”，停止批量工具测试，继续独立的图片测试。
若没有提供批量工具，报告“未提供对应工具”，不要改用其他文件编辑工具冒充此次验收。
阅读工具说明仅算说明核实，不算工具执行通过。

三、批量文件编辑：三个用例按顺序执行

所有路径都位于本轮临时目录。每次调用结束后读取实际文件，逐行核验；只看到 Success 不算通过。

F1：使用一次批量调用创建两个不同文件。
- a.txt：三行，分别为 A1、A2、A3。
- b.txt：一行，为 B1。
- 核验两个文件均存在，内容完全符合预期。

F2：等 F1 成功并核验后，使用下一次批量调用更新两个文件。
- a.txt：将第一行改为 A1-updated、第三行改为 A3-updated，第二行仍为 A2。
- b.txt：内容改为 B1-updated。
- 按实际工具说明组织操作；核验修改结果。

F3：等 F2 成功并核验后，使用下一次批量调用操作两个文件。
- 整体替换 a.txt，最终只保留一行 REPLACED。
- 删除 b.txt。
- 核验 a.txt 的旧内容已全部消失，b.txt 已不存在。

四、图片查看：两个用例

使用已安装且可用的正规图片库，在本轮临时目录生成以下 PNG：
- I1：1×1 像素纯红色图片，RGB 为 (255, 0, 0)。
- I2：32×32 像素纯蓝色图片，RGB 为 (0, 0, 255)。

禁止手工拼接 PNG 字节、CRC 或未经验证的 Base64。
生成后必须用图片库重新打开并完整解码，核验尺寸和像素颜色；仅检查扩展名或文件头不算验证。
如果没有可用图片库，标记图片测试“受阻”，不要安装依赖或猜测图片编码。

对验证成功的 I1、I2，分别调用一次真实 view_image。
确认工具实际返回图片，并简述看到的颜色。图片库解码成功不能代替 view_image 测试通过。
若 I1 的 view_image 调用失败，停用 view_image，I2 标记为受阻，不更换图片重试。

五、清理与报告

只清理本轮创建的文件和目录。清理首次失败后停止，不换工具或语言绕过拒绝；保留完整路径用于报告。

最后用简体中文输出：

1. 工具说明：已收到新规则 / 未收到新规则 / 未提供对应工具；附实际工具定义中的原文。
2. 用例表：用例 F1/F2/F3/I1/I2 | 实际工具名称 | 通过/失败/受阻 | 实际内容或图片核验结果 | 原始错误。
3. 如有失败，保留可定位的调用 ID 或时间；没有则明确说明，不能编造。区分测试输入错误、工具执行失败、环境或权限问题；证据不足时写“原因未确认”。
4. 临时文件清理情况；未清理时列出完整路径。

只报告本轮实际证据，不把未执行的用例算作通过，不宣称所有工具完全正常，也不修改代码来让测试通过。
```
