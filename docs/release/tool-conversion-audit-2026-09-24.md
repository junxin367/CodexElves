# 工具协议转换审查与验证

日期：2026-09-24。目标：修复 Claude 工具调用转换问题，检查相邻工具链路，并构建当前工作区的 Windows 安装包。

## 范围与结论

检查覆盖工具声明、参数 Schema、工具选择、流式事件、非流式响应、调用标识、工具执行结果、历史回放和动态工具发现。审查对象为 `crates/codex-elves-core/src/protocol_proxy.rs`，回归补充在原有 `tests/protocol_proxy.rs` 内；保留工作区原有未提交改动。

真实会话快照包含 **48 项工具声明**：45 个函数工具（含命名空间）、1 个补丁工具、工具搜索、网页搜索。函数覆盖 `exec_command`、`write_stdin`、资源读取、图片查看、协作、Codex App、浏览器 REPL 和目标管理等声明。外部 MCP 动态发现另用受控工具验证。

确认存在多处与“工具选对但转换后不可用”同类的缺陷，已修复下表项目。验证通过的范围是本地转换契约和受控执行链路；不等于所有外部 MCP 服务的业务接口均已实测。

## 已修复问题

| 问题 | 原行为与影响 | 修复及证据 |
| --- | --- | --- |
| 整文件替换产生重复路径 | `replace_file` 生成同一路径 Delete + Add，执行器拒绝 | 改为单次 Add 覆盖；真实 Codex 执行器验证文件内容 |
| 历史动作身份丢失 | 替换调用回放成 batch，模型误判自己的工具选择 | 在响应 item ID 保留代理动作，call ID 不变；兼容旧删除/新增对 |
| 工具搜索参数被重建 | 真实声明中的 `limit` 和限制字段丢失 | 保留客户端提供的完整 parameters |
| 命名空间 strict 丢失 | 子工具的 true/false 标记没有传递 | 两种目标协议均保留显式 strict |
| 包装式函数声明被去重 | 多个 `function.name` 被当作同一个空名称；强制选择同时丢失 | 去重、上下文和工具选择统一读取嵌套名称 |
| 文本调用参数类型错误 | 数字、布尔值、数组、对象和 null 变成字符串 | 按声明恢复类型；覆盖本地 `$ref`、属性联合类型和组合 Schema；字符串中的 JSON 代码保持文本 |
| 文本调用 ID 跨轮重复 | 每轮重新使用 `call_textual_invoke_0` | 使用响应 ID 的摘要和轮内序号；不同响应不再复用 ID |
| 流式工具头过早发布 | id/name/arguments 分开发送时先发布 unknown_tool；空参数不是有效 JSON | 缓存完整工具头；无参函数归一为 `{}`；校验 added/done 的名称和 ID 一致 |
| 补丁 EOF 标记被当作正文 | 历史回放把 `*** End of File` 变成普通上下文行 | 结构化 hunk 保留 `end_of_file`，重新生成合法 EOF 标记 |
| 已移除工具仍被强制选择 | Chat 无搜索后端时删除 web_search，却仍发送强制选择 | 只转发实际仍在工具声明中的目标 |
| 并行调用设置丢失 | Anthropic 转换忽略 `parallel_tool_calls` | 映射到 `disable_parallel_tool_use`；禁用全部工具时不添加无效字段 |
| 工具说明与参数形式冲突 | JSON 参数工具仍被描述成“不使用 JSON”的 FREEFORM 工具 | 明确外层 JSON 参数与内层原始文本/生成补丁的区别 |
| 批量操作缺少使用约束说明 | 未告知同一批次不能重复操作同一文件 | 补充合并修改、提供最终内容或分次调用的说明；验证 Anthropic 和 Chat 均收到规则，不改变转换行为 |

最初新增的 7 项缺陷用例全部在修改前失败；工具选择和并行控制的后续 2 项用例也先复现失败。已有测试还存在两条错误预期（重复路径补丁、字符串数字）和一条空测试函数，均已修正或补实。

### 真实 Codex 执行链路

使用桌面端相同的 `codex-cli 0.155.0-alpha.16`，在临时工作目录、隔离配置和本地模拟上游中执行。MCP 服务为本地只回显参数的测试服务器，没有调用真实业务服务。

三种模式分别完成 **10 轮请求**，合计 30 轮：

- Anthropic 原生 tool_use。
- Anthropic 文本 invoke，包含数字、布尔值、数组和 JSON 字符串参数。
- Chat Completions 原生工具调用。

每种模式实际执行工具搜索、模拟 MCP、`view_image`、`exec_command` 和五类补丁操作。逐步检查新建内容、移动后的路径及内容、替换后的完整中文/空行、删除状态和批量写入结果；同时核对真实回传请求中的替换动作身份以及图片内容块。

首次测试服务器因 Windows 标准输入编码导致 MCP 断连；修正一次性测试服务器的 UTF-8 输入输出后重新验证通过。该失败属于测试环境，没有作为产品修复成果计数。

### 后续独立工具复核

两个子代理分别实际调用原生文件编辑工具和图片查看工具，完成七个对照用例：

- 一次创建两个不同文件、分次新建再更新、整体替换已有文件，均成功且内容核验通过。
- 同一次调用内对同一文件先新建再更新，执行器拒绝，失败后文件不存在。该限制和之前替换错误触发的是同一执行器限制，但本次没有发现转换把正确输入改坏。
- 原手工构造的 1×1 PNG 因校验值错误被拒绝；仅修正一个字节后的同尺寸图片，以及正常编码的 32×32 PNG，均由 `view_image` 成功返回图片。

批量工具因此补充既有执行限制的说明；图片工具没有修改。复测提示词见同目录 `batch-image-tool-test-prompt.md`。

## 明确边界

1. 45 个函数覆盖的是转换与回放；没有逐一执行真实的任务创建、自动化、工单、Figma 或其他会改变外部状态的操作。
2. 网页搜索的原生/后备路由有模拟覆盖；未用真实 Anthropic 供应商执行付费或联网搜索验收。
3. 旧 `local_shell`、`computer_use`、`computer_use_preview` 别名不在当前 48 项声明中。现有相关测试只证明代理序列化，不作为当前 Codex 执行器原生工具支持的证明。
4. Anthropic 顶层 oneOf/anyOf 仍使用既有兼容近似，并不保证完整 JSON Schema 语义等价；本轮保留该设计，没有未经供应商验证修改它。
5. 核心库中一项真实计时恢复测试按原配置忽略，需要约六分钟，属于传输恢复计时，不属于工具转换。本报告不把它计入通过数。
6. 安装包生成与安装运行是不同状态；本轮不会自动安装或重启用户正在使用的代理。
