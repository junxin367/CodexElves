# 2026-10-05 流式响应性能优化

本次在已有修复基础上，优化两个高频内部路径，不改变协议转发或缓存租约判定规则。

## 改动

### 缓存观察器的 SSE 分帧

- 旧实现对每个事件分别搜索 LF 和 CRLF 分隔符，每次搜索可能再次遍历剩余缓冲区；取出事件还会创建 Vec，并两次搬移尾部。合并事件较多时，处理量接近平方增长。
- 新实现一次扫描寻找最早分隔符，借用完整事件切片，每批只搬移一次未完成的尾部。
- 未完成的大事件记录搜索位置，下一个网络分片到达时只重查之前的三个尾字节，覆盖最长的 CRLF CRLF 跨片边界。
- 单行 `data:` 直接借用文本；只有多行数据需要拼接，省去常见路径上的临时 Vec 和 String。
- 丢弃超限缓冲时同步重置游标，保留原有 64 MiB 上限和失败响应处理。

### UTF-8 流式解码

- 没有上一分片遗留字节时，直接验证并追加当前分片，不再先复制到临时 Vec。
- 只有 Unicode 字符跨片时才合并遗留字节，沿用原有不完整字节保留和无效编码替换行为。

## 微基准

环境：Windows，Intel Core i5-13500，rustc 1.95.0；使用 `rustc --edition=2024 -O`。

基准分别提取修改前、修改后的实际函数。SSE 基准运行实际 `observe_bytes`、`consume_sse_blocks` 和分隔符搜索函数，将事件回调替换成黑盒长度计数，**只衡量分帧，不含 JSON 解析、网络、UI 或完整代理请求**。UTF-8 基准运行实际 `append_utf8_safe`，验证输出文本和遗留字节。

每个用例先预热，再运行 7 次取中位数；修改前后交替运行 3 组，表中采用三个中位数的中位数。使用相同的计数分配器记录每次用例的分配及重分配次数，计数包含输出缓冲的初始分配。

| 用例 | 优化前中位数 | 优化后中位数 | 分配次数（前 → 后） |
| --- | ---: | ---: | ---: |
| 同一分片内含 4096 个 SSE 事件 | 128.981 ms | 0.099 ms | 4097 → 1 |
| 单个 256 KiB SSE 事件，每片 128 B | 135.670 ms | 0.103 ms | 14 → 13 |
| 4096 个 SSE 事件逐个分片到达 | 0.332 ms | 0.122 ms | 4097 → 1 |
| 4096 次 4 KiB ASCII 解码 | 0.595 ms | 0.384 ms | 4097 → 1 |
| 4096 次约 4 KiB Unicode 解码 | 6.972 ms | 6.535 ms | 4097 → 1 |
| 混合 Unicode 文本，每片 7 B | 0.813 ms | 0.448 ms | 19312 → 7021 |

以上是局部基准，不能据此推算用户请求延迟或安装版整体提速比例。
