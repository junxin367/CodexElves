# 远程会话工具菜单与二级页面：需求与开发任务

更新日期：2026-10-21。

## 已确定的需求

远程会话页面右上角的“会话工具”按钮向下展开菜单，依次展示“变更”入口、“子代理”和“侧边会话”分类，不显示“工具”标题；分类标题使用较小字号并左对齐。选择后，独立页面从右向左滑入；各页面右上角统一显示“返回”按钮。桌面和手机使用同一页面层级，不使用右侧栏或页签。

返回会话时保留原会话正文、草稿和滚动位置。切换会话不能把上一会话的变更结果显示到新会话。系统返回操作遵循当前页面层级。

子代理和侧边会话返回时，与变更页一样以 220ms 的节奏向右滑出，再恢复主会话。右上角返回、浏览器后退和 Android 返回使用同一处理；退出期间暂停子页交互，快速前进可以取消尚未完成的退出。系统开启“减少动态效果”时直接切换，不等待动画。

### 子代理

- 从当前主会话的 Codex 原生子代理关系读取列表，不把普通 fork 或工具输出中的任意文本当作子代理。
- 保持 Codex 原生列表的顺序，展示仍在执行或等待的子代理名称与执行时间，并单独显示已完成数量。
- 点击条目后使用主会话已有的正文、工具记录、图片及历史分页展示。页面只读，隐藏输入和写操作控件；发送、停止、编辑、队列、目标、审批等操作也在原生操作入口拒绝。
- 子代理页隐藏主会话顶部左、右按钮，右上角仅显示“返回”。只读状态独立于设备权限，返回后主会话仍可正常操作。
- 打开列表时核对状态；执行时间在本地更新，不为每秒计时重新请求列表。原生状态变化时合并刷新列表。

### 侧边会话

- 分类标题共用横向布局。“侧边会话”标题右侧显示无背景的小加号图标，与标题垂直居中，保留至少 12px 间距，图标不收缩；不使用绝对定位或手机端专属位置修正。下方按创建顺序展示当前主会话尚未关闭的侧边会话。
- 用户已确认：新建侧边会话继承主会话截至创建时的完整上下文，之后双方独立继续、互不回写。创建使用 Codex 原生 fork，不以摘要或重新发送历史消息代替。
- 新建侧边会话使用独立默认标题“侧边会话”“侧边会话 2”…，参考 Codex 原生侧边页的命名规则。标题通过原生接口确认保存后才报告创建成功，首屏和菜单使用同一标题；不复制主会话标题。编号按主会话记录，关闭、失败及重开后不复用已有编号，后续标题变更继续沿原生通知更新。
- 点击新建后立即滑入创建中页面，右上角可返回主会话。创建成功回执携带新会话首屏快照，直接恢复会话设置和空聊天区，省去紧接着的会话信息与历史读取；旧服务未提供快照时沿用原读取流程。
- 创建中返回保留主会话草稿和阅读位置；随后收到成功回执只更新侧边列表，不自动切走主会话。重复点击复用原请求，结果未知时停止等待动画并提示查询原回执，不再次创建。
- 对齐 Codex 侧边会话的展示：继承内容只供模型作为上下文参考，新建侧边会话的聊天区为空，只展示创建后在该侧边会话产生的消息；原生 fork 使用侧边会话标记及原生上下文边界，仍持久保存。
- 侧边会话只出现在主会话右上角菜单的“侧边会话”列表，不进入远程页面或桌面的主会话侧边栏；关闭后仍保持隐藏。既有侧边会话沿用原 ID，补记继承历史边界，保留其独立产生的消息；旧聊天展示缓存不再恢复继承的主会话记录。
- 用户已确认：使用持久原生会话及明确的主、侧会话登记，电脑重启后未关闭的侧边会话仍可继续。关闭只移出侧边列表，保留历史，不停止、归档或删除主会话。
- 侧边会话页面复用主会话正文和输入功能，隐藏原顶部左、右按钮，右上角仅显示“返回”。各会话分别保留草稿、正文、展开状态和阅读位置。
- 当前主会话存在尚未关闭、执行完成且未读的侧边会话时，菜单按钮只将左下角方块替换为蓝色实心圆点，其他三个方块保持原样；对应侧边会话条目右侧显示蓝色小点。运行中、等待回复、已读或已关闭的侧边会话不显示完成未读提示。
- 进入侧边会话后使用原生已读接口清除该会话的未读状态，并同步清理菜单缓存；刷新后仍保持已读。如果还有其他未读侧边会话，入口蓝点继续显示。新一轮执行完成后可再次显示蓝点，其他主会话的侧边未读不影响当前入口。
- 长按或右键点击侧边会话条目，弹出仅含“关闭会话”的菜单；滑动取消长按，长按结束不能再触发进入会话。
- 新建和关闭沿用设备写权限及请求回执。创建结果不明时查询原请求，不自动再次 fork。关闭必须验证主、侧会话登记关系，不能利用该接口关闭普通主会话。

### 变更

- “当前项目”指当前会话实际工作目录所在的 Git 仓库，包括当前 worktree，不用同项目其他 checkout 代替。
- 展示未提交文件，区分暂存、未暂存、未跟踪状态，覆盖新增、修改、删除、重命名及冲突。
- 三个分组标题可点击展开或收起，默认展开；支持键盘操作，并按当前会话或项目记住状态。
- 当前项目路径放在顶部栏；搜索框固定在列表上方，仅文件列表滚动。没有手动刷新按钮，再次进入先显示缓存，再后台核对是否变化；详情返回保留原列表状态。
- 文件行突出文件名，下一行显示所属目录或原路径，右侧显示状态；支持按文件名或路径筛选当前变更。
- 点击文件查看该状态对应的差异：暂存区比较 HEAD 与 index，未暂存区比较 index 与工作目录，未跟踪文件显示新增内容。
- 文件详情是独立页面，从右向左滑入；右上角返回回到变更列表，保留筛选和列表滚动位置。变更列表右上角返回回到会话。
- 文本以带行号、增删颜色的 diff 展示；图片提供修改前后预览，新增或删除时明确标注一侧不存在。其他二进制资源显示类型、大小与无法文本比较的说明。
- 文件行采用约 48px 的最小高度，字号增大时自然撑高。搜索、文件行、图标、差异及辅助文字跟随字号设置；diff 使用单列有效行号，文件头和 hunk 不保留空白行号占位。
- 无会话、非 Git 目录、工作目录失效、无变更、读取失败、大文件截断均有明确提示。
- 该功能只读，不包含暂存、还原、提交、推送或任意路径浏览。

### App 缓存

- 菜单中的子代理列表、执行时间、已完成数量和侧边会话列表按授权与主会话独立缓存；切换回来先显示缓存，再按事件或访问时的新鲜度静默核对。内存保留 32 个主会话菜单，并复用现有 IndexedDB 只读缓存；详情见 [缓存约定](remote-cache.md#会话工具菜单)。
- 菜单读取期间不显示加载文案；有缓存先显示缓存，首次没有缓存则在读取完成后补充列表和数量。菜单数据未变化时不重建条目，后台更新不清空数量或弹错误。创建、关闭和已读成功后同步修正缓存，迟到请求及旧授权结果不能回填已失效的数据。
- 列表、文本差异、图片预览及页面状态使用当前授权的只读缓存；键区分已有会话与新建会话所选项目，详情再区分分组和路径。退出或更换授权时由既有缓存清理流程隔离数据。
- 有缓存时先显示，再以 `ifRevision` 核对；未变化只返回小型确认响应，保留原 DOM、图片和位置，不重新下载完整 diff 或图片。每次打开详情单独核对内容版本，不以列表仍显示 `M` 判断内容未变。
- 持久缓存复用 IndexedDB 只读缓存库，整体上限 32 MiB、单条 6 MiB、64 条记录，默认保存 7 天；超出上限或本地存储不可用时降级，不阻塞使用。内存另作有界复用。
- 目录失效、文件不再属于当前变更或授权失效时清除相应旧缓存；普通网络错误可以保留上次内容，但明确显示缓存状态。缓存只用于展示，不能替代服务端授权和路径校验。

### 已取消的范围

用户反馈当前带宽下浏览器体验不佳，已明确取消整个浏览器功能。网页入口、原生桥、Android 浏览器页面与代理、OkHttp 依赖、电脑网络转发模块及相关接口均移除。Android 恢复原先禁止明文流量的策略；原会话 WebView、通知、更新和附件功能保留。

## 接口约定

所有接口沿当前登录入口单路发送，不进入双线路写入竞速。

| 接口 | 输入 | 输出 |
| --- | --- | --- |
| `POST /api/workspace/changes` | `threadId`；新建会话可用 `projectId`；可选 `ifRevision` | `ok`、`root`、`files`、`truncated`、`revision` |
| `POST /api/workspace/change` | 同上，及 `path`、`section` | `ok`、`root`、`path`、`section`、`kind`、`diff`、`before`、`after`、`truncated`、`revision` |
| `POST /api/read/relatedThreads` | `threadId` | `ok`、`threadId`、`subagents`、`completedSubagentCount`、`sideThreads`、`canCreateSideThread` |
| `POST /api/action/createSideThread` | 主会话 `threadId`，稳定的 `Idempotency-Key` | 操作回执；成功结果包含新 `threadId`、`parentThreadId` 及可选首屏快照 `thread` |
| `POST /api/action/closeSideThread` | 侧会话 `threadId`、`parentThreadId`，稳定的 `Idempotency-Key` | 操作回执；成功结果包含 `closed:true` |

变更条目字段为 `path`、可选 `oldPath`、`status`、`section`。`section` 为 `staged`、`unstaged`、`untracked`，同一文件可能同时出现在暂存与未暂存列表。详情 `kind` 为 `text`、`image`、`binary` 或 `unsupported`；图片侧为 `{exists,mime,size,dataUrl}`，不存在的一侧 `exists:false`。工作目录由服务端使用原生会话或项目标识解析，客户端不得直接提供绝对目录。

`revision` 为完整可见响应（含仓库目录）的 SHA-256，`ifRevision` 仅接受 64 位小写十六进制。匹配时返回 HTTP 200 的 `{ok:true,notModified:true,revision,root}`，不附带列表、diff 或图片；未提供条件时仍返回全量响应。两种响应均保留 `Cache-Control: no-store`，私有缓存由 App 显式管理。服务端仍读取并校验当前状态；本次优化减少网络传输与重复渲染，不引入 Git 文件监听或服务端持久缓存。

不再注册浏览器原生桥或 `/api/browser/*` 接口。

## 任务分工与验收

主代理负责需求范围、接口决策、共享文件接线、审查与最终验收。子代理不得改写其他任务拥有的文件；接口调整先交主代理协调。

| 任务 | 负责人 | 独占修改范围 | 验收结果 | 当前状态 |
| --- | --- | --- | --- | --- |
| Git 变更读取 | `workspace_backend` | `remote_access/workspace.rs` | 暂存/未暂存/新增/删除/重命名、图片前后、路径与输出限额 | 完成 |
| 内容版本协商 | `workspace_backend` 与主代理 | `remote_access/workspace.rs`、`remote_access.rs` | 列表及详情的 `ifRevision`、版本校验、未变化时省略正文 | 完成，真实服务已验证 |
| 分组折叠及 App 缓存 | `browser_minimal_ui` 与主代理 | `session-tools.js`、样式、`app.js`、`recovery-store.js` | 折叠及滚动恢复、目标隔离、版本核对、DOM 与图片复用 | 完成，服务及验收 APK 已更新 |
| 缓存独立复核 | `network_browser_review` | 只读审查 | 迟到请求、授权切换、冷启动读取和缓存容量边界 | PASS，已确认问题均闭环 |
| 分类菜单 | `related_threads_menu` | `session-menu.js`、菜单样式 | 分类标题、顺序、执行时间、长按关闭、键盘与遮罩 | 完成 |

| 二级会话导航 | `related_threads_navigation` | `app.js` | 统一返回、主会话恢复、孙级打开来源、独立操作回执 | 完成 |
| 关联会话验收 | 主代理、`related_threads_review`、`related_threads_browser_qa` | API 接线、资源、审查及验收 | 后端回归、桌面与手机尺寸交互、真实读取、资源及 APK | 完成；真实侧边会话写入与 Android 真机待验收 |

| 服务与资源集成 | 主代理 | `remote_access.rs`、`native.js`、PWA/Android 资源清单、本机调试入口 | 接口鉴权、原生 cwd、静态资源清单和现有会话功能 | 完成 |
