# zrok / FRP 主链路切换方案

日期：2026-10-23

状态：已按原型实施，源码与本机隔离验证通过；当前真实远程服务尚未切换。验收范围见 `docs/validation/remote-primary-switch-20261023/README.md`。

2026-10-23 后续调整：用户明确选择支持 HTTP。服务器地址自动提取域名，保留独立填写的服务端口；固定公网地址由服务器与公网映射端口自动生成。删除「当前公网地址」区域。本机同一份单映射配置发生端口冲突时，核对进程归属后自动释放并重试一次；端口未授权不重启。当前规则与 HTTP 媒体验收见 `docs/remote-access.md`、`docs/validation/frp-http-20261023/README.md`；下方早期 HTTPS 强制要求已被本条取代。

2026-10-23 最新界面修订：`zrok / frp` 标签位于「公网入口」标题右侧；FRP 地址改称「固定公网地址」；界面删除证书、私钥和 HTTPS 接入方式控件。第一行按服务器地址、Token、服务端口、公网映射端口排列，两个端口输入框均为 80px 且隐藏上下箭头。主链路操作提示替换按钮左侧的默认说明，仅展示文字，不单独占行、不加背景或边框、不重复弹窗。现有入口验证规则保留。

## 1. 目标与范围

管理器「远程会话网页」允许在 zrok 与 FRP 中选择一个主公网入口，通过面包屑样式切换配置。ngrok 继续作为现有第二通道。

这里的“主链路”具体指：管理器显示和复制的公网地址、用户首次登录的入口、远程服务启动时选用的隧道。业务请求仍按现有延迟和健康状态在“选中的主入口 + ngrok”之间选路。

| 选择 | 主入口 | 第二通道 | 未选中的提供方 |
| --- | --- | --- | --- |
| zrok | zrok 固定地址 | 现有 ngrok | FRP 配置保留，托管进程停止 |
| FRP | 自动生成的 HTTP 地址或既有 HTTPS 地址 | 现有 ngrok | zrok 绑定和固定名称保留，托管进程停止 |

首版只支持一份 FRP 配置和一个 TCP 映射。zrok 与 FRP 不组成第三条同时参与测速的业务线路，也不相互自动切换。

## 2. 面包屑交互

位置：管理器「远程会话网页」中现有「公网入口 · zrok」标题及其配置区域。

```text
公网入口   zrok / frp                 当前生效：zrok · 可访问
          ↑ 两个可点击文本，斜杠分隔，选中项加深

[当前面包屑对应的配置表单]
[固定公网地址（自动生成）] [复制]
[操作提示或默认说明]                [保存并测试]  [应用为主链路]

ngrok Token：[现有输入框] [现有保存并测试按钮]
```

- 面包屑只包含 zrok、frp 两项；ngrok 不进入该选择器。
- 点击某项立即展示该提供方的表单，保留另一份表单草稿，不启动或停止任何隧道。
- 面包屑选中项表示“正在编辑哪份配置”；右侧「当前生效」始终表示正在使用的主入口，两者可以不同。
- 「保存并测试」保存候选配置并检查目标入口；只有「应用为主链路」成功后才改变生效入口。
- 对 zrok 继续保留原注册、下载、绑定、固定名称等流程；当它尚未生效时，准备操作不改变现有主入口。
- ngrok 配置块始终显示在两种表单下方，保持原有输入框、显隐、复制、保存并测试和状态展示。
- 切换中暂时禁止再次应用，显示「正在切换到 FRP…」或「正在切换到 zrok…」。完成后展示结果，失败时保留原入口。
- 沿用面包屑的轻量文本外观；可操作项支持键盘焦点、Enter / Space，选中状态不只通过颜色表达。

## 3. FRP 配置

| 字段 | 约束与用途 |
| --- | --- |
| 服务器地址 | frps 地址；粘贴 HTTP/HTTPS 网址后提取域名，不从后台网址推断服务端口 |
| Token | 仅通过本机凭据接口保存和读取，默认遮挡，不出现在日志、网页发现接口或仓库 |
| 服务端口 | frpc 连接 frps 的端口，输入框宽度 80px，无上下箭头 |
| 公网映射端口 | 商家允许范围内的一个 TCP 端口，输入框宽度 80px，无上下箭头 |
| 固定公网地址 | 自动生成 `http://服务器地址:公网映射端口`，只读并可复制；保留已有 HTTPS 配置 |

本地会话目标由现有监听配置自动取得，通常为 `127.0.0.1:45222`，不让用户再次填写。

默认接入路径为：

```text
手机 HTTP → FRP 公网映射端口 → frpc → 本机已验证的会话入口
```

无需用户拥有服务商域名或提供证书。HTTP 公网传输不加密，用户已明确选择支持该模式；仍保留访问密钥、设备授权、Origin 和已验证入口边界。

界面不提供本机证书导入或 HTTPS 接入方式选择。服务商域名的 HTTPS 能力由其入口维护，用户无需在管理器填写证书和私钥。

HTTP 入口通过回源身份与未登录访问边界验证后，可以应用为主链路。界面显示 HTTP 提示，不再要求额外填写 HTTPS 地址。

FRP 隧道内部仍启用 TLS，这不等同于手机访问使用 HTTPS。本次不包含证书导入、域名购买、自动签发或自动续期。

## 4. 切换生效流程

1. 用户选择面包屑项并完成配置，点击「应用为主链路」。
2. 保持当前主入口运行，启动候选提供方，检查进程、隧道、公网 HTTP/HTTPS、回源身份及未登录访问边界。
3. 候选入口只允许有限的验证请求，不提前发布到业务线路列表；验证不携带真实会话或登录密钥。需要本次随机校验值证明回到了当前服务，不能仅凭页面标题判断成功。
4. 全部验证通过后，在同一受串行保护的切换操作内保存选择、更新主入口和访问策略；重复点击或迟到的测试结果不能覆盖新状态。
5. 切换成功后停止旧提供方的托管进程，保留其配置。新的发现结果仍只有“主入口 + 原 ngrok”。
6. 失败时清理本次候选进程和临时验证许可，保留旧选择、旧公网地址及旧进程，显示具体失败原因。

从 frp 切回 zrok 时，复用原来的显式「启动公网」流程，重新核对绑定和固定名称，不通过后台巡检等待旧错误或退避状态消失。已有同目标的 zrok 进程直接复用；候选启动失败立即返回具体原因，原入口继续运行。启动命令、公网验证及重试间隔维持原有期限，不通过延长等待时间完成切换。

固定名称列表读取遇到 `TLS handshake timeout` 时，间隔 500 毫秒重试一次，两次尝试共用原有 60 秒查询时限。绑定、名称创建和公网分享保持原有单次执行行为。连续失败时保留原主入口，在操作按钮旁显示一条简短原因；不把 Go panic 堆栈或 ANSI 控制字符展示到页面，也不在固定地址下方重复显示同一错误。

不通过重启整个远程服务来实现提供方切换。只调整隧道、入口策略和必要的授权状态，避免额外重启本地监听、原生连接和 ngrok。

服务关闭时只保存配置和下次启动的主入口选择，不展示「运行中」。再次启用或重启管理器后恢复已保存的提供方。已生效的提供方运行中故障时，重试该提供方；不擅自把选择改为另一种。

首版接受公网地址变化带来的重新登录：

- 切换按钮旁明确提示「切换公网地址后，远程设备需用新地址重新登录」。
- 浏览器需打开新的公网地址；Android 需更新原有服务地址。
- 不复制 Cookie，不在 URL 传访问密钥，不承诺打开的旧网页无感迁移。
- 保留现有公网地址变更时的设备授权处理。ngrok 的进程和配置可以保留，但旧设备授权失效后，其通道请求同样需要重新登录，不能承诺旧登录连接不断。
- 已经提交的写操作不因切换自动重发；客户端保留草稿和待确认状态，继续遵守原请求回执规则。

## 5. ngrok 保持范围

ngrok Token、凭据存储、隧道实现、域名处理、通道凭证、测速、选路、写入去重、事件去重和媒体处理均沿用现有实现。不增加新的 ngrok 配置项，不更换 Token，不改变其作为第二通道的角色。

当前启动调用点使用“zrok 已配置”判断是否启动 ngrok。为了让 FRP 模式也能使用原 ngrok，调用方需要改为检查“所选主入口已配置”；这是主入口协调层的必要适配，不改 `ngrok_tunnel.rs` 的隧道实现。

主入口切换时不停止、重建或重新绑定现有 ngrok。关闭整体远程网页服务时，仍按原行为关闭 ngrok。

## 6. 数据与模块边界

### 配置与状态

- `remote-access-primary.json`：上次成功应用的 `zrok` 或 `frp`；旧安装缺失该文件时默认为 zrok。独立保存，避免普通设置刷新触发主入口切换。
- `remote-access-frp/draft.json` 和 `active.json`：分别保存候选与已生效配置，包括 Token 和可选证书；只通过本机管理接口访问。状态及通道发现接口不返回 Token 或私钥。
- `editingProvider`：仅管理器表单状态，点击面包屑时改变，不等于已应用选择。
- `activeProvider`、`publicUrl`：当前真实运行的提供方与入口；未运行时不伪装为可用。
- `switchState`：`idle`、`validating`、`applying`、`failed`，分别对应无切换、检查目标、应用目标和切换失败；失败须返回目标与原因。
- FRP 就绪状态区分缺配置、缺 HTTPS、启动中、可访问、等待重试和错误；只有完整入口检查通过才显示可访问。

### 预计涉及的模块

| 模块 | 规划改动 |
| --- | --- |
| `apps/codex-elves-manager/src/components/RemoteAccessScreen.tsx`、`PrimaryRouteControls.tsx` | 面包屑、两种配置表单、生效状态与切换动作；ngrok 区块保持现有交互 |
| `apps/codex-elves-manager/src/remote-access-types.ts` | FRP 配置及状态类型；普通远程服务设置保持原结构 |
| `apps/codex-elves-manager/src/App.tsx` | 同步浏览器预览数据，便于验证面包屑及切换状态 |
| `crates/codex-elves-core/src/remote_access.rs` | 主入口协调、候选验证、生效与失败保留、Host / Origin 边界 |
| `remote_access/frp_tunnel.rs`、`primary_route.rs` | 固定客户端校验、配置生成、受控进程、重试、候选验证与原子切换；只管理自己启动的进程 |
| `crates/codex-elves-core/src/remote_access/channels.rs`、`assets/remote-access/channels.js` | 明确当前主入口身份，显示 zrok 或 FRP；仍保留一个 ngrok 通道 |
| 网页与 Android 入口规则 | 静态核对后复用当前主地址的同源规则，包含非默认 HTTPS 端口；不放宽原 ngrok 跨域白名单 |

入口校验按协议、主机、端口精确匹配，只接受本机配置并成功验证的地址，不把域名白名单改成任意地址放行。网页及 Android 的连接、媒体、事件规则同步核对。

当前会话路由将 `location.origin` 视为主入口，设备记录也绑定公网 Origin。首版采用重新进入新地址并登录的方式，与现有模型一致；不引入跨域授权迁移协议。

## 7. 实施顺序与验收

用户已授权按原型开发；本次实现与隔离验证不代表已部署到当前真实服务，也不包含安装包或发布。

| 顺序 | 交付内容 | 通过条件 |
| --- | --- | --- |
| 1 | 面包屑与配置模型 | 两份配置独立保存；查看表单不切链路；旧配置仍选 zrok；ngrok 区块不随选择变化 |
| 2 | FRP 入口准备与验证 | TCP、HTTPS、证书、回源身份通过；凭据错误、端口冲突、证书错误均给出明确结果，原主入口继续工作 |
| 3 | 主入口双向切换 | zrok → FRP → zrok 成功；失败保留原入口；重启恢复选择；切换过程不重启 ngrok |
| 4 | 网页与 Android 联调 | 新地址登录、会话读取、单次发送、实时事件、图片视频通过；主入口与 ngrok 测速和故障选路保持原行为 |

额外验收切换期间的待确认请求、并发点击、切换中关闭远程服务、ngrok 未配置以及 FRP 运行中断线。发送必须仍是单次提交，不能靠自动重复写入掩盖切换错误。

运行验收先使用隔离实例。现有手动启动的 FRP 测试进程不自动接管或停止，发生端口占用时明确报告。验证完成后按项目规则清理本次临时测试文件。

## 8. 接入前提与验收边界

- 实施前只有 zrok 主入口与 ngrok 第二通道；本次调整主入口协调层，保留 ngrok 隧道实现。
- `channels.js` 额外接纳当前页面自己的 HTTPS Origin；其他跨入口地址保留原域名限制。Android 通过原有主地址同源规则接入，仍需真机验收。
- `prune_stale_public_devices` 会在公网地址变化后清理旧地址的设备授权，所以本稿明确重新登录，不承诺无感切换。
- 先前测试报告位于 `reports/frp-line-test-20261023-1213/report.md`，只能证明当时的合成数据链路测试通过。
- FRP 的可用 HTTPS 域名及证书仍是完整会话验收的前提，规划和表单开发可以先进行。

本次不接管用户手工运行的 FRP 客户端；源码、浏览器预览、真实隧道和安装部署分别验收。
