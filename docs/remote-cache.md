# 远程会话与 Android 缓存

Android 和浏览器共用远程会话页面。本次增加的是已授权用户的展示数据缓存；Android 原有的静态资源按摘要更新、草稿与输入回执恢复机制继续使用原实现。

## 会话与阅读位置

| 内容 | 保存方式 | 有效期与限制 |
| --- | --- | --- |
| 当前打开的会话、阅读位置、会话列表 | 独立 IndexedDB `codex-elves-read-cache-v1` | 默认 7 天 |
| 已完成、失败、已中断轮次的正文 | 同上 | 与其他只读记录合计 32 MiB，最多 64 条，单条 6 MiB；按最近访问淘汰 |
| 最近查看的正文 | 内存 | 最多 5 个会话，合计 6 MiB；每个最多 250 轮、3000 个消息项 |

打开页面时，先验证设备授权，再恢复该授权的列表、上次选择和正文，同时读取服务器最新状态。正文缓存不会提供当前审批、队列或运行状态，也不会代替发送前的真实会话设置。授权身份同时包含设备 ID 和授权创建时间；退出或收到 401 后清理只读缓存，旧标签页不能读取或清理新授权的记录。

正文超出内存限制时，保留服务器最近一页及其真实分页游标，并合并该页之后收到的新轮次；不截断单条消息或生成游标。最近页也无法容纳时保留已有有效缓存。恢复缓存后，先核对最新页，再允许使用旧分页游标加载更早内容。

滚动位置按 500ms 节流保存，并在切换会话、页面隐藏和离开时补存；一轮完成时立即保存正文。恢复时优先定位原可见消息；该消息已被缓存窗口淘汰时先显示最近内容的底部。没有正文快照时，也恢复有效的会话选择并在线读取。

同一页面内切换会话时，最近访问的会话同时保留已经渲染的消息、图片节点和过程记录展开状态。切回后先复用原页面内容，再后台核对最新消息；未变化的消息保持原节点，新增或修改的内容正常更新。渲染节点只保存在内存，与正文共用最多 5 个会话、总计 6 MiB 序列化正文的缓存限制；长会话回退到最近一页时不复用整页视图。退出、授权变更、删除会话和历史回退会清理对应视图。

缓存只是加速层。首次恢复最多等待 250ms，切换会话和目录补读磁盘时每次最多等待 50ms；IndexedDB 打开超时为 1 秒。损坏、不可序列化、超限或浏览器拒绝存储时回退网络，不阻塞登录或原有草稿恢复。

## 会话工具菜单

子代理名称、执行状态与时间、已完成数量、侧边会话标题与未读标记按授权身份和主会话 ID 分别保存。内存最多保留 32 个主会话的菜单，持久快照使用现有 IndexedDB 的 `session-menu` 类型，默认 7 天，与其他只读记录共用总计 32 MiB、最多 64 条、单条 6 MiB 的限制。

切换回主会话时先显示自己的缓存，不清空列表或数量。页面重开后也先异步恢复持久快照，网络查询并行进行，不等待本地数据库。缓存中的状态只用于展示，当前设备的读写权限与正在创建的操作单独计算，实际写操作仍由原生接口核验。

会话及子代理事件将受影响菜单标记为待核对；当前主会话在后台合并刷新，其他主会话在返回时核对。没有新事件且成功读取未满 30 秒时，重复打开或切换回来不再查询；超过 30 秒后在访问时静默核对，不增加轮询。

菜单读取期间不显示“正在读取相关会话”等加载描述。已有缓存时直接展示；首次没有缓存时保留菜单入口和分类标题，读取完成后再补充列表与数量。后台返回相同数据时保留列表 DOM，执行时间只更新原有时间节点。数据变化时更新列表与数量；有缓存时读取失败也保留原内容且不弹后台错误。迟到请求只更新所属主会话的缓存，不写入当前其他会话；晚到的持久快照不能覆盖较新的网络结果。

创建、关闭和已读的确认回执同步更新内存及持久快照，并使早于这些操作的查询结果失效。采用缓存时同时恢复关联关系，确保可以正确打开或关闭条目；关闭只在原生确认成功后移除。删除已完成子代理时重新核对数量。授权变更、退出和会话删除按既有清理流程隔离或删除相应缓存。

## 模型与 Skill 目录

- 模型及 Skill 目录的新鲜有效期统一为 1 小时，第 55 分钟提前在后台更新；模型目录及默认模型设置在当前授权下全局共享，跨会话和页面重启复用。
- `user`、`system`、`admin` Skill 元数据按路径统一存储。每个工作目录只记录适用的全局路径和项目专属项；同一工作目录的不同会话共享一份目录。
- `repo` Skill 和旧服务未提供 scope 的项保留项目范围；不把项目专属项扩散到其他项目。
- 更新期间继续返回和展示旧目录；新结果完整且格式有效后一次替换。菜单搜索、滚动位置、键盘选中项及已选模型和 Skill 均保留，后台更新不显示加载占位或关闭正在使用的菜单。
- 后台更新按目录合并重复请求。失败时保留上次成功的数据，1 分钟后重试；页面隐藏或离线时暂停定时器，返回前台或恢复网络时立即检查并补刷。Skill 定时维护当前工作目录，其他项目在访问时检查更新，不遍历刷新所有历史项目。
- `skills/changed` 将各项目目录标记为待更新并立即刷新当前目录；旧列表保留到新列表成功生成，通知前尚未完成的请求不能回填。待更新代次会持久化，重启后也不会将其他项目的旧目录误判为新鲜数据。
- 点击现有连接状态刷新入口会强制刷新模型与 Skill；仍沿用已有交互，没有新增刷新按钮、入口或配置项。预更新、变更通知和该入口刷新 Skill 时都要求原生重新扫描。
- 普通首次菜单查询使用原生扫描缓存。实际发送已选 Skill 时，仍强制重新扫描并检查当前项目、名称、路径和启用状态。

目录的 1 小时是新鲜有效期，不是删除旧数据的时间。超过 1 小时会立即尝试后台更新，同时继续使用旧目录；失败不会延长旧数据的成功时间。已授权的旧目录最多保留 7 天，仅作为更新期间或故障时的回退，仍受共享容量、退出清理和授权隔离约束。

## 图片

只有附件小图、队列图片和图片查看记录使用 `/api/images/{id}/thumbnail`。最大边长为 256px，保持宽高比；移动端 50×50px、桌面端 80×80px 的展示尺寸不变。Markdown 正文及点击放大仍使用原图。

派生图采用无损 WebP，处理 EXIF 方向并保留 ICC 配置和透明度。小图、GIF/APNG/动画 WebP、非 RGB8/RGBA8 图片、超过 1600 万像素的图片以及转换失败或体积没有减小的结果，直接返回原图。解码分配预算为 64 MiB；同时最多运行 2 个派生图任务，HTTP 请求取消后仍由实际任务持有并发许可。

服务器按源内容 SHA-256 缓存派生结果和原图回退决定，最多 128 项、16 MiB；每次重新读取并验证源文件，文件内容变化后生成新结果。原图与缩略图支持内容 ETag/304，使用 `private, no-cache` 和 `Vary: Cookie`；每次复用都必须向服务端核验，撤销授权后返回 401。其他私有 API 与图片错误继续 `no-store`。旧电脑服务没有缩略图接口时，页面仅回退一次原图。

2026-10-19 在本机以 Release 模式测量自行生成的样例，结果如下。耗时只包括派生图计算，不代表手机端或完整 HTTP 往返时间。

| 样例 | 原始字节数 | 小图字节数 | 减少 | 首次计算 |
| --- | ---: | ---: | ---: | ---: |
| 1920×1080 合成界面截图 PNG | 154470 | 17982 | 88.4% | 13.4ms |
| 2400×1600 合成照片 JPEG | 828558 | 55996 | 93.2% | 31.5ms |
| 1200×800 透明 PNG | 25297 | 20750 | 18.0% | 5.3ms |
| 带 EXIF 旋转与 ICC 的 JPEG | 64040 | 12896 | 79.9% | 8.2ms |

另外验证了 192px 小图、已高度压缩的 WebP、灰度 PNG、三类动图及超出派生像素预算的图片均保留原图。适合把缩略图用在小尺寸附件区域；正文继续保持原图，避免影响阅读细节。派生结果在服务器内存命中后不再解码，但仍需读取源文件、计算摘要和核对授权。

## 验证范围

使用隔离 localhost 夹具及 Chrome 真实 IndexedDB 验证缓存恢复、TTL、容量淘汰、损坏数据、授权切换、旧标签页隔离、长会话分页回退、目录复用与项目隔离。原生适配器通过隔离 VM 检查普通扫描复用和发送前重验。

目录更新另以可控时钟验证第 55 分钟主动刷新、1 小时新鲜度、单次并发刷新、失败退避、前后台恢复和旧请求防回填；浏览器验收在服务端挂起更新请求时继续操作旧菜单，再释放新结果核对搜索和输入不受影响。

核心回归保留在现有 `remote_access.rs` 测试模块，覆盖缩略图尺寸、透明度、缓存淘汰、原图不变、ETag/304、源内容修改、文件删除与撤销授权。资源清单及私有正文传输继续执行现有回归。

本地隔离验证不等同于安装或 Android 真机验收。正式交付通过根目录 `build.ps1` 生成 Windows 安装包，并在 Android 输入变化时同步执行正式签名 Release 构建和 lint；实际发布状态以产物校验和发行记录为准。缩略图服务和新增原生目录字段需要电脑端更新后完整生效。
