# 远程会话

## 功能范围

管理工具新增独立的「远程会话」导航入口。网页服务由 Rust launcher 托管，网页资源嵌入程序，不要求用户另行安装 Node.js 或 Bun。

网页使用已运行 Codex 桌面应用的原生会话管理器，不启动另一套 app-server，不复制执行会话：

- 读取本机项目、会话、完整分页历史和实时事件。
- 在现有项目中新建原生会话，继续已有会话。
- 项目置顶写回 `pinned-project-ids`；会话置顶使用当前桌面的 `pinnedThreads` 服务，不使用已被桌面忽略的旧置顶列表。
- 项目顺序读取 `project-order`；会话排序使用原生更新时间、`sidebar-project-thread-orders`、`codex-sidebar-chat-order-v1` 和桌面排序偏好。网页不保存独立的项目顺序。
- 渲染用户消息、Markdown、代码块、表格、思考记录、命令输出和文件修改；工具记录可折叠。
- 默认继承会话模型和思考深度；明确选择时才覆盖。新的 GPT 思考深度选择不超过 `xhigh`，Claude 不超过 `max`，不批量改写已有会话配置。
- 通过原生发送入口续聊，展示桌面的原生消息队列，不维护第二套执行队列。
- 处理命令、文件修改、权限审批及常见用户询问。无法安全适配的请求会提示在桌面处理。
- 停止同时调用原生停止与该会话的后台终端清理，不结束其他会话或整台机器的进程。

这不是桌面的完整复制：不提供任意文件浏览、任意 RPC、CDP、脚本执行入口或桌面外部登录代办。复杂嵌入式应用和未适配的询问仍需在桌面查看或处理。本地图片只允许读取原生会话实际引用的受支持图片，不提供客户端传入任意路径的接口。

## 认证与控制权限（2026-10-17）

公开入口仅包含登录所需的静态页面／资源、`/api/login-status` 和 `/api/connect`。获取静态网页不代表获得设备授权。客户端用正确密钥换取设备 Cookie 后可按原有效期继续访问；Cookie 需与服务端保存的设备、当前密钥代次和有效期一致。未设置密钥、没有凭证、伪造凭证、授权撤销或密钥轮换均不能读取会话或调用控制接口。公开页面不提供本机管理密钥、内部 `native.js`、任意 RPC 或任意文件读取。

所有其他 `/api/*` 请求先通过 Host／Origin 边界和服务端身份检查，再解析请求正文。匿名或随机 Cookie 的请求会在读取密钥文件前拒绝，因此没有上传完整图片或触发密钥派生计算的必要。历史、回执、图片、SSE 和 WebSocket 均执行服务端鉴权；前端按钮、Android 保存的登录标记及 PWA 缓存都不作为授权依据。

启用、只读和远程审批权限使用控制器中的当前策略。在应用设置时，策略先于文件锁、隧道检查等等待点发布；旧页面、旧路由状态和已进入处理流程的请求不能沿用较宽松的旧权限。写操作在接收、准备派发及实际 CDP 派发边界复核授权。大请求编码和 WebSocket 握手完成后，持有设备认证、密钥轮换和短暂策略锁完成指令同步入队，随后立即释放锁，再等待网络刷新及原生响应。这样撤权与指令接受有明确先后关系，不会持锁等待整个 Codex 操作。

慢查询的序列化／压缩完成、图片读取完成、回执结果返回前会再次检查授权。授权失效后不继续返回私有结果。SSE／WebSocket 的业务事件也持续核对设备授权及服务启用状态，失效后关闭业务流。

在实际派发前被拒绝的操作保存为 `failed`、标记 `notSent`，保留原幂等 ID 和请求摘要；恢复权限后重试相同请求仍返回原失败回执，不偷偷重新执行。指令已经入队后发生传输故障仍视为 `unknown`。已接受操作之后授权失效，响应只返回通用拒绝和 `outcomeUnknown` 提示，不返回原生结果；网页清除失效登录，但不会把该情况误报为确定“未发送”。授权撤销不承诺撤回已经被 Codex 接受的操作，重新连接后应查看会话确认。

每次授权复核仍读取持久化密钥和登录锁状态。仅对 `id`、`salt`、`hash`、`value` 四字段完全相同、已经通过验证的密钥材料复用最近一次 KDF 结果；最多保留一条，任一字段变化即重新验证。该缓存不缓存设备授权、权限、有效期或登录锁状态，也不依赖文件修改时间。

以上是源码行为；正在运行的旧服务需要更新程序并重新启动后才会应用。隔离验收使用合成凭据、假原生桥及假 CDP 对端，没有操作真实会话或更改真实密钥。

## 低速网络优化（2026-10-17）

以下行为取代本文早期验收记录中有关读取响应“不压缩”和事件连接只依赖浏览器断开通知的说明。

历史、侧栏、会话等 `/api/read/*` 成功响应支持 gzip。客户端允许 gzip、JSON 正文至少 1 KiB 且压缩后更小时才使用压缩；小响应和明确禁用 gzip 的客户端保持原始正文。序列化与压缩在后台任务执行，响应保持 `Cache-Control: no-store`，增加 `Vary: Accept-Encoding`，不为私有会话数据生成 ETag 或持久 HTTP 缓存。鉴权失败、写操作回执、图片和事件流不经过此压缩入口。

事件通道对 WebSocket 握手设置 45 秒期限，对已连接但连续 75 秒没有事件或心跳的连接执行清理和退避重连。浏览器离线时暂停重试，恢复网络后合并恢复请求；后台定时器长时间停顿后先留 20 秒处理已排队事件。SharedWorker 在启动后 20 秒无回复，或前台在线时连续 90 秒不回应端口消息，会隔离旧端口并切换普通 WebSocket。正常多标签页仍共用一个事件连接，不增加业务写操作或自动重发消息。

恢复同步遇到旧请求尚未结束时，会安排合并补读，不把旧请求当作恢复后的最新状态。队列 HTTP 快照同时核对读取开始后的本地状态变化，迟到的旧来源不得退休已接收的新来源。首次读取授权因网络失败而尚未取得 session 时，恢复网络或返回前台也会重试；明确 401 仍需要重新登录。HTTP 探测失败与离线会清除过期的在线延迟展示。

最近查看的会话正文只在当前页面内存中保存，最多 5 个会话、合计 6 MiB，并限制单份轮次和条目数；按设备和会话隔离。切回时先显示可读正文及核对提示，再读取最新状态，不从缓存恢复审批、队列操作权限或可写会话设置。待发送草稿不使用这个淘汰规则。最新历史读取与会话设置并行；同一选择代次的读取合并，已有分页结束后直接补读最新页，调用方等待实际补读完成。旧选择的响应不能覆盖新选择，实时计划和差异也不会被较早的历史快照覆盖。最新页失败保留正文和可见重试入口；服务端确认空历史、会话回退或删除时清除相应旧快照，不让已经移除的记录在下一次切换时重新出现。

HTTP 成功不代表响应正文已完整读取。成功响应的正文读取或 JSON 解析失败时，网页保留失败状态，不再构造缺少历史数据的伪成功结果。历史请求仅对此类正文失败自动重读一次，复用原会话和分页游标；切换会话、离页、取消或删除后不再重读或合入旧结果。完整 JSON 的协议格式错误、HTTP 错误、超时及普通连接失败不在此自动补读范围内。补读仍失败时保留已有历史、草稿和手动重试入口，不无限重试，也不把失败当作空历史。发送等写动作的回包正文失败则核对原请求回执，不重新发送，明确确认前不清除待确认文字和图片。

未发送的文字、Skill、图片和目标输入模式使用 IndexedDB 恢复；图片单独保存并由记录引用，发送回执在 sessionStorage 中只保存轻量元数据。可靠提交仍先持久保存草稿与原幂等 ID，再发出写请求。当前图片读取完成前，按钮和快捷键均不能发送；旧发送回执到达时若新图片仍在读取，不清空当前输入或删除其已保存草稿。切换会话即解除旧图片的读取状态，旧任务迟到完成不清除新任务的读取锁、不向新会话添加图片或提示错误。已知失败先保存可恢复输入再移除 pending；用户已写入新内容时保留新稿，并提供旧输入恢复入口。授权更换或退出清理对应私有恢复记录，旧页面不能跨授权写入；持久化不可用时明确提示，本地小文字回执可退回原有 sessionStorage 路径，大图保存失败则在提交前停止。

写请求增加包含上传、响应头与响应正文的等待预算：基础 90 秒，按请求体大小和保守上传速度追加，最长 20 分钟。超时只表示没有取得结果，保留原回执并退出发送等待，后续仅查询原 ID，不自动重发。只读接口继续有独立期限。

浏览器在页面可用后后台准备当前版本清单中的全部静态资源，包括尚未展示的图表库；可选项按文件大小从小到大准备，Mermaid 不占用基础页面的启动关键队列。后台同时最多下载一项，当前页面急需的资源最多并行两项；同路径需求共享下载，主动前台需求可提升已有任务，并暂停不再紧急的后台传输。会话读取、恢复和写入直到响应正文处理完毕都保持忙状态，后台新任务等其结束后再开始；每 15 秒的被动状态轮询不取消已经进行的下载，避免单个资源耗时超过轮询周期时反复重下。可选资源被主动操作中断两次后退避五分钟并继续后面的资源，当前页面按需请求可直接绕过该退避。共享读取从被动升级为主动时会提高优先级，不重复 HTTP 或被后续被动调用降级。忙状态按标签隔离，每 10 秒续期、30 秒过期，关闭某个标签不会永久阻止后台任务。更新逐项核对 MIME、大小和 SHA-256，复用有效旧缓存及已下载的 HTTP 表示。缓存缺项只能按当前固定版本清单恢复，无法匹配时明确失败，不混用线上新脚本与旧样式。设置弹窗仅在检查、准备、待启用或失败等状态显示说明，并保留失败重试入口；基础缓存就绪后隐藏该状态行。新版待启用时提示重开页面，不强制刷新或丢弃正在输入的草稿。静态资源准备完成后可从缓存加载相应模块；完成前的首次需求仍可能联网。会话消息、审批及图片附件属于动态数据，不会因静态预下载而全部离线可用，也不会自动全量抓取所有聊天。

网页启动依赖分为以下三层：

| 层次 | 资源和触发条件 | 对当前会话的影响 |
| --- | --- | --- |
| 基础页面 | HTML、CSS、`app.js`、事件连接、草稿恢复、附件和轻量 Markdown 入口；HTML 预加载直接模块依赖 | 优先完成登录、会话选择、消息读取和输入；不等待图表及格式库 |
| 正文格式及辅助资源 | 首次有正文时并行导入 `markdown-renderer.js`、Marked、DOMPurify；图标和格式库也进入空闲预下载队列 | 加载期间显示安全转义的纯文本；失败保留正文并提供有限重试，成功后原地恢复 Markdown、Skill、附件等显示 |
| 图表 | Mermaid 静态文件随空闲队列预下载，仅在图表靠近可视区约 200 px 时导入并执行 | 较小的可选资源先准备；已挂载但离屏的图表暂不渲染；切换后清理旧观察项，回到会话后重新登记 |

离线 worker 仅等待基础页面资源校验、保存成功后就绪，可选项失败不撤销基础缓存。模块重试 query 仍对应固定版本清单中的同一路径；成功的模块会复用，不随其他模块的重试重复下载。Markdown、链接、图片和 SVG 的原有安全清洗规则保持不变。格式库不可用时的纯文本由轻量入口转义，不依赖第三方 HTML 解析器。

格式升级、图片完成和图表替换使用同步布局事务：跟随最新消息时保持底部；阅读历史时在变更开始前捕获视口首行的文字位置，变更后在当前消息根内恢复该位置，不跨网络等待保存旧滚动快照。Markdown 标点消失后按正文字符及上下文寻找同一位置，找不到原文字（如源码已变为图表）时退回所在内容块。后续行仍可能因段落或折行变化发生局部重排，不承诺所有屏内像素固定。

Mermaid 下载期间保持源码可读，主题刷新时保留旧图；新图完整解码后一次替换，不再先隐藏源码或强设 220 px 加载高度。图表在切走期间完成时会失效同一个旧渲染标识，重新挂载仍可使用已完成结果，旧任务不能清除新主题的标识。未知尺寸的正文图片先保留短加载行及可触发 lazy 请求的同位置非零元素，完成后写入真实宽高并在同步布局事务中显示；失败移除等待状态并保留原图片不可用提示。原有明确尺寸的附件缩略图保持原布局。异步完成时重新核对当前 DOM 和会话，旧内容不能滚动新会话。

服务端静态资源的摘要和 gzip 也改为按文件首次需要时生成并复用，放在阻塞线程池执行；请求首页不会触发整套 Mermaid 的压缩。gzip 正文使用共享字节存储，保持各编码独立 ETag、条件请求及现有安全响应头。

加载页独立启动缓存管理模块，并提供 `/cache-recovery.html` 恢复入口。恢复页及其自包含脚本不进入版本壳清单，响应使用 `no-store`；即使 PWA 模块本身缺项，也能检查新版或请求当前 worker 按其固定清单补齐必需资源。它不注销设备、不清草稿或回执，也不强制激活新 worker。新版等待启用时必须关闭本站所有旧页面（包括恢复页）后再打开；同版补齐完成后可直接重开。当前版本的缓存清单与完整性标记也损坏时会明确失败，不假装已经修复。

Android 用清单内容版本识别内置资源是否已与服务端一致，更新时复用已校验的当前、上一版和内置文件，只下载差异；gzip 按编码长度限额与解压后的长度、摘要分别校验。资源校验和更新使用独立队列，切换服务、退出或关闭页面会取消当前传输；完整候选仍在下次开页启用。当前和上一份缓存都损坏时回退内置资源，更新失败可重试，不强制打断健康页面。

Android APK 使用独立版本。设置弹窗底部左侧从原生外壳读取并显示 `v版本号`，点击可检查更新；启动及返回前台后也会按间隔检查本仓库的 Android GitHub Release。新版 APK 下载后校验摘要、包名、版本和签名，再交给系统安装器确认安装。APK 自更新与上述服务端网页资源更新分别执行，协议及构建规则见 [Android 版本与应用更新](android-update.md)。

这些是源码行为；正式网页需要更新运行程序后生效。隔离网络与状态回放不代表实体 4G 手机、运营商切换或 Android 真机验收。

## 网页输入与外观

### 本机前端调试

需要保持现有 `codex-elves.exe` 和真实会话运行时，在仓库根目录启动独立调试入口：

```powershell
node .\scripts\dev-remote-access.mjs
```

打开 `http://localhost:1432/`，使用现有远程访问密钥登录。需要直接查看指定会话时，可在地址后追加 `#thread=<会话 ID>`。调试入口只监听 `127.0.0.1`，默认将会话 API、图片和实时事件转发给现有 `http://127.0.0.1:45222`；不会启动或替换 launcher，不需要管理员权限或安装包。端口已占用时用 `--port 1433`，后端端口不同时用 `--upstream http://127.0.0.1:45223`。

网页资源每次从 `assets/remote-access/` 读取，修改 JS/CSS 后刷新调试页即可；浏览器禁止缓存这些调试资源。默认使用 SSE 兼容旧版后端；后端已支持 WebSocket 时可指定 `--events-transport websocket`，仅转发 `/api/events/ws` 升级请求，不开放其它套接字或任意代理路径。调试页使用独立命名的设备 cookie，仍保留后端的登录校验、HttpOnly、SameSite 和 Secure 属性，不读取、保存或输出访问密钥。入口会检查本机 Host、同源 Origin 和跨站请求，再将合法请求转发给固定的本机后端。

管理器中「生成」仅填入候选访问密钥，点击右侧「保存」后才生效；明文及校验摘要保存在本机，输入框默认遮挡明文。成功保存不同的新密钥会撤销已有设备授权。若经用户明确同意，在浏览器中将已有设备授权复用于调试页，则两页共享同一设备授权，任一页点击「退出」都会使另一页失去授权。

这里连接的是真实会话，不是模拟数据：发送、停止、编辑和删除等操作与正式网页一样会作用于真实后端。仅查看渲染时不要发送测试消息。该入口不能让 Rust 后端或嵌入程序的 `native.js` 自动更新，原远程网址也仍由旧程序提供；这两类改动仍需要更新相应运行程序。停止调试时在启动终端按 `Ctrl+C`，原服务不受影响。

使用 localhost 不会改变图片读取权限。历史消息优先使用后端注册的同源图片地址；旧后端返回原生内嵌图片时，网页也可显示缩略图并打开预览，队列同样支持内嵌缩略图。只接受 PNG、JPEG、WebP 和 GIF 的 Base64 图片并核对文件头，不加载外部 URL、SVG 或 `file:` 路径。图片发送和队列图片删除仍按 `/api/session` 的能力声明启用，旧程序未声明支持时不会因更换为 localhost 而开放；需要更新运行程序后使用。

### 长会话与实时消息

历史每页读取最近 5 轮完整消息，使用原生 `itemSnapshot: "latest"` 和 `itemLimit: null`，不复用桌面滚动位置的旧消息游标，也不把 `summary` 当成完整历史。点击「加载更早的消息」继续分页，保留当前阅读位置。

流式通知按浏览器帧合并渲染；未变化的消息和已展开工具保留原节点。折叠工具不生成输出正文，展开后按每段 20,000 个字符显示，可继续加载剩余输出。历史读取期间到达的新消息不会被旧快照覆盖，回合完成通知中的空 `items` 不会清空已有消息；思考摘要与正文分别按原生分段索引更新。

消息正文使用本地打包的 Markdown 解析及 HTML 净化，支持嵌套列表、有序列表起始编号、任务列表、表格、引用和围栏代码。代码块仍可复制，普通本地路径显示文件引用。与原生会话一样移除完整的内部引用控制标记，不把缺少来源元数据的标记展示为正文或猜造链接。会话中的本地图片和用户图片附件通过已注册的同源地址显示缩略图。正文图片保持原比例，桌面端宽高均不超过 150px，手机端均不超过 120px；点击后的原图预览不受此限制。不直接加载外部图片或浏览器 `file:` 地址。

用户消息下方显示原生发送时间和复制操作，桌面悬停或键盘聚焦时出现，触屏和窄屏保持可见，不需要点击气泡展开。时间取自原生回合、排队送达记录或消息条目的真实时间；缺少来源时不以网页接收时间补造。纯图片用户消息同样支持时间和操作。已完成的主回复提供复制操作。最后一轮可编辑的初始用户消息还提供铅笔入口，在原消息位置打开编辑框，仅显示「取消」「发送」，不提供「发送并恢复文件」。发送通过原生编辑入口替换后续回复并重新执行，原附件和隐藏上下文保留，不恢复磁盘文件；底部普通草稿保持不变。支持 Escape 取消、Ctrl/Cmd+Enter 发送，空文字禁用发送；失败时保留修改，回执待确认时锁定重复提交。活动回合、上下文压缩、待确认提交、队列或后续补充消息存在时禁止编辑。提交前再次检查消息 ID 和回合 ID，避免修改已过期消息。

每轮按原生显示结构组织为「用户请求 → 活动 → 主回复」，同一轮只有一个可见的活动耗时标题。思考、过程说明、工具按原始顺序展示，已结束且没有正文的思考记录不生成空行；执行中的补充消息和用户回答单独显示，不会被折叠过程隐藏，也不新增「工作过程」标题或重置计时。`commentary` 属于活动正文，不作为最终答复；主回复单独展示，兼容旧历史中 `phase: null` 的消息。展开状态由用户操作保留，工具正文仍按需加载。

轮次开始事件早于用户消息到达时，不提前显示空的「已处理 / 正在思考」占位，也不为无内容的轮次保留空白间距。用户消息由原生事件或历史读取补回后，同帧按「用户消息 → 活动」显示；已有的过程正文、工具和模型切换记录仍沿用原有展示规则。

已知轮次开始时间且出现实际工作后，在首段工作前显示「已处理 4分38秒」，每秒只更新现有标题，不发起历史轮询；有效 `final_answer` 开始或回合完成后冻结，最终耗时显示「用时 4分38秒」，位于最后一段工作、最终答复之前。完成态优先使用原生 `durationMs`，否则使用可靠的起止时间；未知时间显示「活动」，不使用用户消息时间或网页接收时间补造。切换会话、后台、离开页面或完成后停止时钟；返回前台依据真实起时恢复。历史迟到响应或空时间字段不能清空已确认的实时耗时。

以可见的过程正文为分隔，将连续命令、浏览器及其他 MCP/动态工具、文件修改、网页搜索和已完成思考收纳到一个默认折叠的工作摘要，不再将浏览器调用和文件修改逐条摊开。纯命令显示「运行了命令」；混合记录按实际类别显示，例如「已使用 浏览器和Chrome编辑了多个文件运行了命令」。浏览器名称读取原生结果中的 `codex/toolSurface`，没有结果元数据的统一浏览器插件沿用当前原生的 Chrome 名称，未知工具保留其服务器名称。没有通用浏览器来源的具名工具使用「集成」文案；文件修改沿用原生中文摘要的「编辑了多个文件」，具体去重文件数量保留在提示中。

运行中的摘要优先描述最后一条仍在执行的命令、工具或文件操作；浏览器、MCP 及动态工具使用其 `arguments.title` 具体调用标题，缺少标题时显示可读工具名，不再只显示「正在使用 Chrome」。执行中的折叠标题与展开工具行保留工具图标，以文字流光表示状态，不增加整行扫光背景或「进行中」尾标；所有操作结束后恢复「已使用 Chrome 集成」等类别汇总，不保留最后一次调用标题。实时更新保留展开状态，长标题单行省略且可悬停查看，减少动态效果设置下不播放流光。已完成摘要不把历史失败逐条突出为红色失败条，失败数量仍可通过悬停、辅助技术及展开详情查看。展开后保留原始记录顺序和网页版的「已完成思考」，思考仍可独立展开。子记录使用缩进和左侧竖线区分层级，命令正文使用小号等宽字体并保持单行省略，状态和思考使用界面字体；每行摘要至少 40px 高，兼顾桌面行距和触控点击。输出仍按需加载，面板有最大高度，流式更新保留展开状态和滚动位置。用户消息、过程正文、正在进行的思考、显式错误和计划保留展示边界；纯思考不伪造工具摘要。子代理以彩色小图案、名称和状态组成紧凑单行，位于同一工作过程内，不重复制造工作过程标题，也不展示 thread ID、大卡片、内部提示词或子会话打开入口；状态未知时不伪装完成。

浏览器、MCP 和动态工具行在原位置展开，不给标题及整条记录增加外框。展开内容按返回顺序显示真实的纯文本、图片或错误，不展示调用 ID、输入参数和完整记录 JSON；工具传输层包裹的内容列表会解包后展示。纯文本保留原生风格的结果面板，图片复用同页预览，长文本每次展示 20,000 字符。未知结果类型明确提示在桌面查看，不执行工具输出中的 HTML，也不直接加载外部图片地址。

连续的图片查看记录合并为「已查看 N 张图像」，默认显示 80×80 缩略图，支持折叠和原图预览，不逐条平铺文件名；遇到正文、思考或其它类型记录立即结束合并。缩略图不可用时显示占位，不使用任意路径或外部 URL 兜底。

上下文压缩在消息流中显示「正在压缩上下文 · 可能需要几分钟」，完成后同一记录原位更新；只有原生明确标为自动压缩时显示「上下文已自动压缩」。正常运行时不重复显示输入框上方的黄色警告或额外「正在处理」；送达未知、旧设备授权及待确认状态仍保留锁定和恢复操作。模型切换读取原生 `modelChanged`/`modelRerouted` 记录，按原生锚点显示在对应用户消息前，使用分隔线、模型名称与说明按钮；不把尚未发送的菜单选择伪造为已执行的模型变更。

原生适配器版本 `25` 补齐发送后自动压缩期间的用户消息显示：本轮原生已保存输入、但正式用户消息记录尚未产生时，从原生 `params.input` 补齐文本与图片，在压缩记录之前显示；实时事件和历史重读使用同一来源。正式记录到达后按原生 `clientUserMessageId` / `clientId` 合并，不重复生成气泡，也不依据相同文本去重；迟到的旧历史不会将正式消息恢复为临时记录，或把同一条已完成压缩回退为正在压缩。手动压缩、执行中途的压缩及尚未加载完整的旧记录不补造用户消息；不改变原生压缩的启动时机，也不从网页草稿推断消息已经送达。此改动包含服务内嵌适配脚本，需要更新远程访问服务后生效。

用户消息只展示原生可见的请求、浏览器批注或问答，不平铺 `## My request:` 之前的附加上下文，也不把 `<send_user_message_question_reply>` 的 XML/JSON 当作气泡正文。普通请求渲染链接、加粗等 Markdown 并保留输入换行，图片附件以独立缩略图放在气泡上方。有效问答显示单行问题摘要与纯文本回答，悬停可查看完整问题；损坏格式和无关 XML 保留原文。命令组内的单条命令摘要优先使用原生 `commandActions` 中的实际命令，`js` 工具使用原生提供的简短操作标题。正在思考时以弱化文字显示最新非空片段，最多预览两行，点击后查看完整内容；尚无正文时保留「正在思考」状态。思考展开后使用 Markdown，最大高度与原生的 `8.75rem` 对齐。

单条命令折叠时显示「已运行」及单行命令摘要，展开后收起摘要文字，标题显示「已运行命令」和向下箭头。详情使用带边框的圆角 Shell 面板，先显示 `$ 实际命令`，再按原始换行展示输出；命令选择与折叠摘要一致，不重复平铺可替代的 shell 启动包装。长输出在面板内滚动，每次加载 20,000 字符，完整命令不占输出分页额度；错误输出及非零退出码保留。输出始终按纯文本展示，不作为 HTML 执行。

最终回复后展示已完成的文件修改卡，默认显示 3 个去重后的文件路径，可展开其余文件及该文件的修改记录。卡片只保留标题区与文件列表之间的分隔线，文件行和「再显示」入口之间不加分隔线；路径目录使用次级文字色、文件名使用正文色，「再显示 / 收起」带方向图标。行数统计优先使用原生 `turn.diff`；历史未提供时按原生规则净合并同文件连续 patch，无法按顺序合并的片段保留原分段统计，与桌面文件卡口径一致，不冒充仓库 Git 净变更。损坏、二进制或超出解析上限的差异不显示不完整总计；不提供虚假的撤销按钮。

图片引用由原生历史、队列及原生 item 通知注册，接口只接收已注册 ID，并继续验证设备授权与请求来源。磁盘图片只允许本机固定磁盘的 PNG/JPEG/GIF/WebP，文件最多 25 MiB，拒绝网络路径、设备路径、非图片和超限尺寸。GET 时按真实文件格式返回 MIME，兼容扩展名为 `.png`、内容实际为 JPEG 的截图。内联图片转换为同源注册引用，不将 data URL 平铺到历史或队列响应；缓存最多保存 1024 个引用，内联内容合计最多 64 MiB，达到限制时淘汰较早引用。文件已删除、引用过期或格式不支持时明确显示不可用提示，不扩大为任意文件读取能力。

消息输入框支持选择、粘贴和拖入图片，待发送缩略图为 40×40，可移除，并随会话或新建项目草稿保留。本地选择、预览和移除图片不依赖实时连接；手机打开相册导致网页暂停连接时，选图返回仍保留附件，重连前禁止发送。只读、正在提交及已有消息编辑事务的附件限制仍然生效；上下文压缩期间可继续编辑普通草稿的文字、Skill 和图片，在服务支持且压缩状态已确认时发送到原生队列。每条最多 4 张，单张最多 5 MiB、合计最多 12 MiB，只接受 PNG/JPEG/WebP/GIF；前后端校验格式、实际大小及尺寸，最长边不超过 16384 像素、总像素不超过 100 MP。文本与图片、纯图片均可发送或入队；编辑已发消息或排队消息时原附件只读保留。前端通过会话能力确认后端支持图片发送；旧后端仍可预览，但禁止提交并明确提示更新，避免附件被旧程序忽略。

用户附件和 AI 查看图片记录均支持同页预览，可通过关闭按钮、Escape 或点击遮罩关闭，关闭后焦点返回触发的缩略图。

待发送图片也可点击缩略图或使用 Enter、Space 打开同一预览窗口；右上角移除按钮独立操作，不打开预览，也不提交消息。只读或附件锁定时仍可查看原图，原有移除与发送权限保持不变。

网页按选择器返回的文件列表顺序显示和提交图片，分批选择时追加到已有图片之后；读取速度、草稿恢复和队列恢复不改变顺序。Android 容器在系统支持有序 Photo Picker 时，对多选图片请求启用 `EXTRA_PICK_IMAGES_IN_ORDER`，按用户选取顺序接收图片；取消不添加图片，无法启动时回退原文件选择器。普通浏览器及不支持该能力的旧 Android 仍采用选择器返回顺序，网页无法从文件名、修改时间或图片内容可靠重建选择器未提供的点击次序，不做统一倒序。

消息输入框默认高度 100px，随内容增长到 180px 后内部滚动。发送和停止共用右下角的圆形按钮：执行中且没有文字或图片时显示停止；添加文字或图片后原位切换为发送。会话执行中或已有待执行消息时，新消息优先加入原生服务端队列；服务端队列未启用或不能接收当前消息时，通过 Codex 的 turn coordinator 使用原生本地队列，不维护网页自己的执行队列，也不把普通发送改为引导。空闲且没有队列时沿用原生直接发送。Skills 仍作为原生输入项提交，显式模型与思考深度按原生下一轮设置应用到目标会话，不承诺为每条队列消息冻结独立模型配置。发送与停止均防止重复提交，不额外显示通用「正在处理」行；系统选择减少动态效果时关闭动画。

手机端滚动正文收缩输入区时，按钮行上方间距随收缩比例从 6px 减少至 0，完全收缩后不再保留额外间隙。点击或聚焦恢复编辑时按内容自然撑高，继续输入多行文字、添加或移除图片不会保留上一次的固定输入高度。

点击发送后，按钮立即显示旋转指示和「发送中…」，收到成功回执后以「同步中…」等待消息更新；会话列表在后台刷新，不延长发送按钮的锁定。发送时保留输入焦点，新建会话成功后不把焦点移到侧栏按钮；等待期间可继续输入，后续草稿不会被清空。明确失败时保留原草稿并恢复发送，送达不明时继续锁定且保留回执核对入口，不自动重发。正常发送期间不展示人工解除锁定操作；状态只占输入框底部同一行，不新增消息区的通用处理提示。

排队消息以单行显示正文和第一张 20×20 图片缩略图，不显示其他缩略图或多图计数，仅改变预览、不丢弃其余附件。「编辑」「删除」收纳到 `...` 菜单，保留独立「引导」。桌面可拖动消息正文、缩略图或左侧手柄排序；触屏长按手柄后拖动，文字区保留正常滚动，键盘上下方向键也可排序。提交时核对原 ID 与预期顺序，回执未知时不重复提交。编辑通过原生取出、恢复令牌更新正文或图片，并核对恢复后的身份和真实输入；保留未修改的附件、Skill、隐藏上下文及原生配置，无法安全识别的输入不会被改写。「引导」复用原生队列项与准备器，不复制原文另发新消息。提交状态未知时提示核对，不自动重发。

队列行与折叠目标条共用高度：默认桌面为 34px、手机为 36px，大字号时一起增高。队列最多显示四行，其余消息在队列内部滚动，不继续向上堆叠；不足四条按实际条数显示，短屏可进一步收缩，保留目标条和输入区域。同一会话刷新队列时保留内部滚动位置，切换会话从队列顶部显示；拖动和键盘排序只滚动队列区域。

原生适配器版本 `24` 补齐本地队列兼容：读取、刷新和排序通过 coordinator 的 `loadMessages` 获取当前启用的队列，不再无条件调用服务端队列接口。本地入队通过 `sendMessage`，显式指定排队模式，并按原生重放上下文持久化完整输入，避免重载后丢失 Skill 或图片；编辑继续使用原生取出、恢复令牌，并核对本地保存的真实输入。原生只允许直接发送的特殊会话仍明确拒绝排队，不绕过限制。入队调用开始后无法确认结果时保持未知回执，不自动重发。

原生适配器版本 `26` 为队列快照增加 `queueEpoch` 和单调递增的 `queueRevision`，覆盖入队回执、实时事件、会话及队列读取，以及删除、排序、编辑和引导结果。网页按快照采集顺序更新，迟到的旧空队列不能覆盖已确认入队的消息；相同快照不重复渲染，真正执行或删除产生的新快照仍立即移除对应消息，不使用延时保留或网页私有执行队列。服务重连后以重新读取的快照确认新 epoch，不接受已淘汰服务的旧回包；切换会话时清理对应显示状态。服务端入队后按原生 `afterMutation` 方式刷新，避免复用变更前仍在完成的读取。首次连接不含版本字段的旧服务时仍保留原有兼容路径，完整修复需要更新远程访问服务。

2026-10-16 验证：23 项适配检查、15 项生产前端隔离浏览器流程通过；安装版 Codex `26.1007.9446.0` 的真实 coordinator 类另在独立内存存储中完成两条消息入队、重载、编辑、排序和空闲后自动执行验证，图片及 Skill 输入保留，未调用真实模型或修改现有会话。此修复位于服务内嵌的 `native.js`，需要更新远程访问服务；仅刷新 `1432` 网页不会升级正在运行的原生适配器。

向上阅读离开底部后，输入框上方居中显示圆形定位按钮：执行中为三个动画圆点，完成后为向下箭头。新内容不会强行把阅读位置拉回底部；点击按钮才恢复跟随最新消息。

同一来源的多个正式网页标签通过 SharedWorker 共用一条 WebSocket 事件连接。页面离开时释放订阅，最后一个订阅关闭后断开连接；不支持 SharedWorker 时回退独立连接，并在页面隐藏时释放。原有设备鉴权、断线恢复和撤权处理仍然生效。本机调试默认使用独立 SSE，以兼容仍在运行的旧版后端。

从外部链接进入合法访问地址时，只允许根页面的 GET/HEAD 顶层导航通过来源校验。跨站 API、写请求、错误 Host 和错误 Origin 仍会被拒绝，访问密钥和设备授权规则不变。

### 模型与上下文

输入框下方同时显示当前模型名称和思考深度；点击后弹出菜单，不再使用两个常驻下拉框。模型名称优先使用原生显示名称，思考深度只列出原生模型列表支持的选项，使用「轻度」「中」「高」「极高」「Max」「Ultra」等简洁名称，不显示英文说明或重复标题。菜单不提供「最低」（`minimal`），切换模型时也不自动选择该等级；不改写已有会话的实际配置。Ultra 仅在原生功能开关已开放、本机 `enabled-reasoning-efforts` 设置已启用该等级、且所选模型支持时展示；原生适配读取和提交校验使用同一份过滤结果。旧后端未明确返回 `ultraReasoningEnabled: true` 时，网页默认隐藏 Ultra，也不因当前会话值为 Ultra 补造选项。默认继承会话设置，显式选择仅随下一条消息提交；选择模型时先采用该模型有效的默认深度。菜单支持方向键、Home、End 和 Escape。

模型名称左侧显示 18px 的上下文进度环，与模型及操作按钮保持同一行，长模型名省略而不换行。手机轻点圆环后显示 `200k / 33%，600k` 这样的完整用量提示，再次轻点或点击外部收起；桌面悬停或键盘聚焦也可查看，Escape 收起。浮层显示在工具栏外，并随滚动、输入框收缩和可视区域变化重新定位；打开其他菜单、切换或新建会话、退出页面时收起，只读设备同样可查看。数据取自 Codex 原生 `latestTokenUsageInfo` 的 `last.totalTokens` 和 `modelContextWindow`，表示最后一次请求的上下文占用，不是累计 Token，也不按消息字数估算。Token 通知实时更新当前会话及已展开提示；原生未提供有效容量或用量时显示「上下文信息尚未提供」。

在编辑框输入 `/` 后，菜单顶部显示「压缩」，下方为 Skill，不保留工具栏常驻压缩按钮。选择压缩只移除当前 slash 命令，保留其他草稿，然后调用 Codex 原生手动上下文压缩；是否允许在当前回合提交由原生客户端校验。提交回执不代表压缩完成；压缩期间可继续编辑普通草稿，停止、重复压缩、目标创建、既有消息编辑及队列事务仍保留原门禁。原生已确认正在运行或准备压缩时，普通消息默认加入原生队列，由原生在压缩和当前回合允许的时机按顺序执行。本页请求尚未确认、结果未知或回执属于旧设备授权时，草稿仍可编辑，但发送保持保护；不自动重发压缩，可查询回执或重新读取状态，仅在本机核对后才可人工解除。

压缩期间排队由 `/api/session` 的 `capabilities.compactionQueueSend` 声明。网页普通 `send` 请求在上述已确认状态携带 `queueOnly:true`，保留稳定的 `clientUserMessageId`、Skill、图片以及已选模型/推理参数；未压缩的普通发送不添加该字段。字段若存在必须为布尔值，不能用于目标、新建或其他写动作。原生侧也检查实时压缩状态，即使页面滞后，也不能把压缩中的普通消息直接发送或引导到当前执行中。没有新能力的旧服务允许继续写草稿，排队发送保持禁用并提示更新服务。

排队复用 Codex 的 server/local 队列与调度器，不建立网页自有消息队列。已有 local 消息时走原生 coordinator，避免新增 server 消息排到旧 local 消息之前；同一客户端消息身份的在途重复请求合并，输入不一致时拒绝。结果未知的入队仅核对原生状态，不再次添加；本地 `pending`、`sending`、`outcome-unknown` 占位不能作为已确认排队的依据。只有确认后才清理已提交草稿，发送期间继续编辑的内容不会被旧回执覆盖。

原生适配器版本 `46` 将空闲普通发送也交给同一原生准备器及 coordinator，保留网页的稳定客户端消息 ID、模型、思考深度、图片和 Skill；空闲时仍立即发送，不强制加入 server queue。异步准备期间才开始压缩时，由 coordinator 延后执行。原生 `send-only` 会话保留空闲直接发送，仍拒绝排队或压缩期间发送。follower 窗口仅返回 `queued`、但本地消息仍为 `pending` 时，必须继续核对原生队列或已接受消息，不能据此清草稿或解除防重复保护。准备、模型设置及提交前检查原始 manager 身份和会话删除记录；连接更换或会话已删除时，旧请求不得借当前 manager 继续提交。

原生会话设置目标后，输入框上方显示紧凑目标条，包括状态标题、单行省略的目标正文及运行时间；展开后查看完整正文和原生 Token 指标。排队消息排列在目标条上方，共用与输入框相接的附属背景，不显示为分离的大卡片。不按消息内容推算进度，也不显示不存在的完成百分比。

输入框左下角菜单和 `/` 菜单均提供「目标」。选择后在正文开头显示一个「目标」行内标签，颜色、字号、图标尺寸和基线与 Skill 一致，目标图案保持不变；不再占用底栏按钮。正文和 Skill 可继续编辑，提示为「描述你的目标，定义可衡量的成果，以获得最佳效果」；也识别位于正文开头且有词边界的 `/goal` 命令。目标标签不属于正文，不占正文或 Skill 的位置，也不写入提交的目标文字；每份草稿只有一个固定前缀。可用 Backspace、Delete 或包含标签的选区删除取消本次目标模式，正文、未选中的 Skill 和图片保留，不清除服务器目标；点击标签仅放置光标，不取消模式。全选替换会移除所选标签，删除后继续输入不会自动恢复。模式随会话或新建项目草稿保存，切换草稿、恢复旧输入及取消队列编辑后重新显示对应前缀。空目标不能发送，纯图片目标可提交；创建入口不设置 Token 预算。已有未完成目标时从目标栏编辑，不允许通过输入框覆盖；只读、消息或队列编辑、删除、压缩期间禁止创建。后端未声明 `goalComposer` 能力时保留草稿并提示更新，不将目标降为普通消息。

已有会话通过专用 `setGoal` 操作创建目标，不发送普通消息或排队；所选 Skill 按正文原位置序列化为 `[$name](path)`，图片顺序保持不变。目标标签只属于编辑框，发送后的消息和重新读取的历史沿用原有渲染，不添加目标标签。新会话先发送原生 `/goal` 首条输入，仅在首轮明确接受后设置目标；会话、首条输入和目标结果分别保留在结构化回执中。已确认创建会话后，即使首条被拒绝或设置目标失败，后续都绑定该会话并只允许设置目标，不重新创建或重发首条。等待期间继续编辑的正文、Skill、图片和模式随新会话迁移，已切到其他会话时不抢选择或覆盖草稿。

成功回执仅清除本次仍未改变的草稿及目标模式；失败保留草稿。结果未知时保存原请求标识、阶段及目标草稿，提供只读回执查询和已创建会话入口，不凭相同目标文字推断成功，也不自动重试；用户在本机核对并显式解除后，才可在已创建会话重新设置目标。页面重载后恢复同一回执和草稿身份；原生权威删除该会话时清理对应目标恢复记录与待确认回执，不清理其他会话的新草稿。目标图片在恢复快照中引用本次请求的图片序号，避免把同一 Base64 图片重复存储。

已明确失败或已人工核对解除锁定的目标恢复提示可点击「不再恢复」，只删除对应本地恢复记录，不清除当前正文、Skill、图片或服务器目标；未经核对的未知结果不提供该入口，仍保留回执锁定。

目标栏只展示尚未完成的当前目标。收到完成状态或目标清除通知后立即移除目标卡并停止计时；刷新页面、切换会话后也不会从已完成目标记录恢复该卡片。原生目标历史不删除，上方排队消息和输入草稿保持不变。仍需核对的编辑回执保留独立恢复入口，不恢复已完成目标卡。

运行中的目标沿用原生累计时间与 `updatedAt`，每秒更新目标条和详情中的运行时间；暂停、阻塞和受限目标显示原生累计值，不继续递增。计时只更新文字，不改写用量数据、不重建目标卡或编辑框，也不增加每秒接口请求。隐藏页面、离开页面或断开连接时停止定时更新，恢复后按最后已知目标状态继续显示，并由现有会话读取和目标通知校准；缺少有效时间字段时不补造计时起点。

目标条右侧的编辑按钮打开独立弹窗，提供同尺寸的还原、取消和保存按钮；当前预算只读。弹窗只保留一个必要滚动区域，字节计数放在编辑框内右下角，保留 16 KiB 限制，不显示「刚刚更新」。关闭、Escape 或点击遮罩取消未保存草稿，但不解除未知回执锁定。保存前核对原生目标身份、正文及状态，不改用量计数、不把已暂停目标自动恢复为运行中。只读、离线、已完成目标和待确认回执限制保存；实时用量通知不会重建正在编辑的输入节点或清空草稿。

编辑及回执处理保持用户原来的目标卡展开状态：紧凑目标条编辑保存后仍然紧凑，原先主动展开的目标仍保持展开，可点击目标标题收起。提交、失败或回执待确认不会强制展开正文；待确认结果仍通过编辑入口核对，不解除重复提交锁定。

并发刷新只接纳当前会话最近发起的有效读取响应。读取期间收到的 Token 通知不会被该读取的旧快照覆盖；首次读取尚未完成时也会暂存通知。用量降低同样生效，不按数值大小判断新旧。菜单随窗口和视觉视口尺寸变化重新限制高度；尚未选定会话或进入新建流程时，输入框保持禁用。

### 选择 Skill

在输入框词首或空白后输入 `/`，按名称、显示名或描述检索当前会话项目中的可用 Skill。方向键切换，Enter 或 Tab 选择；选中后以蓝色小图标和名称嵌在正文编辑流中，不使用独立标签栏。支持按光标位置插入、换行、Backspace/Delete 删除及纯文本粘贴。普通 URL 和完整文件路径不会触发菜单，中文输入法组词时不拦截按键。正文和所选 Skill 分别保留在当前页面的会话草稿中，切换会话后恢复。

新会话按照所选本机项目或原生无项目工作目录读取 Skill，不接受网页传入任意目录。发送时同时提交 `$skill-name` 文本标记和原生 `{ type: "skill", name, path }` 输入项，继续通过桌面原有发送队列或创建流程执行。每次发送前重新检查该工作目录的 Skill 名称、路径及启用状态；已停用、跨项目或任意路径不允许提交。一次最多选择 16 项，发送期间编辑的新草稿不会被旧回执清空。

Skill 标记按编辑框中的原始位置与正文交错生成，保留「文字 → Skill」「Skill → 文字」及多个 Skill 的先后顺序，不再统一前置。先按未裁剪正文的位置合并，再处理首尾空白；仅在标记与相邻非空白内容之间补充分隔空格。显式插入的 Skill 不会因正文已有同名 `$skill-name` 而消失。发送前重新读取编辑器中的实际位置，发送后仅移动 Skill 或修改空白的新草稿也不会被旧回执清空；位置快照仅保留在当前页面内存，不改变原生 Skill 请求结构。

发送后的用户消息和重新读取的历史消息使用与编辑器相同的 Skill 图标、蓝色文字和显示名，并在原文位置展示。优先识别消息中的原生 Skill 身份及明确指向本地 `SKILL.md` 的链接；只有纯 `$skill-name` 的旧消息，按当前会话目录中唯一且名称完全匹配的 Skill 补全显示。目录异步读取并与选择菜单共享，不阻塞历史展示；无法确定身份时保留原文。目录迟到或显示名更新会刷新对应用户消息，切换会话后不使用旧目录。

行内代码、代码块、普通链接、转义标记、`$HOME` 等全大写变量以及助手消息保持原样。消息复制继续返回含原始 Skill 标记或链接的文字，显示变化不改写发送数据。图标在 Markdown 净化后由固定界面组件构建，不放宽正文中的 HTML 或 SVG 权限。

连续输入会复用同一范围的在途 Skill 查询；光标移出 slash 单词、失去焦点或进入中文组词时关闭菜单，组词结束后才检索。迟到响应不会重新打开已关闭的菜单，旧会话或旧项目的响应也不覆盖新范围。

新建草稿按项目分别保存正文和 Skill，切换项目时恢复对应草稿。项目切换使旧创建请求失去当前页面的操作权，但不取消已经提交的创建任务。成功或部分创建失败后，仍处于原创建页面时将未提交草稿移入新会话；途中编辑不会被原始正文覆盖。切到其它项目后，旧回执不会切换当前页面。回执仍保存完整提交参数，不再重复保存未使用的草稿副本。

2. 打开管理工具的「远程会话」页面。远程网页可先启用；手动点击「启动公网」前，需确认 Codex 主界面完全打开、能够正常查看会话，且管理器确认桌面已连接。尚未启动或需要重新注入时，使用管理器右上角「重启 Codex」并等待完成。桌面未就绪时按钮禁用并显示操作步骤；下载 zrok 和邮箱注册仍可提前完成。未设置访问密钥时网页只显示登录页，任何设备都无法进入会话。同一行左侧「生成」只将随机密钥填入输入框，也可手动输入 8–64 个非空格 ASCII 字符；右侧「保存」才使密钥生效，无需重启服务。生成草稿不撤销已授权设备。保存后明文及校验摘要保存在本机，刷新后仍可回显，默认使用圆点遮挡；旧版只保存摘要的密钥需要重新输入并保存后才能回显。请妥善保管，仍建议使用随机长密钥。
3. 打开「远程会话网页」栏目右上角开关即保存并生效，无需点击「保存并应用」。后台已连接时立即启停；若启动时所有增强和模型代理都关闭、尚无后台，首次开启后需重启 launcher。启用后不要求开启其他增强或模型代理。
4. 确认保存成功；公网连接使用下方的 zrok。首次使用先点击「下载程序」；输入邮箱时按钮变为「注册公网」，发送注册邮件；取得 token 后粘贴到输入框，并在同一行填写固定公网名称，按钮变为「启动公网」。
5. 在手机打开访问地址，粘贴或输入访问密钥后点击「连接」，也可按回车提交。输入框右侧可切换密钥显隐；无需填写设备名称或生成一次性配对码。
6. 不再使用某台设备时，点击设备旁的「撤销」，或在网页点击「退出」。

电脑必须保持开机，CodexElves launcher 和 Codex 桌面应用必须保持运行。此功能不负责唤醒电脑或设置 Windows 开机任务。

公网首页可访问不代表 Codex 桌面已经就绪。桌面尚未连接或正在重启时，远程会话页持续展示操作提示：在电脑端点击「重启 Codex」，等待主界面完全打开、能够正常查看会话后，再刷新远程网页。既有固定公网仍按原配置自动恢复；公网已连通但桌面未连接时，管理器显示「等待 Codex 就绪」。桥接恢复后，launcher 会将同一组端口对应的 `running_degraded` 更新为 `running`；远程读取也会对 `running_degraded` 实际探测桌面，避免过期状态持续阻断已恢复的会话。

### 密钥登录交互

登录页沿用网页主题，提供访问密钥标签、折叠获取说明与外观设置。空输入不允许连接；支持 8–256 个非空格 ASCII 字符，粘贴时忽略首尾空白，拒绝内部换行，超过 256 位不会静默截断。长度及字符格式不符合要求时，在输入框下明确提示要求并聚焦输入框，不发送验证请求。

连接时显示验证和加载进度，锁定重复提交并重新隐藏密钥。密钥错误、尝试过多及服务不可用分别显示服务端原因；网络异常或超过 20 秒未完成验证/会话连接时提供重试提示，不自动重发。密钥已验证但会话加载失败时，可直接「重新加载会话」，不重复验证或要求再次输入；授权未生效时才重新输入。成功验证后清空明文，不写入 URL、Local Storage 或 Session Storage。

同一访问密钥连续验证错误超过 3 次，即第 4 次错误时，后端立即锁定该密钥的所有新登录，返回 `423`；前 3 次错误返回 `401`，仍可重试。在第 4 次错误之前正确登录会清零连续失败次数。锁定状态由后端持久化，刷新网页、更换 IP、等待或重启服务均不会解除；已登录设备仍保留授权。只有在本机管理器生成不同的新密钥并成功保存后才能解锁，同时撤销原有设备授权。只点击「生成」或重复保存同一密钥均不解锁。

登录页初始化读取匿名只读接口 `GET /api/login-status` 的 `{ ok: true, loginLocked: boolean }`。已锁定时禁用密钥输入和连接，回车或修改输入不能绕过，并提示「访问密钥连续输错超过3次，登录已锁定。请在本机管理器重新生成并保存密钥后再登录。」锁定页可见时约每 5 秒核对一次状态，隐藏或离开登录页时停止；每次查询最长等待 10 秒，网络错误不会自行解锁。后端确认已解锁后，网页清空旧输入并恢复输入新密钥，不自动提交。旧服务未提供此接口而返回 `404` 时，仍可沿用原有登录流程；实际登录始终由后端校验。管理器也展示后端锁定状态，生成候选密钥后仍明确提示保存。

手机保持相同布局，输入框至少 16px，显隐和连接按钮可触控；首次打开不自动唤起键盘。短屏和键盘挤压可滚动查看帮助与按钮。

2026-10-15 隔离验收：使用虚拟密钥与不转发真实接口的 fixture，在应用内浏览器验证输入边界、粘贴、显隐、重复回车、401/429/503、断网、20 秒超时、加载失败恢复、授权失效、正常连接及退出。非法输入的认证请求数为 0；连续三次回车仅增加 1 次请求；已验证后的重新加载未增加认证请求。检查了 1280×900、390×844、390×520、320×480 视口，以及浅色/深色和 20px 字号，未出现横向溢出。Chrome 扩展当时不可用；这些是隔离模拟及视口验收，不是公网、实体手机键盘或真实授权的端到端验证，正式 `45222` 服务未替换。

### 网络配置

默认配置为**关闭**，监听 `127.0.0.1:45222`，仅可从本机访问。它不占用模型代理的默认端口 `45221`，也不扩大现有局域网代理的会话管理权限。

手机通过 **zrok 固定公网地址**连接。CodexElves 自动准备并校验受管 `zrok2`，绑定后使用 `https://<固定公网名称>.shares.zrok.io`；固定名称会保存并在后续启动时复用，不再为每次运行申请随机地址。

远程会话网页仅允许监听本机回环地址，不提供局域网明文直连或自定义 HTTPS 证书入口，也不会配置路由器端口映射或修改防火墙规则。zrok 只转发到该回环地址，访问密钥不会写入公网链接。

### zrok 固定公网配置

1. 启用「远程会话网页」；可在启用前后设置并保存网页访问密钥。zrok 仅转发到回环地址上的本机 HTTP 服务，未设置密钥时仍无法进入任何会话。
2. 首次使用时，「公网入口 · zrok」右侧按钮显示「下载程序」。CodexElves 下载固定版本的 Windows x64 官方 `zrok2`，校验下载地址、文件大小、SHA-256 和程序版本；若 `PATH` 中已有校验通过的相同程序则直接复用。
3. 下载完成且输入为空时，「启动公网」保持置灰。输入邮箱后按钮变为「注册公网」；点击后由 CodexElves 请求 zrok 发送注册邮件。按邮件完成注册并取得 token 后，将 token 粘贴到原输入框。
4. 输入 token 后，同一行显示第二个输入框。填写 3–63 位固定公网名称，只能使用小写字母、数字和连字符，且首尾必须是字母或数字；点击「启动公网」后完成 zrok 环境绑定、预留固定名称并启动公网转发。邮箱或 token 只有在点击右侧按钮后才写入本机 CodexElves 设置；最后一次提交的值会在后续打开页面时回显。
5. 地址显示后，后台自动确认公网首页返回 CodexElves 页面且未登录的 `/api/session` 返回 401；验证通过才显示「可访问」。失败时保留固定地址并自动重试，也可点击「测试访问」立即检查。
6. 手机关闭 Wi-Fi、使用蜂窝网络打开固定地址并输入网页访问密钥。zrok 免费服务首次访问可能显示提示页，点击「Visit Share」后进入登录页。

固定公网名称写入 CodexElves 状态目录的 `remote-access-zrok.json`，zrok 绑定信息由 zrok 自身保存。后续启动时，只要「远程会话网页」仍启用、zrok 已绑定且固定名称有效，程序会自动启动同一固定地址，无需再次输入 token。

点击「启动公网」时，后台先重新确认本机 zrok 环境。已启用的环境直接复用，不会因为旧缓存显示未绑定而再次执行 `enable`；后台旧检查也不能覆盖本次确认结果。若其他进程在检查后完成绑定，程序收到「已有启用环境」时会再次核对，确认已启用后自动继续，不要求用户手工执行 `disable`。状态读取失败、token 错误和其他启动错误仍明确报告，可再次点击重试；不会自动解绑、删除环境或切换账号。

zrok 没有独立启停开关，跟随「远程会话网页」启停。关闭该开关会立即停止 zrok；退出负责启动远程后台的 CodexElves 进程时，Windows Job Object 会同时回收远程网页后台和 zrok。关闭管理器窗口只会最小化到托盘，需要从托盘退出才算退出程序。

不再保留主管理器心跳、3 小时超时或程序退出后继续运行公网服务的逻辑。网络短暂中断或 zrok 异常退出时，当前运行期内会按状态自动重试；固定名称不变，因此不会因重启 CodexElves 频繁申请新的公网地址。

独立后台使用文件锁保证每个用户状态目录只有一个实例。本机管理接口仅监听 `127.0.0.1` 的随机端口，校验本机令牌并拒绝携带 `Origin` 的浏览器请求；不通过 zrok 暴露。`remote-access-service.json` 保存进程、端口及管理令牌，不应对外分享。

公网 TLS 由 zrok 服务终止，再通过隧道回源到本机 HTTP 服务。CodexElves 只信任当前固定名称对应的精确 Origin，不接受 `shares.zrok.io` 通配信任；固定名称变化后会撤销旧地址下的设备授权。本机 HTTP 登录不会因为公网入口存在而错误设置 `Secure` Cookie，公网登录限速使用经过入口校验的转发客户端 IP。

远程网页事件通道使用同源 WebSocket；多个标签页在浏览器支持 SharedWorker 时共用一条连接，断线后指数退避重连。旧 SSE 路由仅保留兼容，不作为 zrok 实时通道。固定名称表示地址可复用，不代表 zrok 免费服务提供生产级可用性承诺。

## 设置与安全

| 设置 | 行为 |
| --- | --- |
| 启用远程会话网页 | 默认关闭，切换开关后立即保存并启停 |
| 监听 IP、独立端口 | 端口范围 1–65535；端口占用会显示错误，不影响模型代理 |
| zrok 固定公网 | 没有独立开关；远程网页启用且绑定完成后自动启动，复用已保存的固定名称 |
| 远程后台生命周期 | 跟随启动它的 CodexElves 进程；程序退出时回收远程网页和 zrok，不使用心跳或 3 小时延迟退出 |
| 受管 zrok2 | 固定版本下载，校验官方 HTTPS 来源、大小、SHA-256 和程序版本 |
| 注册与启动 | 邮箱对应「注册公网」；token 加固定公网名称对应「启动公网」；已绑定后可直接复用 |
| 测试访问 | 验证公网 HTTPS 首页 200 及未登录接口 401；测试不改变当前地址 |
| 访问密钥 | 长期有效，生成与保存独立，使用同一个输入框；成功保存不同的新密钥后旧设备授权失效，并解除登录锁定 |
| 设备授权有效期 | 默认关闭（0），开启后可设 1–720 小时，仅对新登录设备生效 |
| 远程审批及回答询问 | 默认允许，管理页不提供单独开关；历史配置的后端权限仍保留 |

访问密钥以明文和加盐 PBKDF2-HMAC-SHA256（600,000 次）摘要共同保存在本机 `remote-access-key.json`；摘要用于登录校验，明文用于管理页回显。输入框默认使用圆点遮挡，点击小眼睛可查看明文，点击复制可复制当前密钥。旧版本只保存摘要的密钥无法恢复明文，需要重新输入并保存一次。密钥验证有来源限速及并发上限。网页登录后使用随机设备令牌，保存在 HttpOnly、SameSite=Strict cookie 中，zrok 公网连接要求 Secure；磁盘仅保存设备令牌哈希。网页不将访问密钥写入 URL、localStorage 或 sessionStorage。请勿向不可信的人透露密钥。

密钥在隧道和网页服务重启后继续有效，设备授权则遵守有效期。更换密钥使所有旧 cookie 失效，包括服务重启后从磁盘恢复的旧设备；不取消已经提交到 Codex 的任务。撤销单台设备会使其当前授权失效，但知道长期密钥的人仍可再次登录；要阻止再次登录，必须同时更换密钥。

有交互和审批权限的设备可以通过 Codex 操作本机项目，应当像对待桌面账号一样保护它。撤销和到期会停止该设备的数据流，并拒绝后续操作。

服务检查 Host、Origin 和跨站请求，Markdown 不执行 HTML 或 `javascript:` 链接。审批使用原始 request ID（包括数值 `0`），核对所属会话和请求类型；已结束请求不会继续放行。

命令审批只展示和提交原生请求允许的决定；网络审批显示协议、目标主机和端口。询问答案只接受文本，MCP 外部登录等 URL 询问不能通过远程 API 回答，需回到桌面处理。

访问密钥明文及哈希、授权设备及消息回执保存在 CodexElves 状态目录下的 `remote-access-key.json`、`remote-access-devices.json` 和 `remote-access-receipts.json`。这些文件尚未生成时不影响远程网页、公网入口或其他 CodexElves 功能启动；没有访问密钥时所有登录和设备授权都会被拒绝。升级后会清理旧 Quick Tunnel 的配置、冷却记录和受管程序目录；旧版 Named Tunnel 凭据 `remote-access-secrets/cloudflare-tunnel.json` 仍不再使用，可手动删除。损坏的授权文件会使远程服务拒绝启动，但不会使原有模型代理启动失败。

管理器已移除只读访问选项；旧配置中的 `readOnly=true` 仍遵守原有权限，不因 UI 调整自动扩大已有设备权限。密钥栏目不再列出本机地址；固定公网地址在 zrok 栏目中查看及复制。旧 `funnelEnabled`、`cloudflareTunnelEnabled` 和 Quick Tunnel 配置不会控制 zrok，也不会自动完成 zrok 绑定。

## 断线与消息回执

消息提交前保存客户端请求 ID 与回执。同一设备重复提交相同 ID 和内容不会重复发送；同一 ID 携带不同内容会被拒绝。

回执的「完成」指提交动作完成，不代表模型已经生成完毕。网页断线不会终止桌面任务，重新连接后从原生历史恢复。

若发送回执丢失、原生客户端报告结果未知，或服务在提交中重启，网页会锁定重复发送并查询回执。它不会自动重发。请先检查会话，再通过「已人工确认」解除锁定；不要仅因为没有看到回复就再次提交。

已登录设备在桌面暂时离线时保持自动重连，不退回密钥输入页。损坏或属于旧设备授权的浏览器回执会锁定发送并提示人工核对，不会因解析失败白屏，也不会自动丢弃记录后重发。迟到的旧回执和旧授权请求不能解除新消息的锁定或恢复已经退出的页面状态。

## 排队反馈与冗余传输修复（2026-10-15）

### RCA 结论

- 状态：代码瓶颈已复现并修复；实际手机公网链路的归因仍为部分确认。
- 现象：原生已接受排队消息，网页没有立即显示，发送按钮还持续锁定。
- 直接原因：`sendMessage()` 未消费成功回执中的 `queuedMessages`，转而等待 `reloadThread()`；发送锁还要等该流程下载完整历史、更新侧边栏后才释放。
- 根因：独立的队列状态变更被绑定到会话历史的完整刷新流程；已有可靠回执没有作为即时显示的数据源。
- 系统性原因：队列沿用轮次/历史刷新机制，适配器未订阅原生 `thread/queue/changed` 生命周期，其他入口的队列变化也缺少独立同步通道。
- 关键链路：已确认入队 → 忽略回执快照 → 追加会话读取 → 追加历史下载 → 解锁。上述延迟会叠加在实际网络耗时上。

### 修复与防复发

1. 直接使用已确认的队列回执显示内容、清理对应草稿并解锁；排队成功不再主动读取完整历史或侧边栏。未知结果和失败不会伪造入队状态。
2. `pending` 回执恢复走同一即时更新路径；原生队列事件可直接携带新鲜快照，无快照时只补读 `/api/read/queue`。
3. 原生适配器版本升至 `13`，队列快照只通过 `serverQueue.load` 获取，不读取会话历史。新读取入口沿用鉴权，并仅接受合法的 `threadId`。
4. 队列版本保护在途会话读取、轻量读取及编辑/删除回执，防止旧响应覆盖新队列；切换会话后的旧回执不会写入其他会话。

## 队列消息回到主输入框编辑（2026-10-15）

队列编辑不再打开独立弹窗。点击「编辑消息」后，先通过原生队列服务取出该项，再把文字和图片放回主输入框；编辑期间原消息不在待执行队列中。输入框显示「编辑排队消息」和取消入口，原发送按钮变为保存按钮。保存或取消后恢复编辑前的普通草稿、图片、Skill 选择和模型设置；原队列项的 Skill、权限及其他上下文由原生恢复令牌保留。

这次实现替代此前单次 `thread/queue/update` 的网页编辑流程。已核对安装版 Codex `26.1007.9446.0` 的 `Ero`、`elt.handleEditMessage`、`removeQueuedMessage` 与 `restoreQueuedMessage`：原生编辑采用真实取出、重新入队及重排，不是仅在网页隐藏，也不保证队列项 ID 不变。适配器版本升至 `15`，新增 `beginQueuedEdit`、`cancelQueuedEdit`，并为 `editQueued` 增加基于 `editId` 的保存契约；旧单次更新参数仍兼容。恢复位置采用原生令牌中的前后邻居及索引，不把修改后的消息简单追加到队尾，也不在整个编辑期间暂停其他队列项。

- 三阶段请求均使用可靠回执。开始失败不覆盖原草稿；保存或取消失败保留编辑状态；结果待确认时禁用重复提交，不以重新发送普通消息代替保存。
- 编辑记录按会话保存到浏览器会话存储。切换会话和刷新后可继续编辑；其他会话的输入框不会被迟到回执覆盖。开始状态尚未写入回执就中断时，可用同一 `editId` 重新核对取回。
- `queue`、`thread` 和队列事件提供精简 `queuedEdits` 摘要；关闭标签后重新打开会话，可以通过「继续编辑」找回原始排队消息。摘要不包含原生恢复令牌、附件内容或权限上下文。
- 原生桥按 `editId` 防止重复取出、重复恢复及并发冲突。终态重试返回最终结果，不重新进入编辑；结果未知时不重复入队。注入桥重新加载会保留活动令牌。

## Funnel 连接延迟与重连排查（2026-10-15）

### RCA 结论

- 状态：**部分确认**。已确认公网 Funnel 路径明显慢于本机路径，并复现、修复客户端在慢状态请求下的重复重连和状态回退。没有取得真实手机发生断线时的完整网络记录，不能断言已经找到或消除了全部公网断线原因。
- 现象：用户通过 Funnel 访问时频繁看到断开重连，连接等待较长。
- 直接原因：`reconnectStream()` 在等待 `/api/session` 前清空了重试定时器标记；等待期间 `ensureStream()` 可再启动一次重连，两个响应各自建立事件流，后一个关闭前一个刚建立的流。原生连接事件没有同步更新 session 状态，迟到的状态响应还可能覆盖较新的连接事件；`remote/resync` 也被错误地当作本机健康确认。
- 根因：重连定时、状态探测与事件流创建缺少统一的并发约束；HTTP 状态快照和原生连接事件没有版本保护。
- 系统性原因：初始化、重连和轮询各自发起状态读取，缺少合并与只读超时；会话刷新串行等待侧栏。公开静态资源始终 `no-store`、不压缩，会进一步放大慢公网链路的传输成本。
- 关键因果链：慢 session 请求 → 重连期间再触发检查 → 并发探测 → 重复替换事件流；另外，旧状态回包或仅要求补读的 resync → 错误翻转连接显示。

### 修复与防复发

1. 重连定时器直接建立事件流，不再先等待一次 session 网络往返；流建立后，并行探测状态和刷新数据。旧流的回调、迟到响应及已经停止的轮询不能覆盖当前连接。
2. session 探测合并在途请求，轮询增加防重入和代次校验。session/回执只读请求有 15 秒上界，会话数据读取有 60 秒上界，为原生 45 秒执行期限及慢回程留余量。只读挂起不会永久占住请求槽；动作请求没有新增超时或自动重试。
3. `remote/disconnected`、`remote/reconnected` 更新原生可用状态及版本；旧 HTTP 状态不能覆盖更新的事件。`remote/resync` 只触发重新读取，不再直接宣告连接成功。首次事件流尚未就绪时显示「连接中」，不提前显示已连接。
4. 侧栏与选中会话/地址栏指定会话并行读取。最新消息无需等待侧栏完整返回。
5. 9 个公开 HTML/CSS/JS 静态资源按 `Accept-Encoding` 协商 gzip，尊重 `gzip;q=0`，返回 `Vary: Accept-Encoding`；原始与 gzip 表示分别使用 SHA-256 ETag，条件请求命中返回 304，缓存策略为 `no-cache`。压缩结果首次生成后复用，避免每次消耗 CPU。API、图片、鉴权及 SSE 继续 `no-store`，不压缩。依赖只把锁文件中已有的 `flate2 1.1.9` 加为直接依赖，未更新其他版本。

## 排队发送回执自动核对（2026-10-16）

加入队列或网络回执为 `pending` / `unknown` 时，网页按原请求的客户端消息 ID 核对原生队列和已经接收的用户消息，不按正文相同猜测送达，也不重新发送。适配器 29 的只读 `sendState` 接口只接受 `threadId` 和 `clientUserMessageId`；确认存在同一 ID 的原生排队记录、服务端队列记录或已接收用户消息后，网页自动解除该次发送锁定。原生加入队列后发生后续校验或同步异常时，也先执行这一步核对，已有明确接收证据则返回成功。

新服务通过 `queueSendRecovery` 能力启用网页生成的稳定客户端消息 ID，用于回执丢失后的只读核对；旧服务仍可利用回执返回的客户端 ID，从现有队列和最新会话历史中核对。仅有本地占位消息、尚未接受的引导、上下文压缩投影或同文异 ID 消息均不能解除锁定。没有可靠身份或暂时查不到记录时继续保留草稿和防重复发送限制；旧队列编辑标记不随普通发送的确认而被删除。

回执完成态沿用服务端的 `completed`，异步问答回复也使用这一状态，不使用额外的 `done` 状态。

### 命令审批双向状态同步（适配器 38，2026-10-17）

命令审批、文件审批和阻塞式询问以原生会话的待处理请求集合为准。桌面处理后，适配器从会话状态回调推送带会话 ID、`requestsEpoch` 和单调递增 `requestsRevision` 的独立快照；空快照立即移除网页对应审批卡片，不等待整段历史读取。原生完成回调先于请求移除时，适配器在 microtask 中补读最终状态。尚未取得可靠 requests 数组时标记 `requestsKnown: false`，不把未知集合当作审批全部结束。异步问题仍使用原有独立同步通道。

网页选择继续调用原生审批入口，并应用返回的权威快照；原生 follower 仍保留请求时，网页保留待处理卡和重复操作锁定。请求处理中或结果未知时只允许核对状态，不自动重发；明确失败保留待处理卡。迟到的旧读取、旧版本或已退休适配器 epoch 不能恢复已结束的审批。旧服务缺少版本化快照时，通过读取期间的事件屏障和准确请求 ID 防止旧状态回流；读取成功或失败都会补排已合并的一次刷新，且不依赖历史读取结束。

适配器转发 `serverRequest/resolved` 时附加自身 `requestsEpoch`。网页已有版本化集合后，只有匹配当前来源的完成事件才能按请求 ID 立即移除；已退休来源的事件直接忽略，缺少来源或来源尚不匹配时只安排只读核对，避免旧适配器的迟到事件误清新来源复用 ID 的审批。完全无 epoch 的旧服务保留原有按准确 ID 结束的兼容路径。

同一请求的表单在审批区更新时复用原 DOM，提交中、失败或另一审批结束不会清空已填写内容，也不把答案或秘密持久化。已确认的来源 epoch 更替会使旧操作锁、迟到回执和旧确认失效；首次获知同一来源的 epoch 时保留实际在途操作的锁定。

本修改为源码修复，需要更新运行程序才能启用适配器 38；只刷新网页不会升级已运行的原生适配器。隔离验证不涉及真实审批、真实会话写入、安装、部署或重启。
