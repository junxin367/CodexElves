## Codex 执行方式

远程 Codex 实例仅使用服务模式，设置中不再提供运行模式切换。所有会话读写由常驻服务管理；服务持有者使用 app-server，已有桌面持有者通过原生 IPC 协作。旧设备的 CDP 选择不再生效，失败不自动切换通道或重发。Codex App 本地界面增强仍独立保留。详细边界见 [服务模式说明](remote-service-mode.md)。

## Claude / WSL2 会话

默认仅启用本机 Codex；在「设置 → 会话实例」中按检测到的本机 / WSL 实例分别启用。当前暂停本机 Claude 的安装检测，WSL Claude 仍按统一规则检测和接入，已保存的实例偏好保留。新建页在项目当前分支右侧选择已启用且接入就绪的实例；关闭不会停止原生任务，也不会切换已有会话的环境。选择 WSL Claude 后继续使用同一份项目列表和原项目 ID；Windows 服务核对项目身份后，将同一目录映射到所选 WSL，拒绝使用其他发行版中的项目。没有项目时创建独立空工作目录。创建完成后类型与实例固定，后台拒绝通过参数改投其他实例。

类型图标随对应文字字号缩放；最近、项目和置顶列表中的 Codex 与 Claude 会话均在标题前显示对应品牌图标，两类图标与文字居中对齐、间隔 3px，最近列表的项目名不预留图标列。实例菜单与项目菜单共用行高、间距、圆角和展开背景，以 200px 为最小宽度，随内容自适应并限制在视口内。实例名称不拼接“本机”“WSL”标签，本机仅显示类型名，其他实例保留实际发行版，例如“Codex”“Claude · Ubuntu”；Claude 不附加 Linux 用户名。设置、新建、自定义指令及历史实例使用同一命名规则；已有会话路径继续显示实际 WSL 发行版名称。

Claude 会话进入最近列表和所属项目列表，标题前显示 Claude 图标，支持现有搜索、排序和置顶。从列表移除 Claude 会话保留原生 Claude 历史及项目文件，确认框会说明这一点。网页与 Android 共用这套页面，不向 Codex 桌面原生列表伪造 Claude 会话。

新建 Claude 会话使用原版 CLI 的后台会话，网页保持现有消息、Markdown、工具卡片和执行状态展示，页头展示对应品牌与实际 WSL 路径。在该环境的电脑终端可用原版 `claude attach <id>` 连接同一个原生会话。网页发出的消息、执行过程和回复可在 CLI 查看，CLI 发起的消息和执行结果也会自动更新到网页。

启用 Claude 后，加载列表会只读发现指定 WSL 用户的原生 JSONL 和后台任务，不依赖旧网页登记文件或 `sessions-index.json`，也不启动模型来探测会话。原生 UUID 与环境参与去重，已有网页 ID、手动标题、项目选择、置顶、已读和删除状态保留。早期 print 登记在没有执行连接时接入完整原生历史；已打开的发现会话在首次网页发送前也会同步 CLI 后续内容，首次网页发送继续使用原 UUID。匹配现有项目根目录的原生会话归入同一个 Codex 项目；没有匹配项目的只进入最近列表。

列表请求通过 `enabledInstanceIds` 选择具体实例，只扫描并合并其中的 Claude 环境；空数组表示全部关闭。旧客户端的 `includeClaude: true` 只启用原默认 Claude 实例；未传两者时保持 Codex 列表，不启动 WSL 发现连接。

网页只有明确确认当前会话执行中时才把普通消息保存在持久化待发送队列；空闲、状态未知或仅有旧队列残留时直接发送。尚未投递的消息支持逐条引导、编辑、删除和排序；点击某一条“引导”只将该条投递到当前同一个原生 Claude 会话，其余消息继续等待。投递前原版 CLI 看不到这些远程待发送消息，投递后双方继续共享上下文和执行。已有队列在原生确认空闲、没有权限或问答等待时，按当前顺序一次投递一条；停止生成会暂停队列，之后显式发送新消息或引导队列可恢复。原版 CLI 继续使用自己的原生输入和队列，不接管其未发送草稿，不新增控制权租约；唯一的跨客户端互斥是网页编辑历史，同一原生会话同时只允许一个网页编辑。

引导使用原生 `reply(nextTurn: true)`，对应 CLI 的 `priority: "next"`：当前工具调用完成后吸收该消息，若本轮已经结束则作为下一轮处理。引导前后都不发送 Esc、不等待旧轮停止，也不把旧轮次标为“已停止”；只有明确的停止或审批操作使用原生交互按键。已有审批继续由 CLI 处理，引导不替用户批准或拒绝。只逐条释放选中的网页队列消息，其余消息继续保留编辑、排序和删除能力。已经交给原生的消息显示“已发送”，不能再编辑或重排；原生接收记录确认后进入正文。消息投递前保存派发意图，结果未知时保留待核对状态，不自动重发；自动续发也会再次检查原设备授权和当前访问策略。原生同轮吸收的实测见[Claude 原生引导验收](validation/claude-native-steering-20261113.md)。

Claude 原生模型切换确认复用网页审批区，显示目标模型、原生成本或 Hook 提示，以及“确认切换 / 保留原模型”。等待确认时显示等待状态，模型选择标记为“待确认”；原生实际生效后才更新会话模型。确认操作仅回答原弹窗，已收到的消息由同一个原生会话继续执行，不重发消息。提交前重新读取原生终端快照并核对会话和等待代次，已提交请求不重复处理。

本次适配覆盖 Claude Code 2.1.323 的完整编号模型/思考深度确认框；未识别或无编号的原生弹窗显示“Claude 正在等待本机确认”，需在该会话的原版 CLI 中处理。不会自动确认模型切换或绕过原生 Hook。原生拒绝可能不写入历史日志，因此同时核对明确拒绝后的弹窗关闭，以及后续实际请求使用的模型。验证记录见 [Claude 原生模型确认验收](validation/claude-model-confirmation-20261113.md)。

模型和思考深度采用当前 CLI 返回的能力；系统提示、CLAUDE.md、MCP、Skills、Hooks、认证与权限配置继续由原版 CLI 加载。网页新建后台会话使用仅该会话生效的 `worktree.bgIsolation: none`，使工具操作留在所选项目目录，不修改全局配置或跳过审批。模型能力读取、旧版会话和网页编辑历史时的结构化回退使用 print 协议；共享会话的消息、状态与工具结果从同一原生会话投影，流式正文预览在原生完整消息到达后按 Markdown 原文校正。

Claude 的模型和思考深度变更复用 Codex 的紧凑提示行。变更依据原生实际请求中的 `requestedModel`、`effort` 等元数据生成：首次使用新配置的请求对应到该条用户消息前，同一轮中途变更保留在对应请求前；首次出现或旧配置缺失时不猜造切换。原生 `/model`、`/effort` 控制记录及关联回显不作为聊天气泡，恢复时重复应用相同配置不产生新提示；用户手写或引用相同标签的内容继续保留。历史重进使用稳定事件身份，不因补回提示重置未读，也不修改原生 JSONL。

新建 Claude 会话前，网页通过只读 `projectTrust` 检查所选实例的目录信任。未信任时显示实例、真实目录及 Git 信任边界，由用户点击“信任并继续”；取消或切换项目保留草稿，不登记空会话、不发送首条。确认后仅更新该实例原生 `.claude.json` 中对应目录的 `hasTrustDialogAccepted`，复用原生配置锁并原子保存，保留账号和其他设置；不跳过工具审批。无项目会话对专用 `claude-workspaces` 目录确认一次。后端重新核对确认路径、当前设备及写入权限，未确认或路径变化时明确拒绝，不能视为送达未知。能力由 `claudeProjectTrust` 声明，需更新运行服务后使用。

模型目录按会话实例共用缓存，新建页、不同项目和历史会话读取同一份选项；每个会话的当前模型与思考深度独立保存。历史中单个已用模型只作展示，不写入完整目录缓存。目录尚未缓存时，浏览历史不启动 CLI，点击模型选择器才在该会话绑定的实例中初始化读取完整选项；读取不恢复历史任务或发送消息。完整目录已缓存时直接复用，读取失败保留已有目录并显示错误，重新打开菜单可重试。

Claude 目录中的别名与完整模型 ID 按原生 `resolvedModel` 对齐，页面选中状态、推理等级和后端提交校验使用相同规则。重选同一模型保留已选等级，切换模型不继承旧等级；精确模型值优先，只显示原生已报告的选项。

提示词优化是独立功能，Codex 与 Claude 实例均显示入口，沿用 CodexElves 桌面端的优化设置；已配置独立优化模型时优先使用该模型，不改变会话模型。优化不依赖会话执行引擎或实例额外声明能力，继续检查远程优化能力、设备授权和草稿写入状态。结果仅更新当前草稿，保留附件和 Skill，可取消或恢复原文；继续编辑、切换实例或授权后，迟到结果不能覆盖新的草稿。

上下文容量与用量统一沿用 Codex 的圆圈和单行弹层。容量优先采用读取到的模型窗口，缺失时使用同一会话的用户配置压缩窗口，不再额外扣减或乘以提前压缩比例。百分比统一按最后请求用量与所用容量计算并四舍五入，与 Codex 原有规则一致。Claude 不显示额外的容量来源、压缩窗口或触发比例说明；模型窗口与配置窗口都缺失时保留真实 Token，并使用共用的未知状态。读取复用已有报告与配置，不修改原生 CLI、statusline 或用户设置。

账号订阅登录的 Claude 实例在输入框下方现有空位右侧显示 `剩余 5h 76% · 7d 48%`，百分比按 `100 - 原生已用比例` 四舍五入；前缀与 `5h`、两个窗口的圆点两侧均为 5px 间距。额度行绝对定位，复用既有 20px 下边距，不增加输入框、工具栏、消息区或底部的间距。点击打开宽度为 300px 的“账号信息”，查看订阅等级、窗口剩余比例、重置时间及本地使用量和预测；等级缺失时隐藏标签，悬停或聚焦不展开，Escape 或点击外部关闭。

额度只通过会话所属 WSL、用户和原生 Claude 可执行文件的 `get_usage` 控制请求获取，初始化后不发送模型消息、不恢复后台任务；`skip_behaviors` 跳过历史行为扫描。专用读取进程不持久化会话，Hooks/MCP 的关闭参数仅作用于该读取进程，不修改用户设置、CLI 或 statusline。应用不读取 OAuth 凭据、不自行调用额度 HTTP 接口、不使用第三方额度服务，也不在原生能力缺失时绕过 Claude。原生 CLI 判定为 API Key、第三方提供方或额度不可用时隐藏该行；只读设备仅使用已有的新鲜缓存，不启动 CLI。

额度缓存按授权和实例隔离并合并并发读取，前台最多每分钟刷新一次。切换实例会话时，只要目标会话缓存或侧栏已明确实例身份，就直接展示目标实例的有效额度及详情缓存，不先隐藏再等会话详情；身份未确认时不借用旧会话或默认实例。进入后台、断开连接及离开页面会退役旧读取；断线期间仍可显示有效快照，迟到响应不能填到新实例。账号信息先显示缓存的使用量和预测，再后台更新；金额和 Token 分别保留原采集时间，单项缺失或暂时空响应不清除已有有效数据。缺失、非法、超过三分钟的旧快照或已到重置时间的窗口隐藏，不把未知额度显示为 0%，也不因重新缓存延长有效期。原生 `get_usage` 控制能力此前已用 Claude Code 2.1.322 核对；本次显示优化未重新执行实际 CLI 验证，旧版本不支持时保持隐藏。

图片继续使用现有缩略图与点击放大预览。原版通过文件引用接收网页图片后，连接端将原生图片附件并回同条用户消息；重新打开会话会补齐已经发送的图片，不需要再次上传或发送。

会话身份、历史投影、远程待发送队列和编辑状态保存在本机状态目录的 `remote-claude-sessions.json`。网页关闭不丢弃服务端队列，也不停止原版后台任务；连接服务恢复后先读取同一原生会话的新快照，再继续尚未投递的队列。已派发但结果未知的消息保持待核对，不能自动重发。后台适配使用本轮测试的 Claude Code 2.1.322 的本地后台协议 v1，需要 WSL 中有 Python 3；这些后台传输接口尚未公开承诺稳定，CLI 升级后需回归双向消息、排队、审批、停止和编辑交接。

网页编辑 Claude 历史消息采用交接方式（用户确认的 B 方案），不再用按键操作 `/rewind` 菜单。连接端先确认会话完全空闲：没有执行中的轮次、待确认弹窗、上下文压缩或后台命令/监控/后台子代理（原生底栏 `↓ to manage` 提示），也没有其他网页正在编辑同一会话。随后用原版 `claude stop` 停止同一后台会话，通过只作用于短进程的 print 协议发送 `rewind_conversation`，回退到所选消息之前，并以网页当前分支最后一条记录做已见校验；该进程不启动 MCP、不触发 Hook、不调用模型。回退成功后用 `claude respawn` 恢复同一后台会话，再发送修改后的消息。会话 UUID 与后台短 ID 不变，原生记录只追加回退标记，不改写或删除旧分支。已连接的原版终端会提示会话已退出，重新 `claude attach` 后显示编辑后的内容。原生明确拒绝时恢复原会话且不修改历史；回退答复丢失时同样恢复会话，保留待核对状态，不自动重发。原版终端自己用 `/rewind` 回退时不写记录标记，网页要等任一端发出下一条消息后，才能从分支关系显示结果；回退菜单打开期间的处理见下文。`rewind_conversation` 是未公开控制请求。验收见 [Claude 编辑交接验收](validation/claude-edit-handoff-20261113.md)。

首期隐藏 Claude 的 Codex 目标、子智能体菜单和侧边会话入口。原生工具调用仍可显示，不为 Claude 注入 Codex Skill 路径或替换系统提示。

Claude 工具调用按原生工具类型复用现有卡片，映射位于 `claude_tools.rs`。`Bash` 显示为命令卡片，退出码取自原生错误结果开头的 `Exit code N`；转入后台的命令在任务结束前不显示退出码。`Edit`、`MultiEdit`、`Write` 显示为已编辑文件，差异取自原生 `structuredPatch`；只有原生确认新建时才按新增文件展示全文，编辑失败时保留原生错误文本。`WebSearch` 显示为网页搜索，`mcp__服务__工具` 显示为 MCP 调用。`Read`、`Grep`、`Glob` 等读取类工具在工作摘要中归为「浏览了文件」；其他内置工具使用中文动作说明，例如「读取网页 · 域名」「创建定时任务」，未知工具保留原名。工具结果中的 base64 图片复用图片预览，`tool_reference` 显示为「已加载工具：名称」。连接端只转发渲染所需的结果元数据，补丁总长超过 1 MiB 时不转发，与网页「已编辑文件」上限一致。并行工具调用的每条结果挂在各自调用之下，原生父子链上只有最后一条处于当前分支；连接端会保留答复当前分支调用的其余结果，被回退分支上的结果仍不显示。

`TaskCreate`、`TaskUpdate`、`TodoWrite` 不单独成卡，而是合成会话计划清单，复用 Codex 的 `turn.plan` 展示。`TodoWrite` 整体替换清单；`TaskCreate` 按原生返回的编号追加；`TaskUpdate` 按编号更新状态或标题，或删除任务。清单跨轮次延续，编号与原生 `TaskList` 一致；调用失败时显示一张失败卡片。

后台命令、监控和后台子代理结束或发来事件时，原生写入 `<task-notification>`，Claude 随后自动继续回复。定时任务触发时，原生先写入 `system/scheduled_task_fire`，再写一条以它为父节点的提示（已实测一次性任务）。网页把这两类记录显示为事件行，例如「后台命令已完成 · Claude 自动继续」「监控收到事件」「监控已结束」「定时任务已触发」，并开启不可编辑的自动续跑轮次，不显示为用户消息，Claude 的回复归入该轮次。连续送达、尚未回复的多条通知并入同一轮次。对应命令卡片同步显示「后台已完成」或「后台失败」及退出码；会话进程退出时仍未结束的后台命令显示「后台结果未知」。原版底栏带 `↓ to manage` 时，输入框上方提示「后台任务运行中：1 个后台命令」等，内容取自底栏中「数字 + 类型」的片段；`← 2 agents`、`esc to interrupt` 等其他片段不计入，未知类型保留原文。

原版终端执行的本地斜杠命令显示为「终端执行了 /命令」事件行，新旧两种记录格式都支持。命令输出去掉终端颜色后放在事件详情中，最多 4000 字；`/model`、`/effort`、`/goal`、`/compact` 沿用各自的专用展示，`/context` 等命令附带的 `isMeta` 记录不显示。离开期间回顾、原生提示，以及阻止继续或执行出错的 Stop Hook 也显示为事件行。

计划模式下，Claude 调用 `ExitPlanMode` 后，原生先弹出计划审批框，对应记录稍后才写入。连接端按画面识别该审批框，即「Would you like to proceed?」及其编号选项。计划正文优先读取实例配置目录 `plans/` 下的计划文件（上限 64 KiB），读不到时使用画面文字。网页以 Markdown 显示计划，为每个原生批准选项各提供一个按钮，例如「批准并使用自动模式」「批准，编辑逐项确认」，悬停可见原生原文；另提供修改意见输入框。批准时发送对应编号。修改意见合并为单行（最多 4000 字），经原生「Tell Claude what to change」提交，Claude 修改计划后会重新弹出审批框。计划审批框优先于通用工具审批识别，网页的「允许」不会再按编号 `1` 误选「Yes, and use auto mode」。

在 Claude 开始输出前停止时，原生会撤回这条输入，把原文放回原版终端输入框，记录中不留标记。连接端同时满足以下条件时判定输入已撤回：会话空闲且在线；该消息之后没有回复或中断记录；终端输入框内容与原文开头一致。网页随即结束该轮次并显示「已撤回」，不再停在「等待开始」。之后网页发送的新消息正常送达；留在原版终端输入框里的原文，需要在终端中自行清除或发送。

原版终端打开 `/rewind` 回退菜单时，原生状态为等待中（`dialog open`），记录中不写任何内容。这时网页发送的消息会被原生接收并放进原生队列，但菜单关闭前不会执行。终端按 Esc 取消后，这些消息在原对话上执行。终端选择「Restore conversation」完成回退后，这些消息接在回退点之后执行，被回退的消息随之从网页移除，所选消息原文放回终端输入框。连接端按画面识别回退菜单的两页：选消息页显示 `Restore the code and/or conversation…`，底栏为 `Esc to cancel`；确认页显示 `Confirm you want to restore…`、所选消息原文和包含 `Never mind` 的编号选项。网页显示「原版终端打开了回退菜单（/rewind）」及上述排队说明，并提供「关闭终端回退菜单」按钮。点击并二次确认后，连接端重新读取画面，核对菜单仍在，再执行取消：选消息页发送 Esc；确认页先选「Never mind」退回选消息页，再发送 Esc。网页只能关闭菜单，不能确认回退；终端已自行关闭菜单时，旧卡片的点击不会发送任何按键。

连接端读取终端画面时，单行上限由 1 MiB 提高到 16 MiB，避免较大的画面帧被截断后读不到底栏和弹窗。以上行为在 Claude Code 2.1.323 上实测，见 [Claude 渲染与交互验收](validation/claude-rendering-interaction-20261114.md)。

原生带 `interruptedMessageId` 的中断控制记录显示为原回复下方的「请求已中断」，悬停可查看原生标记，不单独形成用户消息。仅隐藏明确非 API 错误的原生合成占位回复 `No response requested.`；真实模型正文、用户引用和错误信息保留。HTTP 分页与实时同步均核对有效轮次 ID，清理旧误分类缓存并重算游标，不改写原生 JSONL。详见[Claude 消息渲染排查](validation/claude-message-rendering-20261112.md)。

Claude 终端预览与正式历史分开保存。预览绑定当前连接、原生用户消息和已读取的正文摘要；仅工具状态或用量变化时保留已显示内容，正式正文到达后一次性接替。迟到、缩短、无法确认归属的终端片段不覆盖正式消息；终端工具状态行不作为回复展示，Markdown 与终端纯文本的重复只用于过滤预览，不改写正式正文。临时预览不进入服务端持久化历史，升级后清理旧版残留的预览记录；HTTP 读取和实时通知使用同一接替规则。

默认配置使用独立实例 `codex-elves-claude-test`、用户 `elves-test` 和 `/home/elves-test/.local/bin/claude`。可在本机状态目录的 `remote-claude-wsl.json` 显式设置 `distribution`、`user`、`executable`，也可在页面选择其他已检测且接入就绪的实例；已有会话保留创建时绑定的环境。所有发行版使用相同的名称、用户和路径校验，不按发行版名称增设功能限制。API 地址及密钥由各实例自己的 Claude 配置管理，不写入本文件或仓库。

## zrok / FRP 主入口

管理器在「公网入口」标题右侧使用 `zrok / frp` 面包屑切换配置表单。查看表单不改变正在运行的入口；「保存并测试」验证候选入口，「应用为主链路」验证成功后才切换。ngrok 保持第二通道，切换主入口不重建其进程、不更换 Token，业务仍按已有延迟与健康状态选路。主入口变更后，远程设备需要使用新地址重新登录。

FRP 表单中的地址统一称为「固定公网地址」，不展示证书上传、私钥或 HTTPS 接入方式选择。第一行按「服务器地址 → Token → 服务端口 → 公网映射端口」排列，两个端口输入框均固定为 80px；窄窗口按该顺序换行。服务器地址接受带 `http://`、`https://` 的粘贴内容，保存时提取域名；粘贴网址中的端口不会覆盖单独填写的服务端口。固定公网地址默认按 `http://服务器地址:公网映射端口` 自动生成，也可直接填写服务商提供的独立 HTTP/HTTPS 根地址；清空输入后恢复自动生成。删除重复的「当前公网地址」区域。

两个端口输入框隐藏上下箭头。主链路的保存、测试、切换和复制结果统一显示在操作按钮左侧，替换默认说明，不单独占行、不加背景或边框，也不额外弹窗。HTTP 入口验证通过后可以应用为主链路，界面说明公网传输不加密；既有 HTTPS 配置继续保留。切换配置标签或启停远程服务后清除旧操作提示。

FRP 配置保存在本机状态目录的 `remote-access-frp/draft.json`，生效配置保存在 `active.json`；主入口选择保存在 `remote-access-primary.json`，旧安装默认 zrok。候选配置不覆盖正在运行的配置。Token 与兼容配置中的私钥只经本机管理接口处理，不出现在网页发现或运行状态中。发生端口占用时核对本机受管客户端程序、启动时间、状态目录内配置、服务器、服务端口、Token 和单一映射端口；确认归属后关闭旧映射并重试一次。升级前的 0.54.0 客户端还需核对程序摘要。多映射客户端、其他端口、其他设备和无法核对归属的进程不自动停止。服务商端口许可不足单独提示，不能靠重启解除。修改正在使用的 FRP 配置时，停止旧连接后直接测试并应用新配置；新配置验证成功即替换当前主入口，验证失败时旧入口不会继续使用。

Windows x64 托管固定版本 FRP 0.71.1，下载与执行均校验 SHA-256。候选隧道只开放随机回源校验及匿名 401 检查；只有验证通过并生效的入口才开放会话。FRP Host 直接抵达原监听端口时仍会被拒绝，不能绕开已验证入口。HTTP 登录仍校验密钥、设备授权和来源，Cookie 保留 HttpOnly、SameSite=Strict，并按协议决定 Secure 属性；公网设备仍绑定所选 Origin。网页只额外接纳当前页面自身的 HTTP/HTTPS Origin，ngrok 第二通道仍限既有 HTTPS 白名单。

HTTP 下图片和队列编辑使用兼容的 SHA-256 指纹实现；原图、缩略图、视频封面与 Range/HEAD 请求沿用授权校验。Android 接受用户明确输入的 HTTP 主地址，保留同源资源与下载校验、HTTPS 第二通道规则和证书错误拦截。HTTP 普通浏览器不支持 Service Worker/PWA 离线安装，这不影响在线网页访问。实现及验收边界见 `docs/validation/frp-http-20261023/README.md`。

切换到 frp 标签只展示配置。远程网页已启用时，点击「保存并测试」或「应用为主链路」会先检查当前版本的 frpc，缺失或摘要不符时自动从官方 GitHub Releases 下载。下载期间在「保存并测试」按钮左侧显示进度条、百分比及已下载大小；没有总大小时显示不定进度。下载成功后继续校验并测试连接，失败后恢复操作结果提示。远程网页未启用时仅保存配置，不触发下载。

## 会话菜单与工作区工具

会话右上角的“会话菜单”在 PC 布局中提供“变更”“文件”，手机布局额外保留“浏览器”，跨 760px 断点时同步更新；下方为“子智能体”和“侧边会话”分组，不增加“工具”标题。变更和文件打开独立页面，右上角“返回”回到原会话。

工作区边界由服务根据会话或项目标识解析，客户端不能指定任意工作目录。已有会话读取对应实例的真实目录，新建页读取服务核验后的项目目录。取得目录后，由电脑端直接读取 Git 或本地文件；Git 项目以实际仓库或 worktree 根目录为边界，非 Git 项目的文件页以会话目录为边界。工作区接口允许已授权的只读设备查看，不提供写文件、还原、暂存或提交。

“变更”分别显示暂存、未暂存和未跟踪文件；仅执行权限等元数据变化而内容未变的修改不显示，新增、删除、重命名、冲突和二进制内容变化仍展示。文件详情提供文本 diff，以及受支持图片的修改前后预览；PNG、JPEG、GIF、WebP 和通过受限检查的 SVG 可预览，其他二进制或超限内容显示说明。再次进入时可先显示缓存，再后台核对版本；读取失败保留可用缓存并提示，工作目录或授权失效时清理对应内容。

“文件”提供当前工作区文件树、名称搜索和文件内容预览，文件夹优先，名称按中文自然排序。文本、受支持图片和通过检查的 SVG 可预览；路径越界、Git 元数据、符号链接、特殊文件及超限内容受到服务端限制。正文中的本地文件引用也可打开文件页，或通过受鉴权的工作区地址在浏览器中打开；HTML 响应使用隔离沙箱，不能据此访问任意电脑路径。

“浏览器”要求当前已授权线路包含 FRP，并且 Android App 提供 `browserVersion: 1` 原生桥。未开启 FRP、普通浏览器或旧 APK 会提示相应条件，不提供网页内的通用浏览器。该页面与工作区文件的“浏览器打开”是两个入口，具体能力边界见 [会话工具说明](remote-session-tools.md)。

“子智能体”沿用原生列表及状态，正在执行或等待的条目显示名称与时间，完成条目可展开查看。远程只能查看，不能创建或向子智能体发送消息；临时子智能体不另建会话或持久登记。

“侧边会话”由服务独立创建和管理临时分支，不与 Codex 桌面的原生侧边标签同步。新建时使用服务内的临时会话，名称缺失时显示“新建侧边会话”；仍为默认名时，从首条含有效文字的真实用户消息中合并连续空白、去除首尾空白，截取前 15 个 Unicode 码点命名。图片、空文字、待提交输入和压缩输入不参与命名。名称保存在服务内存中，已有自定义名称保持优先。

侧边会话可续聊和选择自己的模型、思考深度。侧边初始继承父会话设置，后续模型与思考深度独立选择，并在新发送时生效。子智能体顶部只读显示其实际模型和深度。两类详情隐藏主会话侧栏及延迟按钮，保留会话菜单和“返回”；子智能体隐藏编辑框，侧边会话不支持编辑已发送消息。临时侧边不持久化、不加入主会话侧栏，关闭前提示无法恢复；失效后显示过期提示，不能继续发送。主会话与侧边会话分别保留草稿、展开状态和阅读位置。详细行为与接口见 [会话工具说明](remote-session-tools.md)。

## 主入口与 ngrok 双通道

管理端在「ngrok 第二线路」右侧提供「启用 ngrok 第二线路」开关，默认关闭，包括未配置过该开关的旧设置。关闭时仅保留标题和开关，隐藏 Token 输入框、查看与复制按钮、「保存并测试」按钮及状态说明；已保存的 Token 保留，重新开启后恢复显示。开启后才能点击「保存并测试」建立 ngrok HTTPS 入口，核对本机登录状态接口及匿名会话接口的 401 响应。Token 单独保存在本机用户目录的 `.codex-session-delete/remote-access-ngrok.json`，不随源码分发，不通过管理状态或网页发现接口回显。Windows x64 使用固定版本、校验 SHA-256 的官方 ngrok 程序；其他平台保留原有 zrok 连接，不下载 Windows 程序。

ngrok Token 与「设置访问密钥」共用同一输入控件，默认圆点遮挡，可通过小眼睛查看明文或点击复制。保存成功后保留已保存的 Token 并恢复遮挡；重新进入页面时，仅通过管理器本机凭据接口读取并回填，后台刷新不会覆盖正在编辑的内容。「保存并测试」仍可用于重新验证已保存的 Token。

已保存 Token 且第二线路开关开启时，启动所选主入口才会同步启动 ngrok；关闭开关会停止已运行或正在启动的第二线路、撤下第二入口，并保留 Token。开关立即保存生效，不重启主线路、网页监听或撤销已有设备授权。停止远程网页时关闭两条隧道。主入口进程临时退出重试期间，已启用的 ngrok 独立维持连接。管理端不展示 ngrok 域名。安卓仍只需填写所选主入口的固定公网地址并登录，网页通过已授权的 `/api/channels` 自动发现第二入口，每分钟尝试刷新；发现或第二线路失败时原有入口继续可用。

开关变化会在停止隧道前发布带版本号的 `remote/channelsChanged` 事件，并进入事件补读记录。页面和 SharedWorker 收到后立即撤下旧的第二线路、停止对应事件连接，再通过主线路重新发现配置，不等待一分钟轮询。迟到的旧发现响应、旧页面配置以及新页面初始化的空配置不能恢复已关闭的线路；重新开启时，也须重新取得授权地址和凭证后才能使用。第二线路上仍在等待的只读请求可转向主线路；已经提交的写请求继续核对原回执，不自动重发或清除未知结果。

第二入口使用十分钟有效的内存凭证，允许会话读取、变更读取、事件订阅，以及携带稳定 `Idempotency-Key` 的全部会话写操作，包括提示词优化与取消、停止、审批问答、队列、侧边会话、重命名和删除。它关联原设备授权，每次请求与事件发送仍检查服务开关、密钥代次及设备有效期；只读策略和远程操作权限继续由服务端复核。网页不复制 HttpOnly Cookie，登录密钥及具有写权限的通道凭证不进入 URL。图片、缩略图、视频和封面使用独立只读短期凭证；该凭证仅可读取已登记媒体，不能用于会话 API、写操作或事件订阅。CORS 仅接受已登记入口，连接地址限制为受支持的 HTTPS 隧道域名。

实时事件在电脑端广播前统一附加 `channelEpoch` 和递增的 `channelSequence`，保留最近 1024 个事件。会话网页及共享事件 worker 按最新延迟选择一条 WebSocket，测得另一条更快时切换连接；第二入口通过服务标识检查后才交付事件，继续按序号去重、补齐缺号，记录过期或服务重启时重新读取当前会话。连接失败后按退避时间重新选路，关闭事件流时取消补读与重连计时器。安卓独立后台通知仍保留两条 SSE 冗余订阅及其去重策略，不与前台网页连接共用生命周期。

会话状态、侧栏、历史、会话详情、模型、Skill、通知、队列、操作回执、优化结果及工作区页等业务请求先使用现有测量选择一条入口。安全读取白名单在网络、网关或限流错误后可顺序尝试另一条已授权线路，最多两次；有健康备用时，慢速读取等待 8 秒后也可切换。功能本身返回的无 `Retry-After` 应用级 `503` 不判定为线路故障，也不换路重读。写操作每次只提交一条线路。图片与视频在设置媒体地址时采用同一选路结果。安卓 WebView 放行携带对应凭证的业务请求、媒体读取及预检，继续禁止跨域页面和脚本。页面与静态资源沿当前入口和原有资源缓存机制加载；初次登录尚无通道凭证，继续使用登录入口。连接测速明确访问两路，用于产生后续业务选路依据。

每次业务请求直接使用右上角已有的线路状态和 RTT，不增加请求前探测。有有效测量时，选择未标记不可用且 RTT 最小的线路；延迟相同时优先原入口。尚无有效测量时，在未标记不可用的候选线路中优先原入口；两路都标记不可用时取消本次请求，写入保留草稿，不留下未实际发出的待确认回执。线路测量与当前设备、入口、连接代次保持一致，旧设备或旧入口的测量不参与选择。后台通过 `/api/channels` 的 `requestRoutingVersion: 2` 声明完整请求选路能力；旧服务继续按其 `sendActions` 能力选择兼容线路。

单次操作只调用一次写请求。请求发出后即固定线路，超时、网络异常或回包丢失时仅通过原请求 ID 查询共享回执或核对原生消息，不自动换线路重发。两路使用相同设备身份和服务端回执表，回执在派发前原子登记；即使同一请求 ID 经不同入口到达，也只执行一次，相同 ID 携带不同内容会被拒绝。此发送策略需要同时更新电脑端服务、网页资源和 Android App 的第二入口请求规则。新版 Android 通过 `app-info.requestRoutingVersion: 2` 声明原生能力；旧 APK 保留其允许的请求路径，新写操作及媒体继续走原入口，避免热更新网页后被旧原生策略阻断。

发送发生传输失败、回包读取失败或第二路凭证失效时，更新右上角该线路的不可用状态，下一条消息据此选路；只读限制等明确业务拒绝不视为断线。较早发送的失败不能覆盖后续已恢复的测量，也不能影响另一设备、连接或服务实例。入口域名相同但 `serverId` 变化时仍清空旧延迟并拒绝迟到测量；同一实例正常续期凭证不会清空已有延迟。

写操作响应和只读回执查询均校验 `requestId`、回执状态及成功标记，错误身份或格式不完整的回执不能清除草稿、解除待确认锁定。已明确未发送的本次请求即使本地草稿恢复记录写入失败，也会解除发送锁并保留原错误与当前输入，不将其误标为已提交待确认。

此功能需要更新电脑端运行程序及网页资源，并更新安卓 APK，才能启用 WebView 的第二入口访问策略及后台双路通知。双隧道共享手机和电脑出口时仍可能同时变慢，不能据隔离测试推定真实手机网络的延迟改善比例。

双路启用后，远程会话右上角的延迟按钮分为上下两行，上方为所选主入口（zrok 或 FRP），下方为 ngrok。沿用会话状态探测周期，分别统计两条 `/api/session` 请求从发出到完整解析响应的耗时；较快线路先更新，另一条最多等待 15 秒后显示结果或「暂不可用」。新一轮探测不会丢弃另一条线路尚未返回的超时结果，同一线路的旧结果也不会覆盖较新的测量。测速请求可并行并先返回有效状态；业务读取按上述白名单顺序恢复，写操作保持单次提交。单路保留原显示，点击延迟区域及键盘 Enter、Space 同时刷新延迟和会话。

## 会话视频预览

会话正文中的本地视频 Markdown 链接和视频附件可显示静态封面，支持 MP4、M4V、WebM、MOV、OGV/OGG 文件；实际播放能力取决于浏览器或 Android WebView 的解码支持。文件必须来自会话中登记的本机固定磁盘路径，不开放任意路径读取或远程 URL 代理。

正文只请求 `/api/videos/<id>/poster`。电脑通过 Windows 本地缩略图接口提取至多 256 像素封面并缓存；没有可用缩略图时返回小型通用视频封面，不回退下载原视频。打开预览弹窗时播放器使用 `preload="none"` 且不设置 `src`，点击弹窗下方的播放按钮后才设置视频地址。下方同时显示进度条与时间，支持播放、暂停、重播和拖动进度；关闭弹窗会清除视频地址并停止加载，切到后台会暂停。

图片、封面及视频地址沿当前延迟较优的可用入口读取，第二入口使用独立只读短期媒体凭证；不竞速下载视频，支持 HTTP Range 分段流式读取，避免整文件读入内存。暂停后继续播放或拖动时会更新已续期的媒体地址并保留播放位置。封面接口支持授权后 ETag 重验证，设备撤销后不能继续发起封面或视频读取。旧 Android APK 保留原入口读取，新通道能力需要更新 APK；源码变更不代表已构建或安装新包。

## 功能范围

管理工具提供独立的「远程会话」导航入口。网页服务运行在 CodexElves 独立 Rust 后台，由伴随管理器程序的 `--remote-access-service` 模式提供，生命周期由拉起它的 CodexElves 进程托管。网页资源嵌入程序，不要求用户另行安装 Node.js 或 Bun。

Codex 会话统一通过服务模式读取和执行；Claude 会话继续使用所属实例的原生 CLI。能力由当前后端明确声明：

- 读取本机项目、会话、完整分页历史和实时事件。
- 在现有项目中新建原生会话，继续已有会话。
- 项目置顶写回 `pinned-project-ids`；会话置顶使用当前桌面的 `pinnedThreads` 服务，不使用已被桌面忽略的旧置顶列表。
- 项目顺序读取 `project-order`；最近会话日期分组按原生最近更新时间倒序，项目及会话的真实置顶记录、手动顺序仍来自原生。最近/项目视图偏好按设备授权在各远程客户端独立保存，刷新后保持，不被其他客户端覆盖。保留现有视图切换和置顶入口，不新增独立排序菜单。
- 渲染用户消息、Markdown、代码块、表格、思考记录、命令输出和文件修改；工具记录可折叠。
- 默认继承当前会话模型和思考深度，明确选择时才覆盖。远程菜单和提交按原生模型目录的 `supportedReasoningEfforts` 校验，不用本地代理的模型规则替代原生目录。
- 通过原生发送入口续聊，展示桌面的原生消息队列，不维护第二套执行队列。
- 展示命令、工具和文件修改记录；可处理已适配的命令、网络或权限请求与用户问答。文件审批没有专用远程展示和交付保证；未适配请求及外部账号登录需在桌面处理。
- 停止同时调用原生停止与该会话的后台终端清理，不结束其他会话或整台机器的进程。

原生读取成功时直接使用原生结果；侧栏仅返回 `nativeBridge: "read_only"` 时仍可尝试 service。明确的 `4xx` 或 `nativeOnly` 拒绝保持原结果，不换读取来源掩盖会话错误；其他符合白名单的读取失败才进入 service。

侧边会话引导成功后，正文与原生 `steered` 确认按消息 ID 合并，状态不会覆盖正文；执行中、历史分页和重新进入均保留同一份引导内容。引导中不插入正文；成功展示按队列或逻辑消息身份收敛，不按文字去重，也不会重复派发已接受消息。检查记录见 [侧边引导历史修复](validation/side-steer-history-20261112.md)。

Codex 的发送由会话服务核对当前持有者、执行状态、待处理请求和队列，再派发给对应的 app-server 或桌面 IPC 持有者。图片、Skill、目标、队列及临时侧边沿用服务各自的校验规则，不能静默丢弃不支持的输入。桌面持有者已处理、拒绝或结果未知时，不再调用另一执行通道。超时和未知送达状态只核对原回执，不自动重发。

原生模块发现兼容旧版命名资源与新版 Rspack 数字资源。新版仅从页面已经加载的同源入口取得运行时，检查已执行模块的实际导出，不执行缓存之外的模块工厂；创建、权限、消息准备及关联会话仍调用对应原生接口。模块 ID 和文件哈希不参与能力选择，队列编辑的原始输入序列化保留独立的已核准合同摘要检查。

新建、停止、目标、审批问答、编辑、队列和侧边会话管理等写能力仍依赖原生。`/api/session` 分别声明原生连接、service 连接、原生写能力和功能能力；原生写能力不可用时可以保留 service 文本发送，不能据此启用所有原生操作。设备原有只读策略和服务器授权仍独立生效。

远程不提供任意 RPC、CDP、脚本执行入口或桌面外部登录代办。文件浏览限于上述已授权工作区；会话媒体另按原生引用登记，只接收已登记媒体 ID。

## 认证与控制权限

公开入口仅包含登录所需的静态页面／资源、`/api/login-status` 和 `/api/connect`。获取静态网页不代表获得设备授权。客户端用正确密钥换取设备 Cookie 后可按原有效期继续访问；Cookie 需与服务端保存的设备、当前密钥代次和有效期一致。未设置密钥、没有凭证、伪造凭证、授权撤销或密钥轮换均不能读取会话或调用控制接口。公开页面不提供本机管理密钥、任意 RPC 或任意文件读取。

所有其他 `/api/*` 请求先通过 Host／Origin 边界和服务端身份检查，再解析请求正文。匿名或随机 Cookie 的请求会在读取密钥文件前拒绝，因此没有上传完整图片或触发密钥派生计算的必要。历史、回执、图片、SSE 和 WebSocket 均执行服务端鉴权；前端按钮、Android 保存的登录标记及 PWA 缓存都不作为授权依据。

启用、只读和远程审批权限使用控制器中的当前策略。在应用设置时，策略先于文件锁、隧道检查等等待点发布；旧页面、旧路由状态和已进入处理流程的请求不能沿用较宽松的旧权限。写操作在接收、准备派发及实际服务派发边界复核授权。完成请求准备后，持有设备认证、密钥轮换和短暂策略锁完成指令同步入队，随后立即释放锁，再等待网络刷新及原生响应。这样撤权与指令接受有明确先后关系，不会持锁等待整个 Codex 操作。

慢查询的序列化／压缩完成、图片读取完成、回执结果返回前会再次检查授权。授权失效后不继续返回私有结果。SSE／WebSocket 的业务事件也持续核对设备授权及服务启用状态，失效后关闭业务流。

在实际派发前被拒绝的操作保存为 `failed`、标记 `notSent`，保留原幂等 ID 和请求摘要；恢复权限后重试相同请求仍返回原失败回执，不偷偷重新执行。指令已经入队后发生传输故障仍视为 `unknown`。已接受操作之后授权失效，响应只返回通用拒绝和 `outcomeUnknown` 提示，不返回原生结果；网页清除失效登录，但不会把该情况误报为确定“未发送”。授权撤销不承诺撤回已经被 Codex 接受的操作，重新连接后应查看会话确认。

每次授权复核仍读取持久化密钥和登录锁状态。仅对 `id`、`salt`、`hash`、`value` 四字段完全相同、已经通过验证的密钥材料复用最近一次 KDF 结果；最多保留一条，任一字段变化即重新验证。该缓存不缓存设备授权、权限、有效期或登录锁状态，也不依赖文件修改时间。

本说明依据工作区源码，运行中的旧服务需要更新程序并重新启动后才会应用；功能描述不代表安装版或 Android 真机已经验收。

## 低速网络优化

历史、侧栏、会话等 `/api/read/*` 成功响应支持 gzip。客户端允许 gzip、JSON 正文至少 1 KiB 且压缩后更小时才使用压缩；小响应和明确禁用 gzip 的客户端保持原始正文。序列化与压缩在后台任务执行，响应保持 `Cache-Control: no-store`，增加 `Vary: Accept-Encoding`，不为私有会话数据生成 ETag 或持久 HTTP 缓存。鉴权失败、写操作回执、图片和事件流不经过此压缩入口。

事件通道对 WebSocket 握手设置 45 秒期限，对已连接但连续 75 秒没有事件或心跳的连接执行清理和退避重连。浏览器离线时暂停重试，恢复网络后合并恢复请求；后台定时器长时间停顿后先留 20 秒处理已排队事件。SharedWorker 在启动后 20 秒无回复，或前台在线时连续 90 秒不回应端口消息，会隔离旧端口并切换普通 WebSocket。正常多标签页仍共用一个事件连接，不增加业务写操作或自动重发消息。

恢复同步遇到旧请求尚未结束时，会安排合并补读，不把旧请求当作恢复后的最新状态。队列 HTTP 快照同时核对读取开始后的本地状态变化，迟到的旧来源不得退休已接收的新来源。首次读取授权因网络失败而尚未取得 session 时，恢复网络或返回前台也会重试；明确 401 仍需要重新登录。HTTP 探测失败与离线会清除过期的在线延迟展示。

最近查看的会话使用页面内存缓存，并将符合条件的已结束轮次、会话显示信息、侧栏和阅读位置写入独立 IndexedDB 只读缓存；授权确认后可先恢复展示，再静默读取最新状态。临时会话不写持久展示缓存；缓存不能恢复审批、队列执行权限或可写设置。只读缓存与草稿恢复库独立，按当前设备授权隔离，默认总量 32 MiB、单条 6 MiB、最多 64 条，按过期和容量规则淘汰。最新历史与会话设置并行，旧选择的响应不能覆盖新选择，实时计划和差异不被较早快照回退；最新页失败保留已有正文及重试入口。确认空历史、回退或删除时清理对应快照，避免已移除记录重新出现。详细边界见 [缓存说明](remote-cache.md)。

HTTP 成功不代表响应正文已完整读取。成功响应的正文读取或 JSON 解析失败时，网页保留失败状态，不再构造缺少历史数据的伪成功结果。历史请求仅对此类正文失败自动重读一次，复用原会话和分页游标；切换会话、离页、取消或删除后不再重读或合入旧结果。完整 JSON 的协议格式错误、HTTP 错误、超时及普通连接失败不在此自动补读范围内。补读仍失败时保留已有历史、草稿和手动重试入口，不无限重试，也不把失败当作空历史。发送等写动作的回包正文失败则核对原请求回执，不重新发送，明确确认前不清除待确认文字和图片。

连接在线不代表当前会话设置和最新历史已经读完。当前选中会话读取失败或仍只有缓存，且没有在途读取时，后续成功的既有15秒连接探测会补读；读取成功后停止补读，不对正常会话新增全文轮询。静默恢复失败也记录待补读状态。再次选择同一未读完整的会话会重新读取，不因缓存历史存在而直接返回。草稿、已有消息和未决写回执保留；只有取得当前会话的有效设置后才恢复发送，不通过放宽发送门禁解决置灰。

未发送的文字、Skill、图片和目标输入模式使用 IndexedDB 恢复；图片单独保存并由记录引用，发送回执在 sessionStorage 中只保存轻量元数据。可靠提交仍先持久保存草稿与原幂等 ID，再发出写请求。当前图片读取完成前，按钮和快捷键均不能发送；旧发送回执到达时若新图片仍在读取，不清空当前输入或删除其已保存草稿。切换会话即解除旧图片的读取状态，旧任务迟到完成不清除新任务的读取锁、不向新会话添加图片或提示错误。已知失败先保存可恢复输入再移除 pending；用户已写入新内容时保留新稿，并提供旧输入恢复入口。授权更换或退出清理对应私有恢复记录，旧页面不能跨授权写入；持久化不可用时明确提示，本地小文字回执可退回原有 sessionStorage 路径，大图保存失败则在提交前停止。

写请求增加包含上传、响应头与响应正文的等待预算：基础 90 秒，按请求体大小和保守上传速度追加，最长 20 分钟。超时只表示没有取得结果，保留原回执并退出发送等待，后续仅查询原 ID，不自动重发。只读接口继续有独立期限。

浏览器在页面可用后后台准备当前版本清单中的全部静态资源，包括尚未展示的图表库；可选项按文件大小从小到大准备，Mermaid 不占用基础页面的启动关键队列。后台同时最多下载一项，当前页面急需的资源最多并行两项；同路径需求共享下载，主动前台需求可提升已有任务，并暂停不再紧急的后台传输。会话读取、恢复和写入直到响应正文处理完毕都保持忙状态，后台新任务等其结束后再开始；每 15 秒的被动状态轮询不取消已经进行的下载，避免单个资源耗时超过轮询周期时反复重下。可选资源被主动操作中断两次后退避五分钟并继续后面的资源，当前页面按需请求可直接绕过该退避。共享读取从被动升级为主动时会提高优先级，不重复 HTTP 或被后续被动调用降级。忙状态按标签隔离，每 10 秒续期、30 秒过期，关闭某个标签不会永久阻止后台任务。更新逐项核对 MIME、大小和 SHA-256，复用有效旧缓存及已下载的 HTTP 表示。缓存缺项只能按当前固定版本清单恢复，无法匹配时明确失败，不混用线上新脚本与旧样式。设置弹窗仅在检查、准备、待启用或失败等状态显示说明，并保留失败重试入口；基础缓存就绪后隐藏该状态行。新版待启用时提示重开页面，不强制刷新或丢弃正在输入的草稿。静态资源准备完成后可从缓存加载相应模块；完成前的首次需求仍可能联网。会话消息、审批及图片附件属于动态数据，不会因静态预下载而全部离线可用，也不会自动全量抓取所有聊天。

网页启动依赖分为以下三层：

| 层次 | 资源和触发条件 | 对当前会话的影响 |
| --- | --- | --- |
| 基础页面 | HTML、CSS、`app.js`、事件连接、草稿恢复、附件和轻量 Markdown 入口；HTML 预加载直接模块依赖 | 优先完成登录、会话选择、消息读取和输入；不等待图表及格式库 |
| 正文格式及辅助资源 | 首次有正文时并行导入 `markdown-renderer.js`、Marked、DOMPurify；图标和格式库也进入空闲预下载队列 | 加载期间显示安全转义的纯文本；失败保留正文并提供有限重试，成功后原地恢复 Markdown、Skill、附件等显示 |
| 图表 | Mermaid 静态文件随空闲队列预下载，仅在图表靠近可视区约 200 px 时导入并执行 | 较小的可选资源先准备；已挂载但离屏的图表暂不渲染；切换后清理旧观察项，回到会话后重新登记 |

离线 worker 仅等待基础页面资源校验、保存成功后就绪，可选项失败不撤销基础缓存。模块重试 query 仍对应固定版本清单中的同一路径；成功的模块会复用，不随其他模块的重试重复下载。Markdown、链接、图片和 SVG 的原有安全清洗规则保持不变。格式库不可用时的纯文本由轻量入口转义，不依赖第三方 HTML 解析器。

格式升级、图片完成和图表替换使用同步布局事务：跟随最新消息时保持底部；阅读历史时在变更开始前捕获视口首行的文字位置，变更后在当前消息根内恢复该位置，不跨网络等待保存旧滚动快照。Markdown 标点消失后按正文字符及上下文寻找同一位置，找不到原文字（如源码已变为图表）时退回所在内容块。后续行仍可能因段落或折行变化发生局部重排，不承诺所有屏内像素固定。

Mermaid 下载期间保持源码可读，主题刷新时保留旧图；新图完整解码后一次替换，不再先隐藏源码或强设 220 px 加载高度。图表在切走期间完成时会失效同一个旧渲染标识，重新挂载仍可使用已完成结果，旧任务不能清除新主题的标识。未知尺寸的正文图片先保留短加载行及可触发 lazy 请求的同位置非零元素，完成后写入真实宽高并在同步布局事务中显示；失败移除等待状态并保留原图片不可用提示。原有明确尺寸的附件缩略图保持原布局。异步完成时重新核对当前 DOM 和会话，旧内容不能滚动新会话。

文件 Markdown 预览同样渲染 Mermaid 围栏，提供图表／源码切换和源码复制；语法错误或资源不可用时保留源码。文件与会话分别按各自滚动容器延迟渲染，共用图表缓存和安全规则，打开文件不会取消消息中的图表观察。切换主题只更新图表并保留文件阅读位置，切换文件、进入源码或关闭预览后清理旧观察。

服务端静态资源的摘要和 gzip 也改为按文件首次需要时生成并复用，放在阻塞线程池执行；请求首页不会触发整套 Mermaid 的压缩。gzip 正文使用共享字节存储，保持各编码独立 ETag、条件请求及现有安全响应头。

加载页独立启动缓存管理模块，并提供 `/cache-recovery.html` 恢复入口。恢复页及其自包含脚本不进入版本壳清单，响应使用 `no-store`；即使 PWA 模块本身缺项，也能检查新版或请求当前 worker 按其固定清单补齐必需资源。它不注销设备、不清草稿或回执，也不强制激活新 worker。新版等待启用时必须关闭本站所有旧页面（包括恢复页）后再打开；同版补齐完成后可直接重开。当前版本的缓存清单与完整性标记也损坏时会明确失败，不假装已经修复。

Android 用清单内容版本识别内置资源是否已与服务端一致，更新时复用已校验的当前、上一版和内置文件，只下载差异；gzip 按编码长度限额与解压后的长度、摘要分别校验。资源校验和更新使用独立队列，切换服务、退出或关闭页面会取消当前传输；完整候选仍在下次开页启用。当前和上一份缓存都损坏时回退内置资源，更新失败可重试，不强制打断健康页面。

Android APK 使用独立版本。设置页面底部左侧从原生外壳读取并显示 `v版本号`，点击可检查更新；启动及返回前台后也会按间隔检查本仓库的 Android GitHub Release。设置页面从右侧滑入，左侧按“通用设置”“外观主题”“通知事件”“诊断日志”分组导航，右侧切换对应内容；通知事件和诊断日志仅在 Android 容器提供相应能力时显示。新版 APK 下载后校验摘要、包名、版本和签名，再交给系统安装器确认安装。APK 自更新与上述服务端网页资源更新分别执行，协议及构建规则见 [Android 版本与应用更新](android-update.md)。

## 网页输入与外观

### 本机前端调试

发布或修改远程网页资源后，先在 `apps/codex-elves-manager/` 执行 `npm run check`。该检查会按 ES module 语法解析 `assets/remote-access/` 下的 JavaScript，验证本地静态 `import` 目标存在，并核对开发入口和 Rust 远程服务是否都提供这些资源；`npm run build` 也会自动执行同一门禁。网页资源发生变化时同步递增 `assets/remote-access/resource-revision.txt`，让 Android/WebView 资源缓存识别新版本。

需要保持现有 `codex-elves.exe` 和真实会话运行时，在仓库根目录启动独立调试入口：

```powershell
node .\scripts\dev-remote-access.mjs
```

打开 `http://localhost:1432/`，使用现有远程访问密钥登录。需要直接查看指定会话时，可在地址后追加 `#thread=<会话 ID>`。调试入口只监听 `127.0.0.1`，默认将会话 API、图片和实时事件转发给现有 `http://127.0.0.1:45222`；不会启动或替换 launcher，不需要管理员权限或安装包。端口已占用时用 `--port 1433`，后端端口不同时用 `--upstream http://127.0.0.1:45223`。

网页资源每次从 `assets/remote-access/` 读取，修改 JS/CSS 后刷新调试页即可；浏览器禁止缓存这些调试资源。默认使用 SSE 兼容旧版后端；后端已支持 WebSocket 时可指定 `--events-transport websocket`，仅转发 `/api/events/ws` 升级请求，不开放其它套接字或任意代理路径。调试页使用独立命名的设备 cookie，仍保留后端的登录校验、HttpOnly、SameSite 和 Secure 属性，不读取、保存或输出访问密钥。入口会检查本机 Host、同源 Origin 和跨站请求，再将合法请求转发给固定的本机后端。

管理器中「生成」仅填入候选访问密钥，点击右侧「保存」后才生效；明文及校验摘要保存在本机，输入框默认遮挡明文。成功保存不同的新密钥会撤销已有设备授权。若经用户明确同意，在浏览器中将已有设备授权复用于调试页，则两页共享同一设备授权，任一页点击「退出」都会使另一页失去授权。

这里连接的是真实会话，不是模拟数据：发送、停止、编辑和删除等操作与正式网页一样会作用于真实后端。仅查看渲染时不要发送测试消息。该入口不能让 Rust 后端 自动更新，原远程网址也仍由旧程序提供；这两类改动仍需要更新相应运行程序。停止调试时在启动终端按 `Ctrl+C`，原服务不受影响。

使用 localhost 不会改变图片读取权限。历史消息优先使用后端注册的同源图片地址；旧后端返回原生内嵌图片时，网页也可显示缩略图并打开预览，队列同样支持内嵌缩略图。只接受 PNG、JPEG、WebP 和 GIF 的 Base64 图片并核对文件头，不加载外部 URL、SVG 或 `file:` 路径。图片发送和队列图片删除仍按 `/api/session` 的能力声明启用，旧程序未声明支持时不会因更换为 localhost 而开放；需要更新运行程序后使用。

### 长会话与实时消息

历史优先读取最新内容，普通原生与 CLI 分页均以每页 3 轮、每个消息页 40 项为基准，轮次和消息分别保留分页游标；执行中轮次及 owner 快照按各自来源合并。首屏不代表历史已经全部加载，向上继续读取更早内容时保留阅读位置，不把摘要或局部文件统计当作完整历史。

流式通知按浏览器帧合并渲染；未变化的消息和已展开工具保留原节点。折叠工具不生成输出正文，展开后按每段 20,000 个字符显示，可继续加载剩余输出。历史读取期间到达的新消息不会被旧快照覆盖，回合完成通知中的空 `items` 不会清空已有消息；思考摘要与正文分别按原生分段索引更新。

消息正文使用本地打包的 Markdown 解析及 HTML 净化，支持嵌套列表、有序列表起始编号、任务列表、表格、引用和围栏代码。代码块仍可复制，普通本地路径显示文件引用，短按打开文件页，长按或右键提供“文件”和“浏览器”入口；浏览器入口通过当前会话鉴权的工作区地址打开本地文件，HTML 使用隔离沙箱响应。与原生会话一样移除完整的内部引用控制标记，不把缺少来源元数据的标记展示为正文或猜造链接。会话中的本地图片和用户图片附件通过已注册的同源地址显示缩略图。正文图片保持原比例，桌面端宽高均不超过 150px，手机端均不超过 120px；点击后的原图预览不受此限制。不直接加载外部图片或浏览器 `file:` 地址。

用户消息下方显示原生发送时间和复制操作，桌面悬停或键盘聚焦时出现，触屏和窄屏保持可见，不需要点击气泡展开。时间取自原生回合、排队送达记录或消息条目的真实时间；缺少来源时不以网页接收时间补造。纯图片用户消息同样支持时间和操作。已完成的主回复提供复制操作。最后一轮可编辑的初始用户消息还提供铅笔入口，在原消息位置打开编辑框，仅显示「取消」「发送」，不提供「发送并恢复文件」。发送通过原生编辑入口替换后续回复并重新执行，原附件和隐藏上下文保留，不恢复磁盘文件；底部普通草稿保持不变。支持 Escape 取消、Ctrl/Cmd+Enter 发送，空文字禁用发送；失败时保留修改，回执待确认时锁定重复提交。活动回合、上下文压缩、待确认提交、队列或后续补充消息存在时禁止编辑。提交前再次检查消息 ID 和回合 ID，避免修改已过期消息。

每轮按原生显示结构组织为「用户请求 → 活动 → 主回复」，同一轮只有一个可见的活动耗时标题。思考、过程说明、工具按原始顺序展示，已结束且没有正文的思考记录不生成空行；执行中的补充消息和用户回答单独显示，不会被折叠过程隐藏，也不新增「工作过程」标题或重置计时。`commentary` 属于活动正文，不作为最终答复；主回复单独展示，兼容旧历史中 `phase: null` 的消息。展开状态由用户操作保留，工具正文仍按需加载。

轮次开始事件早于用户消息到达时，不提前显示空的「已处理 / 正在思考」占位，也不为无内容的轮次保留空白间距。用户消息由原生事件或历史读取补回后，同帧按「用户消息 → 活动」显示；已有的过程正文、工具和模型切换记录仍沿用原有展示规则。

已知轮次开始时间且出现实际工作后，在首段工作前显示「已处理 4分38秒」，每秒只更新现有标题，不发起历史轮询；有效 `final_answer` 开始或回合完成后冻结，最终耗时显示「用时 4分38秒」，位于最后一段工作、最终答复之前。完成态优先使用原生 `durationMs`，否则使用可靠的起止时间；未知时间显示「活动」，不使用用户消息时间或网页接收时间补造。切换会话、后台、离开页面或完成后停止时钟；返回前台依据真实起时恢复。历史迟到响应或空时间字段不能清空已确认的实时耗时。

以可见的过程正文为分隔，将连续命令、浏览器及其他 MCP/动态工具、文件修改、网页搜索和已完成思考收纳到一个默认折叠的工作摘要，不再将浏览器调用和文件修改逐条摊开。纯命令显示「运行了命令」；混合记录按实际类别显示，例如「已使用 浏览器和Chrome编辑了多个文件运行了命令」。浏览器名称读取原生结果中的 `codex/toolSurface`，没有结果元数据的统一浏览器插件沿用当前原生的 Chrome 名称，未知工具保留其服务器名称。没有通用浏览器来源的具名工具使用「集成」文案；文件修改沿用原生中文摘要的「编辑了多个文件」，具体去重文件数量保留在提示中。

运行中的摘要优先描述最后一条仍在执行的命令、工具或文件操作；浏览器、MCP 及动态工具使用其 `arguments.title` 具体调用标题，缺少标题时显示可读工具名，不再只显示「正在使用 Chrome」。执行中的折叠标题与展开工具行保留工具图标，以文字流光表示状态，不增加整行扫光背景或「进行中」尾标；所有操作结束后恢复「已使用 Chrome 集成」等类别汇总，不保留最后一次调用标题。实时更新保留展开状态，长标题单行省略且可悬停查看，减少动态效果设置下不播放流光。已完成摘要不把历史失败逐条突出为红色失败条，失败数量仍可通过悬停、辅助技术及展开详情查看。展开后保留原始记录顺序和网页版的「已完成思考」，思考仍可独立展开。子记录使用缩进和左侧竖线区分层级，命令正文使用小号等宽字体并保持单行省略，状态和思考使用界面字体；每行摘要至少 40px 高，兼顾桌面行距和触控点击。输出仍按需加载，面板有最大高度，流式更新保留展开状态和滚动位置。用户消息、过程正文、正在进行的思考、显式错误和计划保留展示边界；纯思考不伪造工具摘要。子代理以彩色小图案、名称和状态组成紧凑单行，位于同一工作过程内，不重复制造工作过程标题，也不展示 thread ID、大卡片、内部提示词或子会话打开入口；状态未知时不伪装完成。

浏览器、MCP 和动态工具行在原位置展开，不给标题及整条记录增加外框。展开内容按返回顺序显示真实的纯文本、图片或错误，不展示调用 ID、输入参数和完整记录 JSON；工具传输层包裹的内容列表会解包后展示。纯文本保留原生风格的结果面板，图片复用同页预览，长文本每次展示 20,000 字符。未知结果类型明确提示在桌面查看，不执行工具输出中的 HTML，也不直接加载外部图片地址。

连续的图片查看记录合并为「已查看 N 张图像」，默认显示 80×80 缩略图，支持折叠和原图预览，不逐条平铺文件名；遇到正文、思考或其它类型记录立即结束合并。缩略图不可用时显示占位，不使用任意路径或外部 URL 兜底。

上下文压缩在消息流中显示「正在压缩上下文 · 可能需要几分钟」，完成后同一记录原位更新；只有原生明确标为自动压缩时显示「上下文已自动压缩」。正常运行时不重复显示输入框上方的黄色警告或额外「正在处理」；送达未知、旧设备授权及待确认状态仍保留锁定和恢复操作。模型切换读取原生 `modelChanged`/`modelRerouted` 记录，按原生锚点显示在对应用户消息前，使用分隔线、模型名称与说明按钮；不把尚未发送的菜单选择伪造为已执行的模型变更。

已确认执行的压缩在空输入时显示可点击的停止方块，实时压缩状态先于会话执行状态到达时也能停止；有文字或图片时仍按原生排队能力发送。未确认送达或结果未知时，保留原回执锁定。

会话列表的执行中圆圈在 PC 和 App 均持续旋转；系统选择减少动态效果时，单独保留这一运行状态指示，其余动画仍按系统设置关闭。

发送后自动压缩期间，本轮原生已保存输入、但正式用户消息记录尚未产生时，从原生 `params.input` 补齐文本与图片，在压缩记录之前显示；实时事件和历史重读使用同一来源。正式记录到达后按原生 `clientUserMessageId` / `clientId` 合并，不重复生成气泡，也不依据相同文本去重；迟到的旧历史不会将正式消息恢复为临时记录，或把同一条已完成压缩回退为正在压缩。手动压缩、执行中途的压缩及尚未加载完整的旧记录不补造用户消息；不改变原生压缩的启动时机，也不从网页草稿推断消息已经送达。此改动包含服务内嵌适配脚本，需要更新远程访问服务后生效。

用户消息只展示原生可见的请求、浏览器批注或问答，不平铺 `## My request:` 之前的附加上下文，也不把 `<send_user_message_question_reply>` 的 XML/JSON 当作气泡正文。普通请求渲染链接、加粗等 Markdown 并保留输入换行，图片附件以独立缩略图放在气泡上方。有效问答显示单行问题摘要与纯文本回答，悬停可查看完整问题；损坏格式和无关 XML 保留原文。命令组内的单条命令摘要优先使用原生 `commandActions` 中的实际命令，`js` 工具使用原生提供的简短操作标题。正在思考时以弱化文字显示最新非空片段，最多预览两行，点击后查看完整内容；尚无正文时保留「正在思考」状态。思考展开后使用 Markdown，最大高度与原生的 `8.75rem` 对齐。

单条命令折叠时显示「已运行」及单行命令摘要，展开后收起摘要文字，标题显示「已运行命令」和向下箭头。详情使用带边框的圆角 Shell 面板，先显示 `$ 实际命令`，再按原始换行展示输出；命令选择与折叠摘要一致，不重复平铺可替代的 shell 启动包装。长输出在面板内滚动，每次加载 20,000 字符，完整命令不占输出分页额度；错误输出及非零退出码保留。输出始终按纯文本展示，不作为 HTML 执行。

最终回复后展示已完成的文件修改卡，默认显示 3 个去重后的文件路径，可展开其余文件及该文件的修改记录。卡片只保留标题区与文件列表之间的分隔线，文件行和「再显示」入口之间不加分隔线；路径目录使用次级文字色、文件名使用正文色，「再显示 / 收起」带方向图标。行数统计优先使用原生 `turn.diff`；历史未提供时按原生规则净合并同文件连续 patch，无法按顺序合并的片段保留原分段统计，与桌面文件卡口径一致，不冒充仓库 Git 净变更。损坏、二进制或超出解析上限的差异不显示不完整总计；不提供虚假的撤销按钮。

图片引用由原生历史、队列及原生 item 通知注册，接口只接收已注册 ID，并继续验证设备授权与请求来源。磁盘图片只允许本机固定磁盘的 PNG/JPEG/GIF/WebP，文件最多 25 MiB，拒绝网络路径、设备路径、非图片和超限尺寸。GET 时按真实文件格式返回 MIME，兼容扩展名为 `.png`、内容实际为 JPEG 的截图。内联图片转换为同源注册引用，不将 data URL 平铺到历史或队列响应；缓存最多保存 1024 个引用，内联内容合计最多 64 MiB，达到限制时淘汰较早引用。文件已删除、引用过期或格式不支持时明确显示不可用提示，不扩大为任意文件读取能力。

消息输入框支持选择、粘贴和拖入图片，待发送缩略图为 40×40，可移除，并随会话或新建项目草稿保留。本地选择、预览和移除图片不依赖实时连接；手机打开相册导致网页暂停连接时，选图返回仍保留附件，重连前禁止发送。只读、正在提交及已有消息编辑事务的附件限制仍然生效；上下文压缩期间可继续编辑普通草稿的文字、Skill 和图片，在服务支持且压缩状态已确认时发送到原生队列。每条最多 4 张，单张最多 5 MiB、合计最多 12 MiB，只接受 PNG/JPEG/WebP/GIF；前后端校验格式、实际大小及尺寸，最长边不超过 16384 像素、总像素不超过 100 MP。文本与图片、纯图片均可发送或入队；编辑已发消息时原附件只读保留；排队消息在服务声明 `queuedImageEditing` 时可增删图片，否则按已声明能力保留或移除原图。前端通过会话能力确认后端支持图片发送；旧后端仍可预览，但禁止提交并明确提示更新，避免附件被旧程序忽略。

消息编辑框支持 `Ctrl+Z` 撤销，`Ctrl+Y` 或 `Ctrl+Shift+Z` 重做；macOS 使用 `Command+Z`、`Command+Shift+Z`。连续输入按片段撤销，粘贴、换行、选区替换及中文输入法提交也有独立记录，Skill／目标标签和光标位置随内容恢复。切换会话、授权或队列编辑事务，以及发送后清空编辑框时重置记录；不撤销已发送消息或图片附件操作。

用户附件和 AI 查看图片记录均支持同页预览，可通过关闭按钮、Escape 或点击遮罩关闭，关闭后焦点返回触发的缩略图。

待发送图片也可点击缩略图或使用 Enter、Space 打开同一预览窗口；右上角移除按钮独立操作，不打开预览，也不提交消息。只读或附件锁定时仍可查看原图，原有移除与发送权限保持不变。

网页按选择器返回的文件列表顺序显示和提交图片，分批选择时追加到已有图片之后；读取速度、草稿恢复和队列恢复不改变顺序。Android 容器在系统支持有序 Photo Picker 时，对多选图片请求启用 `EXTRA_PICK_IMAGES_IN_ORDER`，按用户选取顺序接收图片；取消不添加图片，无法启动时回退原文件选择器。普通浏览器及不支持该能力的旧 Android 仍采用选择器返回顺序，网页无法从文件名、修改时间或图片内容可靠重建选择器未提供的点击次序，不做统一倒序。

消息输入框默认高度 100px，随内容增长到 180px 后内部滚动。发送和停止共用右下角的圆形按钮：执行中且没有文字或图片时显示停止；添加文字或图片后原位切换为发送。会话执行中或已有待执行消息时，新消息优先加入原生服务端队列；服务端队列未启用或不能接收当前消息时，通过 Codex 的 turn coordinator 使用原生本地队列，不维护网页自己的执行队列，也不把普通发送改为引导。空闲且没有队列时沿用原生直接发送。Skills 仍作为原生输入项提交，显式模型与思考深度按原生下一轮设置应用到目标会话，不承诺为每条队列消息冻结独立模型配置。发送与停止均防止重复提交，不额外显示通用「正在处理」行；系统选择减少动态效果时关闭动画。

手机端滚动正文收缩输入区时，按钮行上方间距随收缩比例从 6px 减少至 0，完全收缩后不再保留额外间隙。点击或聚焦恢复编辑时按内容自然撑高，继续输入多行文字、添加或移除图片不会保留上一次的固定输入高度。

点击发送后，按钮立即显示旋转指示和「发送中…」，收到成功回执后以「同步中…」等待消息更新；会话列表在后台刷新，不延长发送按钮的锁定。发送时保留输入焦点，新建会话成功后不把焦点移到侧栏按钮；等待期间可继续输入，后续草稿不会被清空。明确失败时保留原草稿并恢复发送，送达不明时继续锁定且保留回执核对入口，不自动重发。正常发送期间不展示人工解除锁定操作；状态只占输入框底部同一行，不新增消息区的通用处理提示。

发送和引导只有取得成功回执或相同原生消息的接受证据后才进入正文；仅确认入队、发送中或结果未知都不展示成功气泡。已确认内容使用原有会话缓存保留，空队列、迟到快照和历史暂缺不会让它消失；原生正文到达后按稳定消息身份接替并去重。明确编辑回退或会话删除会清理对应展示记录。发送确认检查记录见 [发送确认验证](validation/send-confirmation-20261112.md)。

模型、添加、Skill、会话及文件引用菜单与排队附属区参考原生 Codex，使用独立于输入框的控件表面色，随明暗模式和自定义配色重新计算。菜单 hover 在此底色上合成，背景图位于页面内容底层。编辑区普通悬停提示使用可随主题变化的提示层，浅色下反色显示；上下文用量等详细提示继续使用控件表面色。远程端没有对比度选项，暂沿用原生默认深色 60%、浅色 45% 的派生公式。

模型触发按钮的悬停、键盘聚焦和菜单打开状态在输入框底色上合成高亮，不使用更暗的页面 hover。上下文提示的单行用量使用主题正文色；模型与推理等级之间保留 1px 分隔线，深色模式采用更清晰的派生重边框色，浅色沿用原线色。以上颜色随外观配色重新计算。

模型搜索框、设置页的文字／数字输入框、指令编辑区和 Select 复用会话输入框表面色；滑条、开关及文件选择器保留各自状态样式。外观颜色的 HEX 字段可直接编辑，完整合法的六位色值才会保存，非法或未完成的输入失焦时恢复实际颜色；只有旁边的色块按钮打开连续取色器。取色器在色相条下方提供原有 12 个预设色，并同步色块、HEX 与当前主题的颜色设置。

程序字号、代码字号和文件阅读字号统一使用数字输入框，范围分别保持 10～20px、8～24px、6～14px。按 Enter 或离开输入框后应用，空值、小数及越界值恢复为当前设置；Escape 取消本次未确认输入，文件阅读字号仍可一键恢复默认 12px。

排队消息以单行显示正文和第一张 20×20 图片缩略图，不显示其他缩略图或多图计数，仅改变预览、不丢弃其余附件。「编辑」「删除」收纳到 `...` 菜单，保留独立「引导」。桌面可拖动消息正文、缩略图或左侧手柄排序；触屏长按手柄后拖动，文字区保留正常滚动，键盘上下方向键也可排序。提交时核对原 ID 与预期顺序，回执未知时不重复提交。编辑通过原生取出、恢复令牌更新正文或图片，并核对恢复后的身份和真实输入；保留未修改的附件、Skill、隐藏上下文及原生配置，无法安全识别的输入不会被改写。「引导」复用原生队列项与准备器，不复制原文另发新消息。提交状态未知时提示核对，不自动重发。

带图队列引导按同条消息的原生附件上下文核对图片。服务端 `image` 与原生准备产生的 `localImage`，只有在 `src`、`localPath` 或 `file://` 解码后的绝对路径能够唯一对应时才视为同一输入；不按文件名或图片数量放行。正文、顺序、显式图片细节、其他输入、消息身份、恢复上下文和目标轮次继续核对，无法证明对应时保留原队列并返回未发送。该兼容仅用于引导，不放宽编辑或历史回执校验。验证见[带图队列引导兼容](validation/queue-image-steer-20261112.md)。

队列行与折叠目标条共用高度：默认桌面为 34px、手机为 36px，大字号时一起增高。队列最多显示四行，其余消息在队列内部滚动，不继续向上堆叠；不足四条按实际条数显示，短屏可进一步收缩，保留目标条和输入区域。同一会话刷新队列时保留内部滚动位置，切换会话从队列顶部显示；拖动和键盘排序只滚动队列区域。

本地队列的读取、刷新和排序通过 coordinator 的 `loadMessages` 获取当前启用的队列，不再无条件调用服务端队列接口。本地入队通过 `sendMessage`，显式指定排队模式，并按原生重放上下文持久化完整输入，避免重载后丢失 Skill 或图片；编辑继续使用原生取出、恢复令牌，并核对本地保存的真实输入。原生只允许直接发送的特殊会话仍明确拒绝排队，不绕过限制。入队调用开始后无法确认结果时保持未知回执，不自动重发。

队列快照使用 `queueEpoch` 和单调递增的 `queueRevision`，覆盖入队回执、实时事件、会话及队列读取，以及删除、排序、编辑和引导结果。网页按快照采集顺序更新，迟到的旧空队列不能覆盖已确认入队的消息；相同快照不重复渲染，真正执行或删除产生的新快照仍立即移除对应消息，不使用延时保留或网页私有执行队列。服务重连后以重新读取的快照确认新 epoch，不接受已淘汰服务的旧回包；切换会话时清理对应显示状态。服务端入队后按原生 `afterMutation` 方式刷新，避免复用变更前仍在完成的读取。首次连接不含版本字段的旧服务时仍保留原有兼容路径，完整修复需要更新远程访问服务。

向上阅读离开底部后，输入框上方居中显示圆形定位按钮：执行中为三个动画圆点，完成后为向下箭头。新内容不会强行把阅读位置拉回底部；点击按钮才恢复跟随最新消息。

同一来源的多个正式网页标签通过 SharedWorker 共用一条 WebSocket 事件连接；SharedWorker 不可用或失联时回退独立连接。页面隐藏时停止前台读取、连接轮询和重连计时，已有事件连接不会仅因隐藏而直接关闭；独立连接也暂停隐藏期间的新建连接和超时判断。`pagehide` 才关闭当前页的事件流或释放共享订阅，最后一个共享订阅离开后断开共享连接。恢复可见时按现有连接与状态补读恢复。设备鉴权和撤权仍然生效；本机调试默认使用独立 SSE 兼容旧后端。

从外部链接进入合法访问地址时，只允许根页面的 GET/HEAD 顶层导航通过来源校验。跨站 API、写请求、错误 Host 和错误 Origin 仍会被拒绝，访问密钥和设备授权规则不变。

### 模型与上下文

输入框下方显示当前模型名称和思考深度，点击后弹出菜单。模型目录优先来自原生，读取失败时可按白名单使用 CLI `model/list`；模型名称优先显示目录中的名称，深度只列出该模型的 `supportedReasoningEfforts`，过滤 `minimal`。`Max`、`Ultra` 等等级以当前目录实际声明为准，不因当前会话值补造目录选项。

已有会话默认显示其实际模型和深度，显式选择随后续提交应用；更换模型时采用该模型可用默认深度。新建页优先恢复当前设备授权下记住且仍在目录中的模型，否则使用服务返回的全局默认值；新建页选择模型会更新这份浏览器本地记忆，不覆盖已有会话配置。菜单支持方向键、Home、End 和 Escape。

模型名称左侧显示 18px 的上下文进度环，与模型及操作按钮保持同一行，长模型名省略而不换行。手机轻点圆环后显示 `200k / 33%，600k` 这样的完整用量提示，再次轻点或点击外部收起；桌面悬停或键盘聚焦也可查看，Escape 收起。浮层随滚动、输入框收缩和可视区域变化重新定位，只读设备同样可查看。用量优先来自原生或 service 返回的当前会话 `tokenUsage`，包括 owner 快照的 `latestTokenUsageInfo`；有效的 `last.totalTokens` 和 `modelContextWindow` 表示最后一次请求占用，不是累计用量或按字数估算。成功读取的同一会话缺少有效用量时，电脑端按精确会话 ID 从本机只读数据库查到 rollout，再提取真实 `token_count` 的最后请求用量，不覆盖已有有效值，不接受网页指定路径。Token 通知继续更新当前显示；所有来源仍缺少有效数据时显示「上下文信息尚未提供」。

在编辑框输入 `/` 后，菜单顶部显示「压缩」，下方为 Skill，不保留工具栏常驻压缩按钮。选择压缩只移除当前 slash 命令，保留其他草稿，然后调用 Codex 原生手动上下文压缩；是否允许在当前回合提交由原生客户端校验。提交回执不代表压缩完成；压缩期间可继续编辑普通草稿，停止、重复压缩、目标创建、既有消息编辑及队列事务仍保留原门禁。原生已确认正在运行或准备压缩时，普通消息默认加入原生队列，由原生在压缩和当前回合允许的时机按顺序执行。本页请求尚未确认、结果未知或回执属于旧设备授权时，草稿仍可编辑，但发送保持保护；不自动重发压缩，可查询回执或重新读取状态，仅在本机核对后才可人工解除。

压缩期间排队由 `/api/session` 的 `capabilities.compactionQueueSend` 声明。网页普通 `send` 请求在上述已确认状态携带 `queueOnly:true`，保留稳定的 `clientUserMessageId`、Skill、图片以及已选模型/推理参数；未压缩的普通发送不添加该字段。字段若存在必须为布尔值，不能用于目标、新建或其他写动作。原生侧也检查实时压缩状态，即使页面滞后，也不能把压缩中的普通消息直接发送或引导到当前执行中。没有新能力的旧服务允许继续写草稿，排队发送保持禁用并提示更新服务。

排队复用 Codex 的 server/local 队列与调度器，不建立网页自有消息队列。已有 local 消息时走原生 coordinator，避免新增 server 消息排到旧 local 消息之前；同一客户端消息身份的在途重复请求合并，输入不一致时拒绝。结果未知的入队仅核对原生状态，不再次添加；本地 `pending`、`sending`、`outcome-unknown` 占位不能作为已确认排队的依据。只有确认后才清理已提交草稿，发送期间继续编辑的内容不会被旧回执覆盖。

普通发送只在明确执行中时入队；空闲、未知状态、旧队列残留或 follower 身份都不单独触发排队。空闲输入仍交给同一原生准备器及 coordinator，使用 `send-now` 且不预先本地入队，保留稳定客户端消息 ID、模型、思考深度、图片和 Skill。异步准备后复核真实执行状态；只有另一轮或压缩已开始时才入队，本次发送自身的启动占位不算另一任务。原生 `send-only` 会话仍拒绝执行或压缩期间排队。原生仅返回 `queued`、但本地消息仍为 `pending` 时继续核对队列或已接受消息，不能据此清草稿或解除防重复保护。service 的直接发送意图单独核对，不作为等待队列展示或自动重放。准备、模型设置及提交前检查原始 manager 身份和会话删除记录；连接更换或会话已删除时，旧请求不得借当前 manager 继续提交。

会话读取或目标通知返回有效且未完成的目标后，输入框上方显示紧凑目标条，包括状态、单行正文及运行时间；展开后查看完整正文和目标自身的 Token 指标。service 读取可从同一 owner 的 `threadGoal` 或 CLI `thread/goal/get` 提供目标，创建和修改仍走原生写入口。目标预算与用量是目标字段，不使用上面的最后请求上下文占用补算。排队消息排列在目标条上方，共用附属背景；不按消息内容推算进度或完成百分比。

输入框左下角菜单和 `/` 菜单均提供「目标」。选择后在正文开头显示一个「目标」行内标签，颜色、字号、图标尺寸和基线与 Skill 一致，目标图案保持不变；不再占用底栏按钮。正文和 Skill 可继续编辑，提示为「描述你的目标，定义可衡量的成果，以获得最佳效果」；也识别位于正文开头且有词边界的 `/goal` 命令。目标标签不属于正文，不占正文或 Skill 的位置，也不写入提交的目标文字；每份草稿只有一个固定前缀。可用 Backspace、Delete 或包含标签的选区删除取消本次目标模式，正文、未选中的 Skill 和图片保留，不清除服务器目标；点击标签仅放置光标，不取消模式。全选替换会移除所选标签，删除后继续输入不会自动恢复。模式随会话或新建项目草稿保存，切换草稿、恢复旧输入及取消队列编辑后重新显示对应前缀。空目标不能发送，纯图片目标可提交；创建入口不设置 Token 预算。已有未完成目标时从目标栏编辑，不允许通过输入框覆盖；只读、消息或队列编辑、删除、压缩期间禁止创建。后端未声明 `goalComposer` 能力时保留草稿并提示更新，不将目标降为普通消息。

已有会话通过专用 `setGoal` 操作创建目标，不发送普通消息或排队；所选 Skill 按正文原位置序列化为 `[$name](path)`，图片顺序保持不变。目标标签只属于编辑框，发送后的消息和重新读取的历史沿用原有渲染，不添加目标标签。新会话先发送原生 `/goal` 首条输入，仅在首轮明确接受后设置目标；会话、首条输入和目标结果分别保留在结构化回执中。已确认创建会话后，即使首条被拒绝或设置目标失败，后续都绑定该会话并只允许设置目标，不重新创建或重发首条。等待期间继续编辑的正文、Skill、图片和模式随新会话迁移，已切到其他会话时不抢选择或覆盖草稿。

成功回执仅清除本次仍未改变的草稿及目标模式；失败保留草稿。结果未知时保存原请求标识、阶段及目标草稿，提供只读回执查询和已创建会话入口，不凭相同目标文字推断成功，也不自动重试；用户在本机核对并显式解除后，才可在已创建会话重新设置目标。页面重载后恢复同一回执和草稿身份；原生权威删除该会话时清理对应目标恢复记录与待确认回执，不清理其他会话的新草稿。目标图片在恢复快照中引用本次请求的图片序号，避免把同一 Base64 图片重复存储。

已明确失败或已人工核对解除锁定的目标恢复提示可点击「不再恢复」，只删除对应本地恢复记录，不清除当前正文、Skill、图片或服务器目标；未经核对的未知结果不提供该入口，仍保留回执锁定。

目标栏只展示尚未完成的当前目标。收到完成状态或目标清除通知后立即移除目标卡并停止计时；刷新页面、切换会话后也不会从已完成目标记录恢复该卡片。原生目标历史不删除，上方排队消息和输入草稿保持不变。仍需核对的编辑回执保留独立恢复入口，不恢复已完成目标卡。

运行中的目标沿用原生累计时间与 `updatedAt`，每秒更新目标条和详情中的运行时间；暂停、阻塞和受限目标显示原生累计值，不继续递增。计时只更新文字，不改写用量数据、不重建目标卡或编辑框，也不增加每秒接口请求。隐藏页面、离开页面或断开连接时停止定时更新，恢复后按最后已知目标状态继续显示，并由现有会话读取和目标通知校准；缺少有效时间字段时不补造计时起点。

目标条右侧的编辑按钮打开独立弹窗，提供同尺寸的还原、取消和保存按钮；当前预算只读。弹窗只保留一个必要滚动区域，字节计数放在编辑框内右下角，保留 16 KiB 限制，不显示「刚刚更新」。关闭、Escape 或点击遮罩取消未保存草稿，但不解除未知回执锁定。保存前核对原生目标身份、正文及状态，不改用量计数、不把已暂停目标自动恢复为运行中。只读、离线、已完成目标和待确认回执限制保存；实时用量通知不会重建正在编辑的输入节点或清空草稿。

手机编辑弹窗以键盘收起时的可视高度为基准，下方40%留空，上方60%作为安全区域。弹窗高度固定为安全区域的80%（即基准高度的48%），在安全区域内居中，顶部距基准区域上沿6%。打开时锁定尺寸，键盘弹出、收起及其引起的视口滚动均不改变弹窗大小；转屏导致宽度改变时重新计算。长正文在输入框内滚动，字节计数与底部按钮保持可见。

目标展开后，编辑图标下方纵向显示「暂停／开始」和「删除」图标。运行中可暂停，暂停或阻塞后可开始；预算和用量受限时不强行恢复。状态按钮调用原生 `setThreadGoalStatus`，暂停目标推进，不额外停止当前生成。删除经确认后调用 `clearThreadGoal`，只清除目标，保留会话消息。三个操作复用 `updateGoal` 及原回执机制，以可选 `operation` 区分 `edit`（缺省）、`pause`、`resume`、`delete`；未知结果只查原回执，不重复提交，也不覆盖后来的目标。

编辑及回执处理保持用户原来的目标卡展开状态：紧凑目标条编辑保存后仍然紧凑，原先主动展开的目标仍保持展开，可点击目标标题收起。提交、失败或回执待确认不会强制展开正文；待确认结果仍通过编辑入口核对，不解除重复提交锁定。

并发刷新只接纳当前会话最近发起的有效读取响应。读取期间收到的 Token 通知不会被该读取的旧快照覆盖；首次读取尚未完成时也会暂存通知。用量降低同样生效，不按数值大小判断新旧。菜单随窗口和视觉视口尺寸变化重新限制高度；尚未选定会话且未进入新建流程时，输入框保持禁用；新建流程按所选项目、无项目能力和创建状态判断是否可发送。

### 选择 Skill

在输入框词首或空白后输入 `/`，按名称、显示名或描述检索当前会话项目中的可用 Skill。方向键切换，Enter 或 Tab 选择；选中后以蓝色小图标和名称嵌在正文编辑流中，不使用独立标签栏。支持按光标位置插入、换行、Backspace/Delete 删除及纯文本粘贴。普通 URL 和完整文件路径不会触发菜单，中文输入法组词时不拦截按键。正文、Skill 及其插入位置随当前授权的会话或项目草稿保存，切换后恢复；本地恢复库可用时也能在重开页面后恢复，保存失败时明确提示。

新会话按照所选本机项目或原生无项目工作目录读取 Skill，不接受网页传入任意目录。发送时同时提交 `$skill-name` 文本标记和原生 `{ type: "skill", name, path }` 输入项，继续通过桌面原有发送队列或创建流程执行。每次发送前重新检查该工作目录的 Skill 名称、路径及启用状态；已停用、跨项目或任意路径不允许提交。一次最多选择 16 项，发送期间编辑的新草稿不会被旧回执清空。

Skill 标记按编辑框中的原始位置与正文交错生成，保留「文字 → Skill」「Skill → 文字」及多个 Skill 的先后顺序，不再统一前置。先按未裁剪正文的位置合并，再处理首尾空白；仅在标记与相邻非空白内容之间补充分隔空格。显式插入的 Skill 不会因正文已有同名 `$skill-name` 而消失。发送前重新读取编辑器中的实际位置，发送后仅移动 Skill 或修改空白的新草稿也不会被旧回执清空；位置以草稿 Skill 的 `_offset` 随 IndexedDB 恢复记录保存，不改变原生 Skill 请求结构。

发送后的用户消息和重新读取的历史消息使用与编辑器相同的 Skill 图标、蓝色文字和显示名，并在原文位置展示。优先识别消息中的原生 Skill 身份及明确指向本地 `SKILL.md` 的链接；只有纯 `$skill-name` 的旧消息，按当前会话目录中唯一且名称完全匹配的 Skill 补全显示。目录异步读取并与选择菜单共享，不阻塞历史展示；无法确定身份时保留原文。目录迟到或显示名更新会刷新对应用户消息，切换会话后不使用旧目录。

行内代码、代码块、普通链接、转义标记、`$HOME` 等全大写变量以及助手消息保持原样。消息复制继续返回含原始 Skill 标记或链接的文字，显示变化不改写发送数据。图标在 Markdown 净化后由固定界面组件构建，不放宽正文中的 HTML 或 SVG 权限。

连续输入会复用同一范围的在途 Skill 查询；光标移出 slash 单词、失去焦点或进入中文组词时关闭菜单，组词结束后才检索。迟到响应不会重新打开已关闭的菜单，旧会话或旧项目的响应也不覆盖新范围。

新建草稿按项目分别保存正文和 Skill，切换项目时恢复对应草稿。项目切换使旧创建请求失去当前页面的操作权，但不取消已经提交的创建任务。成功或部分创建失败后，仍处于原创建页面时将未提交草稿移入新会话；途中编辑不会被原始正文覆盖。切到其它项目后，旧回执不会切换当前页面。回执仍保存完整提交参数，不再重复保存未使用的草稿副本。

通用「新建会话」入口预选当前打开会话所属的项目；当前会话无项目或没有打开会话时，选择「不在项目中工作」，不自动选中列表首项。归属以侧栏的会话项目记录为准，不根据工作目录猜测；从项目菜单发起时，明确指定的项目优先。项目胶囊位于输入框外的上方附属条，点击后优先向上展开搜索列表；胶囊及项目选项仅在悬停或键盘聚焦时显示背景，选中项保留勾号，不持续高亮。选择项目后，悬停或键盘聚焦胶囊时，文件夹图标原位显示清除按钮，提示「不在项目中工作」；点击只清除本次选择，不删除本机项目。列表底部固定提供同名选项，搜索无匹配时也可清除选择；网页不提供「新建项目」入口。项目可按名称或路径搜索，同名项目同时显示路径，清除或重新选择仍按项目恢复各自草稿。

支持 `projectlessCreation` 能力的服务允许直接发送并创建无项目会话，复用本机原生 `projectless-thread-cwd` 解析器决定工作目录及输出目录，以 `workspaceKind: "projectless"` 交给原生创建并登记归属，不接受网页指定任意目录。旧服务未声明该能力时，无项目状态保留草稿并提示更新或选择已有项目，不向旧服务提交不支持的创建请求。网页不提供分支操作。

### 网页外观

登录页和会话侧边栏底部的「设置」共用齿轮图标。PC 设置直接打开和关闭；手机保留整页从右侧滑入及返回动画。设置按会话、会话实例、自定义指令、外观分组，Android 继续提供通知事件和诊断日志。会话正文宽度上限默认 950px，可填写 320～3840px；先按右侧可用空间保留配置宽度，只有实际放不下时才收窄，有足够留白才对齐整个可视窗口中心。设置内容采用同样的宽度优先逻辑，上限固定 1000px，导航宽度随字体自适应，滚动条不挤占这 1000px。手机保留对称边距并适应窄屏。

设置内容使用分组卡片，标题保持「设置」，不增加内部面包屑或主题／字体／背景导航。「外观」按视觉风格、背景图片及可展开的高级排版分组，模式使用自动、浅色、深色三个预览选项；自动模式沿用本地时间与 Android 光照逻辑。ChatGPT、VS Code Plus 两种主题分别保存明暗配色，强调色、背景、前景支持直接编辑 HEX，点击色块打开连续取色浮层；取色器支持饱和度／亮度拖动、色相条、键盘、HEX 输入及原有预设颜色，非法色值不会保存。程序及代码字体使用统一 Select，检测当前设备的常用可用字体并保留已保存的自定义项；字号、字重继续独立设置，默认系统字体／系统等宽字体、14px，保留独立文件阅读字号。手机输入框继续至少使用 16px。检查记录见[会话与设置布局验证](validation/settings-layout-20261112.md)。

界面偏好即时生效，保存在当前浏览器的 `codex-elves-web-appearance` 中，不修改本机 Codex 主题，也不存访问密钥。损坏设置或非法颜色回退到默认值；浏览器拒绝保存时会明确提示。「自定义指令」仅选择会话实例，读取和保存该实例配置目录中的用户级全局 `AGENTS.md` 或 `CLAUDE.md`。实例开关不限制全局指令编辑；后端根据实例 ID 确认固定文件，不再提供项目作用范围。保存复核设备授权、只读策略和文件版本，冲突时保留按实例隔离的网页草稿，并保留原 CRLF / LF 换行。

「自定义指令」的“重新读取”和“保存指令”位于设置页底部右侧，该页隐藏“完成”；切换到其他设置页时恢复“完成”。保存不会自动关闭编辑页，仍可通过顶部关闭按钮退出。

WSL Claude 的文件查看按会话身份映射 Linux 路径、挂载盘和 WSL UNC，继续限制在原项目内。完整验收见[会话栏与设置优化验收](validation/session-settings-20261112.md)。

### 下拉组件与侧边栏菜单

新会话项目与设置中的每项目会话数使用自定义下拉；项目可按名称或路径搜索。方向键、Home/End 切换选项，Enter 选择，Escape 收起并返回触发器，点击外部或 Tab 离开会收起。浮层按可用空间调整并内部滚动。侧栏顶部按会话实例多选筛选，只显示设置中已开启的实例；同类型不同 WSL 实例独立，旧类型或实例单选会迁入对应选择。选择“全部会话”同步清除其它选择，选择具体实例后退出全部模式，取消最后一项则恢复全部；全部模式也只涵盖已开启实例。只有一个已开启实例时选择后关闭菜单，多个实例时保留菜单供连续选择，点击外部或键盘离开后关闭。多选结果保存在当前浏览器，覆盖最近、项目、置顶和搜索，保留原列表及未读状态。PC 右上角会话菜单点击图标后固定显示，再点同一图标关闭，移除额外的显示开关；手机保持原菜单行为。菜单与图标下边缘统一间隔 10px。

会话行菜单提供打开、置顶或取消置顶、删除会话；项目行提供在此项目新建会话、置顶或取消置顶。已置顶对象保留标记；桌面端的更多按钮在悬停或键盘聚焦时显示，手机端长按会话行打开同一菜单，也支持右键、菜单键或 Shift+F10。长按定时器和浏览器原生菜单事件共用一次手势状态，两者先后到达均只打开一次，释放后的合成点击不会打开会话；新手势可以立即再次打开。滑动、多指操作取消长按，浏览器接管触摸时停止定时器并由原生菜单事件决定是否打开。侧边栏刷新保留滚动位置及正在操作的菜单，触发器滚出可见区域时关闭菜单。

删除前显示会话标题及不可恢复提示，取消不提交请求。确认后使用独立回执标识执行永久删除，不占用消息发送回执；只读、离线或该会话仍有待确认写操作时禁止删除。确认永久删除成功（包括列表清理部分失败）才移除侧栏记录、草稿及相关本页缓存；删除当前会话后回到欢迎页并清除对应 URL，删除其他会话保留当前页面和输入内容。等待回执期间切换会话或设备不会被旧回执改回。

明确失败保留会话并解除删除锁定；网络中断、服务端错误或未知结果保留记录、草稿和回执锁定，菜单及当前会话提示提供「核对删除结果」，仅查询回执，不自动重发删除。刷新页面后继续保留未确认回执。收到原生 `thread/deleted` 通知后同步清理；同一浏览器会话中已确认删除的记录按设备保存，迟到的侧栏读取、会话详情或通知不能使它重新出现。

手机侧栏以视口宽度的 80% 作为抽屉宽度。

搜索覆盖会话标题、项目名和项目路径，命中折叠项目时临时展开，清空搜索后恢复折叠。最近会话与项目视图在本地立即切换，不因侧栏读取或其他侧栏操作禁用；偏好按当前设备授权写入浏览器 `localStorage`，只读或离线时同样可用，不调用原生偏好写接口，也不影响其他客户端。保存失败时本页选择继续生效并提示刷新后可能丢失。最近更新使用 `updatedAt`，缺失时回退到 `recencyAt`、创建时间；真实项目与会话置顶、原生手动顺序仍读取桌面状态，置顶写操作需在线且可写。实时刷新保留筛选条件、控件焦点及已取得的较新更新时间。

最近会话视图不单独显示「置顶」分组，置顶会话与其他会话合并去重，按优先级规则进入「优先级」，其余会话按浏览器本地日期进入「今天」「昨天」或「历史」并显示所属项目。三个日期分组统一按最近更新时间倒序，不继承桌面手动会话顺序；更新时间相同时按创建时间、会话 ID 保持稳定顺序。最近更新时间来自原生会话数据，不单独推算执行完成时间。项目视图保留原有置顶分组和置顶操作。

侧边栏仅展示主会话，不显示 subagent 独立会话。原生会话目录与最近摘要统一过滤子代理来源；网页接收侧栏数据时也过滤最近、置顶和项目内的子会话，使当前旧后端返回的子代理记录不会混入页面。仅按来源标记过滤，不按「新会话」等标题判断，正常未命名主会话仍保留。过滤仅影响侧栏展示，不删除、归档或修改实际会话及置顶设置；主会话内的子代理活动与历史记录保持不变。

会话执行时显示旋转指示，执行完成且未阅读时在同一位置显示蓝点；已读取后蓝点消失。当前页只有在会话可见且跟随底部时才主动标记已读，只读设备不写原生已读状态。

设置固定在侧边栏底部左侧，「退出」在同一行右侧。「退出」撤销当前设备授权；退出、会话级审批和人工解除发送锁定使用统一确认弹窗，支持键盘取消，全局结果从页面顶部提示。只读、断线或置顶写入期间禁止相应会话写操作，本地视图切换仍可用。自动恢复会话或首次进入新建页不收起用户已打开的手机侧栏；手动选择会话或新建时先收起一次，用户随后重新展开时，迟到读取不会再次收起。减少动态效果设置会关闭非必要动画。

模型菜单贴近模型按钮展开，间距为 4px，空间不足时向下翻转或避让边缘。模型列表与推理等级分别滚动，模型数超过 8 个时显示搜索，可按显示名和请求标识查询；选择后保留滚动位置和可见焦点，中文组词期间不重建搜索输入。鼠标或触屏点击控件不显示高亮外框，键盘 Tab 导航保留焦点提示。上下文用量通过前述圆环查看。发送按钮以当前正文、Skill 序列化结果或图片判断是否有输入，支持服务允许的纯图片消息及目标；空目标不能提交，图片未读完、对应能力缺失、未加载会话、离线、只读及待确认操作等状态仍禁用。执行中无可发送草稿时可原位显示停止，发送或停止期间阻止重复提交。

## 启用与连接

1. 使用包含本功能的新版本 CodexElves launcher 启动 Codex。旧的、仍在运行的 launcher 不会自动获得新服务。
2. 打开管理工具的「远程会话」页面。远程网页可先启用；zrok/FRP 公网入口、绑定和主链路切换不要求 Codex 桌面已经连接，会话读取和执行等待服务就绪。已有桌面持有的会话通过原生 IPC 协作时，需保持对应 Codex App 可响应。下载 zrok、邮箱注册和入口测试可提前完成。未设置访问密钥时网页只显示登录页，任何设备都无法进入会话。同一行左侧「生成」只将随机密钥填入输入框，也可手动输入 8–64 个非空格 ASCII 字符；右侧「保存」才使密钥生效，无需重启服务。生成草稿不撤销已授权设备。保存后明文及校验摘要保存在本机，刷新后仍可回显，默认使用圆点遮挡；旧版只保存摘要的密钥需要重新输入并保存后才能回显。请妥善保管，仍建议使用随机长密钥。
3. 打开「远程会话网页」栏目右上角开关即保存并生效，无需点击「保存并应用」。后台已连接时立即启停；若启动时所有增强和模型代理都关闭、尚无后台，首次开启后需重启 launcher。启用后不要求开启其他增强或模型代理。
4. 确认保存成功；公网连接选择 zrok 或 FRP。以下为 zrok 的首次配置：首次使用先点击「下载程序」；输入邮箱时按钮变为「注册公网」，发送注册邮件；取得 token 后粘贴到输入框，并在同一行填写固定公网名称，按钮变为「启动公网」。
5. 在手机打开访问地址，粘贴或输入访问密钥后点击「连接」，也可按回车提交。输入框右侧可切换密钥显隐；无需填写设备名称或生成一次性配对码。
6. 不再使用某台设备时，点击设备旁的「撤销」，或在网页点击「退出」。

电脑必须保持开机，负责远程访问的 CodexElves 后台必须保持运行。独立 Codex 会话由服务的 app-server 执行；桌面已持有的会话通过原生 IPC 协作时仍需 Codex App 就绪。此功能不负责唤醒电脑或设置 Windows 开机任务。

公网首页可访问不代表 Codex 桌面已经就绪。桌面尚未连接或正在重启时，远程会话页持续展示操作提示：在电脑端点击「重启 Codex」，等待主界面完全打开、能够正常查看会话后，再刷新远程网页。既有固定公网仍按原配置自动恢复；公网已连通但桌面未连接时，管理器显示「等待 Codex 就绪」。桥接恢复后，launcher 会将同一组端口对应的 `running_degraded` 更新为 `running`；远程读取也会对 `running_degraded` 实际探测桌面，避免过期状态持续阻断已恢复的会话。

### 密钥登录交互

登录页沿用网页主题，提供访问密钥标签、折叠获取说明与外观设置。空输入不允许连接；支持 8–256 个非空格 ASCII 字符，粘贴时忽略首尾空白，拒绝内部换行，超过 256 位不会静默截断。长度及字符格式不符合要求时，在输入框下明确提示要求并聚焦输入框，不发送验证请求。

连接时显示验证和加载进度，锁定重复提交并重新隐藏密钥。密钥错误、尝试过多及服务不可用分别显示服务端原因；网络异常或超过 20 秒未完成验证/会话连接时提供重试提示，不自动重发。密钥已验证但会话加载失败时，可直接「重新加载会话」，不重复验证或要求再次输入；授权未生效时才重新输入。成功验证后清空明文，不写入 URL、Local Storage 或 Session Storage。

同一访问密钥连续验证错误超过 3 次，即第 4 次错误时，后端立即锁定该密钥的所有新登录，返回 `423`；前 3 次错误返回 `401`，仍可重试。在第 4 次错误之前正确登录会清零连续失败次数。锁定状态由后端持久化，刷新网页、更换 IP、等待或重启服务均不会解除；已登录设备仍保留授权。只有在本机管理器生成不同的新密钥并成功保存后才能解锁，同时撤销原有设备授权。只点击「生成」或重复保存同一密钥均不解锁。

登录页初始化读取匿名只读接口 `GET /api/login-status` 的 `{ ok: true, loginLocked: boolean }`。已锁定时禁用密钥输入和连接，回车或修改输入不能绕过，并提示「访问密钥连续输错超过3次，登录已锁定。请在本机管理器重新生成并保存密钥后再登录。」锁定页可见时约每 5 秒核对一次状态，隐藏或离开登录页时停止；每次查询最长等待 10 秒，网络错误不会自行解锁。后端确认已解锁后，网页清空旧输入并恢复输入新密钥，不自动提交。旧服务未提供此接口而返回 `404` 时，仍可沿用原有登录流程；实际登录始终由后端校验。管理器也展示后端锁定状态，生成候选密钥后仍明确提示保存。

手机保持相同布局，输入框至少 16px，显隐和连接按钮可触控；首次打开不自动唤起键盘。短屏和键盘挤压可滚动查看帮助与按钮。

### 网络配置

默认配置为**关闭**，监听 `127.0.0.1:45222`，仅可从本机访问。它不占用模型代理的默认端口 `45221`，也不扩大现有局域网代理的会话管理权限。

手机通过所选主入口的固定公网地址连接，FRP 配置见本文开头。使用 zrok 时，CodexElves 自动准备并校验受管 `zrok2`，绑定后使用 `https://<固定公网名称>.shares.zrok.io`；固定名称会保存并在后续启动时复用，不再为每次运行申请随机地址。

远程会话网页仅允许监听本机回环地址，不提供局域网明文直连或自定义 HTTPS 证书入口，也不会配置路由器端口映射或修改防火墙规则。zrok 只转发到该回环地址，访问密钥不会写入公网链接。

### zrok 固定公网配置

1. 启用「远程会话网页」；可在启用前后设置并保存网页访问密钥。zrok 仅转发到回环地址上的本机 HTTP 服务，未设置密钥时仍无法进入任何会话。
2. 首次使用时，「公网入口 · zrok」右侧按钮显示「下载程序」。CodexElves 下载固定版本的 Windows x64 官方 `zrok2`，校验下载地址、文件大小、SHA-256 和程序版本；若 `PATH` 中已有校验通过的相同程序则直接复用。
3. 下载完成且输入为空时，「启动公网」保持置灰。输入邮箱后按钮变为「注册公网」；点击后由 CodexElves 请求 zrok 发送注册邮件。按邮件完成注册并取得 token 后，将 token 粘贴到原输入框。
4. 输入 token 后，同一行显示第二个输入框。填写 3–63 位固定公网名称，只能使用小写字母、数字和连字符，且首尾必须是字母或数字；点击「启动公网」或主入口的「保存并测试」「应用为主链路」后完成 zrok 环境绑定、预留固定名称并启动公网转发。右侧按钮或主链路操作都会把当前 token 写入本机 CodexElves 设置；最后一次提交的值会在后续打开页面时回显。
5. 地址显示后，后台自动确认公网首页返回 CodexElves 页面且未登录的 `/api/session` 返回 401；验证通过才显示「可访问」。失败时保留固定地址并自动重试，也可点击「测试访问」立即检查。
6. 手机关闭 Wi-Fi、使用蜂窝网络打开固定地址并输入网页访问密钥。zrok 免费服务首次访问可能显示提示页，点击「Visit Share」后进入登录页。

固定公网名称写入 CodexElves 状态目录的 `remote-access-zrok.json`，zrok 绑定信息由 zrok 自身保存。后续启动时，只要「远程会话网页」仍启用、zrok 已绑定且固定名称有效，程序会自动启动同一固定地址，无需再次输入 token。

点击「启动公网」时，后台先重新确认本机 zrok 环境。已启用的环境直接复用，不会因为旧缓存显示未绑定而再次执行 `enable`；后台旧检查也不能覆盖本次确认结果。若其他进程在检查后完成绑定，程序收到「已有启用环境」时会再次核对，确认已启用后自动继续，不要求用户手工执行 `disable`。状态读取失败、token 错误和其他启动错误仍明确报告，可再次点击重试；不会自动解绑、删除环境或切换账号。

zrok 没有独立启停开关，跟随「远程会话网页」启停。关闭该开关会立即停止 zrok；退出负责启动远程后台的 CodexElves 进程时，Windows Job Object 会同时回收远程网页后台和 zrok。关闭管理器窗口只会最小化到托盘，需要从托盘退出才算退出程序。

不再保留主管理器心跳、3 小时超时或程序退出后继续运行公网服务的逻辑。网络短暂中断或 zrok 异常退出时，当前运行期内会按状态自动重试；固定名称不变，因此不会因重启 CodexElves 频繁申请新的公网地址。

独立后台使用文件锁保证每个用户状态目录只有一个实例。本机管理接口仅监听 `127.0.0.1` 的随机端口，校验本机令牌并拒绝携带 `Origin` 的浏览器请求；不通过 zrok 暴露。`remote-access-service.json` 保存进程、端口及管理令牌，不应对外分享。

公网 TLS 由 zrok 服务终止，再通过隧道回源到本机 HTTP 服务。CodexElves 只信任当前固定名称对应的精确 Origin，不接受 `shares.zrok.io` 通配信任；固定名称变化后会撤销旧地址下的设备授权。本机 HTTP 登录不会因为公网入口存在而错误设置 `Secure` Cookie，公网登录限速使用经过入口校验的转发客户端 IP。

远程网页事件通道使用同源 WebSocket；多个标签页在浏览器支持 SharedWorker 时共用一条连接，断线后指数退避重连。旧 SSE 路由仅保留兼容，不作为 zrok 实时通道。固定名称表示地址可复用，不代表 zrok 免费服务提供生产级可用性承诺。

## 设置与安全

| 设置 | 行为 |
| --- | --- |
| 启用远程会话网页 | 默认关闭，切换开关后立即保存并启停 |
| 监听 IP、独立端口 | 端口范围 1–65535；端口占用会显示错误，不影响模型代理 |
| zrok 固定公网 | 没有独立开关；远程网页启用且绑定完成后自动启动，复用已保存的固定名称 |
| 远程后台生命周期 | 跟随启动它的 CodexElves 进程；程序退出时回收远程网页和 zrok，不使用心跳或 3 小时延迟退出 |
| 受管 zrok2 | 固定版本下载，校验官方 HTTPS 来源、大小、SHA-256 和程序版本 |
| 注册与启动 | 邮箱对应「注册公网」；token 加固定公网名称对应「启动公网」；已绑定后可直接复用 |
| 测试访问 | 验证公网 HTTPS 首页 200 及未登录接口 401；测试不改变当前地址 |
| 访问密钥 | 长期有效，生成与保存独立，使用同一个输入框；成功保存不同的新密钥后旧设备授权失效，并解除登录锁定 |
| 设备授权有效期 | 默认关闭（0），开启后可设 1–720 小时，仅对新登录设备生效 |
| 远程审批及回答询问 | 默认允许，管理页不提供单独开关；历史配置的后端权限仍保留 |

访问密钥以明文和加盐 PBKDF2-HMAC-SHA256（600,000 次）摘要共同保存在本机 `remote-access-key.json`；摘要用于登录校验，明文用于管理页回显。输入框默认使用圆点遮挡，点击小眼睛可查看明文，点击复制可复制当前密钥。旧版本只保存摘要的密钥无法恢复明文，需要重新输入并保存一次。密钥验证有来源限速及并发上限。网页登录后使用随机设备令牌，保存在 HttpOnly、SameSite=Strict cookie 中，zrok 公网连接要求 Secure；磁盘仅保存设备令牌哈希。网页不将访问密钥写入 URL、localStorage 或 sessionStorage。请勿向不可信的人透露密钥。

密钥在隧道和网页服务重启后继续有效，设备授权则遵守有效期。更换密钥使所有旧 cookie 失效，包括服务重启后从磁盘恢复的旧设备；不取消已经提交到 Codex 的任务。撤销单台设备会使其当前授权失效，但知道长期密钥的人仍可再次登录；要阻止再次登录，必须同时更换密钥。

同一浏览器或 App 使用持久随机客户端标识，成功登录时复用同一密钥和入口下仍有效的设备授权；有效旧 Cookie 可迁移并保留原设备 ID、草稿和队列归属。客户端标识不能代替密钥或 Cookie，服务端只保存其摘要，不按 IP、UA 或名称合并设备。撤销、过期或换密钥后重新登录会生成新的设备 ID，旧凭据仍失效。32 条上限只限制新增授权；授权记录对应客户端环境，不等于实体设备数。Android App、Android 浏览器和电脑浏览器使用可辨识名称。

有交互和审批权限的设备可以通过 Codex 操作本机项目，应当像对待桌面账号一样保护它。撤销和到期会停止该设备的数据流，并拒绝后续操作。

服务检查 Host、Origin 和跨站请求，Markdown 不执行 HTML 或 `javascript:` 链接。审批使用原始 request ID（包括数值 `0`），核对所属会话和请求类型；已结束请求不会继续放行。

命令审批只展示和提交原生请求允许的决定；网络审批显示协议、目标主机和端口。询问答案只接受文本，MCP 外部登录等 URL 询问不能通过远程 API 回答，需回到桌面处理。

访问密钥明文及哈希、授权设备及消息回执保存在 CodexElves 状态目录下的 `remote-access-key.json`、`remote-access-devices.json` 和 `remote-access-receipts.json`。这些文件尚未生成时不影响远程网页、公网入口或其他 CodexElves 功能启动；没有访问密钥时所有登录和设备授权都会被拒绝。升级后会清理旧 Quick Tunnel 的配置、冷却记录和受管程序目录；旧版 Named Tunnel 凭据 `remote-access-secrets/cloudflare-tunnel.json` 仍不再使用，可手动删除。损坏的授权文件会使远程服务拒绝启动，但不会使原有模型代理启动失败。

管理器已移除只读访问选项；旧配置中的 `readOnly=true` 仍遵守原有权限，不因 UI 调整自动扩大已有设备权限。密钥栏目不再列出本机地址；固定公网地址在 zrok 栏目中查看及复制。旧 `funnelEnabled`、`cloudflareTunnelEnabled` 和 Quick Tunnel 配置不会控制 zrok，也不会自动完成 zrok 绑定。

## 审批与问答

审批以原生待处理请求集合为准。桌面处理后，远程按请求身份及版本快照移除对应卡片；未知请求集合不能当作全部完成。远程只提交原生允许的决定，未适配请求提示回到桌面。正在处理或结果未知时锁定重复操作，明确失败保留卡片和页面内输入，不自动重发。

异步问答显示问题、原始选项与其他回答输入；选择选项不代表提交。点击“提交回答”通过原生专用入口回答，点击“跳过”只跳过当前卡片中尚未完成的问题，不发送预选项或草稿。原提问轮完成不代表题目已回答；仅同一会话、原轮次、消息、问题及面板实体仍有效且原生未答的题目继续显示。回答和逐题跳过的接受状态来自原生，已处理或失效题目不能被迟到读取恢复。

问答卡紧贴编辑框上沿，间隔 8px，直接叠在排队、目标等附属信息上方；普通权限审批仍避让这些内容。问答选项行最小高度为 32px，操作按钮为 28px，自由回答默认单行，长内容内部滚动。未提交问答选择及答案只在当前页面内保留，不承诺刷新、关闭或系统回收后恢复；不持久保存答案。提交后的恢复仅保存原请求标识及核对元数据，在重新连接、回到前台、操作完成及既有连接轮询时只读查询原回执。`pending`、`unknown`、404 或断网均不能触发再次回答；明确成功只清除对应问题的锁定，明确失败保留当前页面答案并解除该操作锁定。

## 断线与消息回执

消息提交前保存客户端请求 ID 与回执。同一设备重复提交相同 ID 和内容不会重复发送；同一 ID 携带不同内容会被拒绝。

回执的「完成」指提交动作完成，不代表模型已经生成完毕。网页断线不会终止桌面任务，重新连接后从原生或 service 读取路径恢复。

若发送回执丢失、原生客户端报告结果未知，或服务在提交中重启，网页会锁定重复发送并查询回执。它不会自动重发。请先检查会话，再通过「已人工确认」解除锁定；不要仅因为没有看到回复就再次提交。

已登录设备在桌面暂时离线时保持自动重连，不退回密钥输入页。损坏或属于旧设备授权的浏览器回执会锁定发送并提示人工核对，不会因解析失败白屏，也不会自动丢弃记录后重发。迟到的旧回执和旧授权请求不能解除新消息的锁定或恢复已经退出的页面状态。
