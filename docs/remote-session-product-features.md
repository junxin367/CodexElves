### 会话历史与内容展示

#### 历史加载与分页

1. **最新历史加载**
   - 首次进入、从其他会话切回或强制重新读取时，按当前会话身份读取最新一页，不携带历史游标；重复选择当前已读完整且关联视图未变化的会话时复用当前内容，不重复请求。当前会话读取未完成或失败时，待没有在途请求后补读。
   - 首次加载且尚无可展示正文时显示“正在加载最新消息…”；分页时对应按钮显示“加载中…”，并暂时禁用其他分页按钮。只有成功核对且没有任何可展示消息时才显示空会话。
   - Codex 主会话、持久子智能体及服务侧边会话每页最多读取 3 个轮次，非执行中轮次的消息单页最多 40 条。服务侧边会话使用独立的轮次和消息游标；原生临时子智能体只读取当前完整快照，不提供分页游标，也不会为读取重新启动。
   - Claude 普通会话及 Claude 子智能体每页最多返回 10 个完整轮次，不再单独进行轮次内消息分页。游标表示历史位置索引；响应同时返回当前完整历史的轮次 ID，用于核对并清理旧缓存中已不存在的轮次。
   - 轮次由新到旧返回，页面按原生轮次顺序由旧到新展示；轮次内保留原生消息顺序，不按到达时间或客户端时间重新排序。仅合并当前会话选择和前台读取代次仍有效的结果；历史数据必须是数组，轮次内分页还必须返回匹配的范围和轮次 ID，原生会话身份由服务端核对。

2. **缓存展示与最新核对**
   - 有有效缓存时先恢复最近正文，再读取最新历史；缓存只用于展示，不恢复审批、执行权限或发送能力。
   - 同一页面切回会话可复用内存正文及渲染节点；跨页面持久正文只保存已完成、失败和已中断轮次。侧边会话及原生临时会话只保留当前页面内存，重开页面后重新读取。
   - 正文缓存超限时，先尝试保留完整快照，其次保留服务端最近一页及其后的新轮次，仍超限则只保留服务端最近一页；全部候选都无法容纳时保留先前有效缓存。不得截断单条消息或自行生成游标；回退到最近页时清除旧阅读锚点并定位底部。
   - 恢复缓存后先核对最新页，再允许使用旧分页游标加载更早内容，避免缓存缺口被误当作连续历史。

3. **更早轮次分页**
   - 返回下一页游标表示仍有更早轮次，游标为空表示已经到达最早一页；不同引擎及会话类型的游标分别按各自规则处理，不得混用。
   - 支持点击“加载更早的消息”；分页入口进入消息区域顶部上下 120px 范围时自动读取。已有请求、缓存仍在核对或自动加载已经失败时不得重复触发；一次只加载一页，成功后重新判断是否继续。
   - 非法游标应直接报错；普通轮次分页只检查返回游标是否与本次请求游标相同，相同则停止并报错。执行中轮次连续读取全部消息页时另维护已见游标集合检测循环，不得把普通分页描述为已统一检测跨请求循环。

4. **轮次内过程记录分页**
   - Codex 的轮次游标与轮次内消息游标必须分开处理；加载过程记录时同时指定当前轮次，返回范围或轮次 ID 不匹配时不得合入。
   - 非执行中的长轮次先展示最新一页，并补回最早一页中的首条用户输入及助手消息作为可见上下文；补回内容只用于展示，不能充当后续分页定位点。
   - “加载更早的过程记录”位于对应工具或思考活动的折叠详情内，任一父级详情收起时不得自动请求；展开详情或向上滚动时，可加载当前可见区域内的入口。加载失败后保留详情内重试入口及展开状态。
   - 加载时将消息插入当前轮次的分页锚点之前，并按消息身份去重；没有下一页游标后不再显示加载入口。

5. **执行中轮次完整恢复**
   - 执行中或等待启动的轮次必须连续读取全部消息页，直到没有下一页游标，确保首条输入、“继续”等过程内容在重新进入后仍然可见。
   - 全量恢复期间检测已见游标循环并按消息身份去重；非执行中轮次继续保持按需分页，不因一次读取全部历史而阻塞首屏。

6. **阅读位置与滚动跟随**
   - 前插更早历史时，以当前可见消息及其相对位置为锚点，加载后保持视口稳定，不得强制跳到顶部或底部。
   - 用户位于正文底部时继续跟随新消息；正在阅读较早内容时保持当前位置，不被最新历史或实时消息拉回底部。
   - 每次滚动重新计时，停止滚动 500ms 后保存阅读位置；切换会话、页面隐藏和离开时立即补存。恢复时优先定位原可见消息，该消息已不在缓存窗口时回退到最近内容底部。

7. **分页与实时内容合并**
   - 最新页刷新时保留已经加载的较早轮次和后续实时轮次；较早页插入已有正文之前，重叠轮次和消息按稳定身份合并、去重。
   - 读取开始后收到的实时内容优先于较早返回的历史页；历史页缺少某条实时消息不能作为删除依据，已完成消息的正文、状态和完成时间不得被不完整快照拆散覆盖。
   - Claude 按完整轮次替换对应的权威正文，并保留符合条件的实时预览；分页游标按从最新轮次开始的连续已加载区间计算，零散旧缓存不能导致中间历史被跳过。

8. **加载失败与重试**
   - 单次历史读取中，只有成功响应的正文未能完整读取或 JSON 解析失败时才立即重读一次，格式校验错误不触发该重读；线路层可按安全读取规则改用另一条授权线路，最多两条线路，两类恢复均不得无限重试。
   - 用户主动加载失败时，初次加载显示错误及重试入口，最新历史刷新保留已有正文并提供重试，较早分页保留当前内容、提示错误并暂停自动翻页。
   - 前后台切换、连接恢复或在线状态探测触发的静默补读失败时，保留当前展示及待补读状态，不反复弹出错误；后续连接恢复、返回前台或在线状态探测可继续核对尚未完成的当前会话，成功后停止补读。
   - 空历史、加载失败和会话失效必须分别处理，不得因请求失败清空已有正文或显示“此会话暂无消息”。

9. **请求隔离与失效处理**
   - 同一会话、同一读取周期只保留一个在途历史请求；请求期间再次要求最新历史时，在当前请求完成后补读最新页。
   - 切换会话、授权变化、页面隐藏或离开以及会话删除后，取消或忽略旧请求；迟到的响应不得覆盖当前会话、重新出现已删除内容或弹出过期错误。
   - 仅按当前授权及准确会话 ID 的明确原生缺失证据处理失效：侧边会话保留已显示正文并进入过期只读，仍允许补读最终正文和历史翻页；子智能体不可读取时返回来源主会话；其他明确不存在的会话清理对应缓存并返回会话列表。
   - 已标识为原生临时会话且未进入上述关联会话失效流程的明确不存在结果，清理正文和缓存并显示“此原生临时会话已关闭或不存在”；仅表示 `thread not loaded:` 的错误不据此清空。普通网络失败不能判定会话过期或不存在。
